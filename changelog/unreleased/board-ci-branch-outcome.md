### Added

- **Engine: the `board/ci/<topic>--done` row takes a `branch_outcome` dim, and the owner stamper reads it first.** `board-ci.yaml` declares `branch_outcome` (string, optional); `DoneVerdict.of` uses it when present and not blank, else `outcome`, else the body's runs. The conexus CI adapter carries the last develop result of a path-filtered workflow (Service CI) onto a later sha that did not run it, so a Service CI red no longer clears when a later sha's other workflows are green; a clear needs every workflow's latest result green. A row without the dim reads as before, and an engine from before this release answers `400 schema_violation` for the dim, which the adapter's one-retry-without-the-dim fallback absorbs.
