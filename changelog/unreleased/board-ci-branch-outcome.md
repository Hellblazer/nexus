### Added

- **Engine: the `board/ci/<topic>--done` row takes a `branch_outcome` dim, and the owner stamper reads it first.** `board-ci.yaml` declares `branch_outcome` (string, optional); `DoneVerdict.of` uses it when present and not blank, else `outcome`, else the body's runs. The conexus CI adapter carries the last develop result of a path-filtered workflow (Service CI) onto a later sha that did not run it, so a Service CI red no longer clears when a later sha's other workflows are green; a clear needs every workflow's latest result green. A per-sha failure is never overridden by it, and an unrecognised value is no verdict. A row without the dim whose body carries a null `carried` (the adapter's carry read failed), a `carried` list with an entry that is not `success` (a carried skipped or neutral does not pass; the sha's own runs keep success, neutral and skipped) or cannot be read, or a `carried_n` above the list's length (an absent list counts as empty) has no verdict when its per-sha result is success, so a failed or unverifiable carry cannot clear a carried red; the stamper logs `board_done_no_verdict` with the reason `carry_failed`, `carried_not_green`, `cancelled` or `unknown`. A body with neither `carried` nor `carried_n` reads as before, and an engine from before this release answers `400 schema_violation` for the dim, which the adapter's one-retry-without-the-dim fallback absorbs.
