### Changed

- After a compaction, the checkpoint now tells the session, once it has done what the user last asked, to act on any open item that has nothing to wait on: a board thread, or a summary item that the board, git or beads still show open. When all it is doing is waiting on a running task, it says what it waits on. It never starts work the user held back or asked it to wait on, work that needs the user's approval, or work another session owns. The line appears once in every compact start, whether the checkpoint is restored or only the no-restore notice is injected, and never on a resume, fork or startup. The transcript census traced the real post-compaction misses to threads that were all blocked while the one unblocked item was named only in the summary, and to a session that waited on a background task without saying so.
