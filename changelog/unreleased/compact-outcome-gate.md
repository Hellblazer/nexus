### Added

- An opt-in end-to-end gate, `tests/e2e/compact-outcome-gate.sh`, drives a real `claude` through a real automatic compaction and scores what the session then does, by effect (the repo state and the tool calls after the compaction), with no user input. Its scenarios are the census's real miss (every board thread blocked, one independent job named only in the summary), a bounded ask ("just do TODO item 2, then stop": the pass is to stop), waiting honesty (the only open item is a background task: the pass is to say what it waits on) and the five-item regression. Its arms are the shipped compaction hooks (`real`), no plugin (`control`), a board-withheld checkpoint (`bad`), the real hooks plus only the narrow directive line (`directive`) or only the broad one (`broad`), a harness-owned open-work overlay (`fix`) and a no-compaction baseline (`nocompact`). The default is 15 runs and 11 passes; it exits 0 only when the gate arm reaches the threshold and beats the control arms by a one-sided Fisher exact test at p < 0.05, prints each arm's Wilson 95% interval and cost, compares the real arm's resume rate with the census (32 of 35) and says "scenario harsher than observed use" when it falls far below it, and exits 2 (never a pass) when any run ends with no verdict, a compaction lands outside the final turn, the hooks did not run, or the harness crashes. The default matrix is 10 arm-scenario cells x 15 runs = 150 sessions, an estimated $12 on haiku and $38 on sonnet (the default model; the measured figure of about $0.03 a run is for the earlier one-paste shape on haiku). It spends model calls, so it is run by hand: no workflow, script or default pytest run starts it, and `tests/hooks/test_compact_outcome_harness.py`, which starts no `claude`, pins that. The stub `nx` answers every call today's checkpoint hook makes, the harness test fails when the hook gains a call the stub does not answer or a call spelling its scan cannot read, `bd` and `gh` are failing stubs, and the live run's environment drops every `NX_`, `NEXUS_` and `CLAUDE_CODE_` variable of the parent (keeping the sign-in ones) and binds no identity.
