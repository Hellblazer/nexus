### Fixed

- **`nx doctor` on a managed deployment shows the eight database rows as not applicable, not as warnings.** Storage service health, Schema migrations, RLS policies, tuples.dead_tuple_ratio, tuples.sweep_freshness, Tenant partitions, Model partitions and Partition leaves read the database with local admin credentials that a managed deployment keeps with the store operator. They now print `[ ]` with "managed deployment, not probeable from this client, so this check was not run", count in neither the warnings nor the verdict, and never show a checkmark. A local install runs and judges them as before. A green managed doctor carries no evidence on these eight rows: what stands behind them is the engine's boot checks, the live Chunk tenant isolation row, and the operator-side read-only query in `docs/runbooks/rdr-225-cloud-deploy.md`, and three of them (tuples.dead_tuple_ratio, tuples.sweep_freshness, Partition leaves) have no server-side check at all. The human output now ends with "N rows not checked on this deployment" when any row was skipped.
- **`mcp.claude_code_connection` no longer reports a weeks-old failure as the latest connection.** Run from a directory whose only ancestor log directory was `/`, it read a stale log and reported "ENOENT, executable not found: stdio" while the server worked. It now ranks the logs of every project directory Claude Code writes under by when they were last written (the current directory's own win only a tie), treats a newest log that ended in a successful connection as the current state, and does not judge a log last written more than 7 days ago: the row says "no recent connection log".
