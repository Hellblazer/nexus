### Fixed

- **`nx doctor`'s Upgrade ladder row and the version-change callout no longer send a managed client with `mint_token` configured to `nx upgrade` for `retire-keys-sweep`.** Such a client presents the minted data token on every route, and the sweep route takes a tenant or root credential and refuses it with 403, so an interactive `nx upgrade` cannot run the sweep. The row now says "not applicable on a managed deployment with mint_token configured: retire-keys-sweep (its sweep is the operator verb `nx t3 retire-keys`, which needs the root token and runs from a host without mint_token)", leaves the rung out of the warning and the checked count, and renders `[ ]` when it is the only rung; the callout says the same. The test is `mint_token` configured and nothing more: a managed client with a tenant or root credential, a static data-scope token without `mint_token`, and a local install still show "not checked" with the warning. `rdr192-manifest-backfill` is unchanged.
