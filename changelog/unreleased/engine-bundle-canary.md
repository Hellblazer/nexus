### Added

- **An engine-bundle canary tests a new engine tag's PG bundle before a client release pins it.** develop CI runs the substrate only on the bundle of `REQUIRED_ENGINE_VERSION`, so a bundle change (the pgvector 0.8.2 to 0.8.7 move in `engine-service-v0.1.194` raised the migration's DDL count by 147) first showed up as a red release PR. `.github/workflows/engine-bundle-canary.yml` runs once per engine tag, on `release: published` for `engine-service-v*` and on `workflow_dispatch`, and `engine-service-release.yml`'s `promote-release` dispatches it after promoting the draft. `scripts/engine_bundle_canary.py` fetches the tag's bundle, runs the journey tests on it, compares `ddl: migration=N` with `tests/ddl_ceiling.toml` `migration_ddl_per_worker` (tolerance 0), and fails on a mismatch, a red test or a run that measured nothing.
