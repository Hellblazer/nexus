### Added

- **An engine-bundle canary tests a new engine tag's PG bundle before a client release pins it.** develop CI runs the substrate only on the bundle of the engine pin, so a bundle change (the pgvector 0.8.2 to 0.8.7 move in `engine-service-v0.1.194` raised the migration's DDL count by 147) first showed up as a red release PR. `engine-service-release.yml`'s new `bundle-canary` job calls `.github/workflows/engine-bundle-canary.yml` after `promote-release` publishes the tag (the workflow also runs on `release: published` and `workflow_dispatch`, once per tag, never per push); read it as a job of the tag's engine release run. `scripts/engine_bundle_canary.py` measures `ddl: migration=N` on the pinned bundle and the tag's bundle, with each one's PostgreSQL and pgvector version in the job summary. It fails when the pinned count is above the `tests/ddl_ceiling.toml` ceiling, a test is red, or nothing was measured; a pinned count below the ceiling, or a tag whose count differs from the pinned one, is a warning that names the ceiling change.
