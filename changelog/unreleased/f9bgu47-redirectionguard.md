### Fixed

- **An upgrade on Windows 11 no longer breaks every launcher, and a rollback works, when RedirectionGuard is enforced.** The installer flipped `tools\current` and `tools\previous` as directory junctions made by your non-elevated process, and the user PATH named `tools\current\bin`. With the mitigation enforced system-wide, Windows refuses to follow a junction made without administrator rights (WinError 448: `nx`, `nx-hook` and `nx-mcp` stopped resolving, and rolling back through `previous` failed the same way); a directory symlink is not an alternative, since it needs Developer Mode (WinError 1314). `current` and `previous` are now plain files that name a generation, so nothing is traversed, and the user PATH names `tools\bin`, a folder of small fixed launchers (one per command, built once into a `tools\shim` environment) that read `current` and run that generation's own launcher. A flip replaces one file and no launcher, so it works while `nx-mcp`, the supervisor or a hook is running, and it leaves no instant where `current` is missing. Measured on Windows 11 build 26300 as a non-elevated user: a junction is refused on traversal, a symlink is refused on creation, and a launcher copied into a fixed folder cannot be renamed or replaced while it runs (WinError 32 and 5), so the fixed launchers read a pointer instead.
- **An install from before this change converts itself.** Both pointers are read without being traversed, `nx self install` (and the repair it runs) turns each junction into a pointer file, builds the launchers, and replaces the old `tools\current\bin` PATH entry with `tools\bin`; `nx uninstall` takes both entries off. A rollback to a `previous` that is still a junction works and leaves both pointers as files. The upgrade run by an older `nx` can still flip with the old code; the next `nx self install` from the new one finishes the conversion.
- **A PATH entry that cannot be traversed no longer raises.** `Path.exists`, `Path.is_file` and `resolve()` raise `OSError` 448 on a path through an untrusted junction, where the probes were meant to say no. The doctor's user-PATH row, the generation reap (which now also sees a pointer-file ledger entry), the orphan-uv row and the real-Windows hook launcher test's PATH filter use probes that answer no. The plugin's hook launcher and the version-lockstep hook read a pointer file.
