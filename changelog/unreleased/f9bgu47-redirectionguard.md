### Fixed

- **An upgrade on Windows 11 no longer breaks every launcher, and a rollback works, when RedirectionGuard is enforced.** The installer flipped `tools\current` and `tools\previous` as directory junctions made by your non-elevated process, and the user PATH named `tools\current\bin`. With the mitigation enforced system-wide, Windows refuses to follow a junction made without administrator rights (WinError 448: `nx`, `nx-hook` and `nx-mcp` stopped resolving, and rolling back through `previous` failed the same way); a directory symlink is not an alternative, since it needs Developer Mode (WinError 1314). `current` and `previous` are now plain files that name a generation, so nothing is traversed, and the user PATH names `tools\bin`, a folder of small fixed launchers (one per command, built once into a `tools\shim` environment) that read `current` and run that generation's own launcher. A flip replaces one file and no launcher, so it works while `nx-mcp`, the supervisor or a hook is running, and it leaves no instant where `current` is missing. Measured on one Windows 11 machine (build 26300), in a non-elevated process started from an ssh session: a junction is refused on traversal, a symlink is refused on creation, and a launcher copied into a fixed folder cannot be renamed or replaced while it runs (WinError 32 and 5), so the fixed launchers read a pointer instead. A process started by Task Scheduler on the same machine was not enforced, so how widely this bites depends on how your processes are started; the fix is safe either way.
- **After the upgrade, open a new terminal and restart Claude Code and any MCP host.** A terminal or host that was already open has a PATH that still names `tools\current\bin`, which no longer exists, so it will not find `nx` until it is restarted. `nx self install` prints this when it changes the PATH.
- **Each `nx` typed at a prompt now starts Python twice** (the fixed launcher, then the generation's own): about 110 to 140 ms more on the machine measured, where starting Python took about 106 ms. The plugin's hooks and MCP server resolve the pointer themselves and do not pay it.
- **An install from before this change converts itself.** Both pointers are read without being traversed, `nx self install` (and the repair it runs) turns each junction, the legacy ledger entry included, into a pointer file, builds the launchers, and replaces the old `tools\current\bin` PATH entry with `tools\bin`; `nx uninstall` takes both entries off. A rollback to a `previous` that is still a junction works and leaves both pointers as files. That older generation's own `nx` cannot flip or upgrade once `current` is a file, and `nx` says so when it makes such a generation current; run `nx self install` from a newer release to move off it. The same holds for an older `nx` that drives an upgrade.
- **A damaged pointer no longer strands the install.** A pointer is written and synced before it replaces the old one, with LF line ends. An empty or headerless `current`, `previous` or ledger file (a restored backup, an antivirus rewrite) is replaced by the next flip rather than refused, and `nx` tells you to rebuild with `uv tool run --from conexus nx self install --bootstrap` when it cannot find a generation. A directory, or a file larger than a pointer, at one of those names is still refused.
- **The Ctrl-C of a command run through the launcher reaches that command.** The launcher waits for the generation's program instead of killing it a quarter second after Ctrl-C.
- **`install.ps1` finds `nx` after a good build.** It looked in `tools\current\bin`, which is nothing now, and exited 1 after a successful install; it looks in `tools\bin` first and in `current\bin` for an older install.
- **A PATH entry that cannot be traversed no longer raises.** `Path.exists`, `Path.is_file`, `Path.is_dir` and `resolve()` raise `OSError` 448 on a path through an untrusted junction, where the probes were meant to say no. The doctor's user-PATH row, the generation list and reap (which also sees a pointer-file ledger entry and no longer opens every file of a generation), the orphan-uv row and the real-Windows hook launcher test's PATH filter use probes that answer no. The plugin's hook launcher and the version-lockstep hook read a pointer file, and ignore a damaged or relative one.
