### Added

- **A generation carries a lease, and gc never deletes one a live interpreter holds.** Every generation built from this release on gets a `.nx-lease` file, a `_nx_lease.py` hook and a `_nx_lease.pth` in its site-packages; each interpreter started from it takes a shared lock on the lease for its life (a held handle on Windows). The process census finds a process by the `gen-<stamp>` text in its command line, so it cannot see one started through `tools/current/...`, one that rewrote its title or one whose command line was cut. gc now asks the lock instead (rule (e), ORed with the census), re-takes it just before the delete and holds it through, and records each generation's lease state (`gc_run.lease`). Generations built before this release have no lease and are guarded by the census alone, until their processes restart. A filesystem without locks (some NFS) falls back to the census and logs `lease_unsupported`; any other lease error keeps the generation for that run. The builders check the lease with a live child and warn if it does not read held.
