### Fixed

- **The `search` MCP tool shows an identical chunk once, not once per collection** (GitHub #1524). The same text indexed in several collections (the RDR template's README, byte-identical in every repo that ships it) is one chunk in each and used to rank first once per collection. `search` now keeps the best-ranked row and names the other collections on it: an `also in:` line in the text result, and an `also_in` list aligned with `ids` in the `structured=True` result, present only when some row has copies. Paging with `offset` still reaches every row. A copy that is sensitive now makes the row it collapses into sensitive and is not named, in `search` and in `query`. `query` and `nx_answer` have collapsed copies since 7.38.0.
