### Fixed

- **`/conexus:nx-preflight` no longer reports a healthy `nx doctor` as unavailable.** `nx doctor` took about 45 s on a healthy install and the preamble bounded it at 15 s, so check 2 could never pass. Doctor now has its own bound (`_DOCTOR_TIMEOUT`, 120 s), a timeout says "nx doctor exceeded 120s; not a failure; run 'nx doctor' directly", and an engine that accepts a connection but does not answer `/health` within 5 s is a WARN naming it, at once, instead of a wait for the long bound. Any HTTP answer, and a refused connection, run doctor as usual (GH #1689).
- **The preamble's CLAUDE.md language check stops guessing.** It matched case-insensitively, so the verb "go" read as Go, Java matched inside JavaScript and Rust inside "rusty", and Lua was missing. Names now match on word boundaries (so `python` and `typescript` in a command line still count), Go needs a cue that cannot be the verb (a version, Golang, `go.mod`, "written in Go", or a go tool command in a code span or at a line start), and Lua and JavaScript are detected (GH #1689).
- **A `bd` with no beads database is no longer reported as "printed nothing" or "unavailable or no results".** `nx brief beads` and the `nx command-context` beads blocks now say "there is no beads database here" for that case, and name the exit code and first stderr line for any other `bd` failure or timeout. The console's needs-sam read, `nx brief` and the preamble share one detector, `nexus.beads_state` (GH #1689).
- **`nx brief beads` prints the `bd prime` primer after a clean, empty `bd ready`.** A project with the beads plugin off and no ready beads used to get no primer, because the hook's runner returned nothing for both an empty list and a failure; it now tells them apart, and only a failed or missing `bd` skips the primer (GH #1689).
