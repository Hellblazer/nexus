### Fixed

- **`nx index pdf` keeps a real title that happens to equal the file name, and `--collection` alone sets the catalog corpus** (GH #1611). A PDF whose metadata title or first heading read the same as its title-cased file name was treated as an untitled placeholder, so a later run could overwrite it; the title is now a fallback only when it came from the file name. The existing-title side is unchanged: a catalog title that equals the file name or its title-cased form is still taken for a placeholder, so a stem-equal title already on a row can be replaced by a later run that finds a real title. With `--collection` naming a knowledge collection (or a bare name) and no `--corpus`, the catalog corpus was `default`; it is now the collection's subject (`agentic-data-systems` for `--collection agentic-data-systems` or `knowledge__agentic-data-systems__...`); a `docs__` or `code__` `--collection` still gives `default`, and `--corpus` still overrides it. Documents registered earlier under `default` keep that corpus; re-indexing one with `--collection` alone now resolves onto that row as another owner's and logs `doc_register_resolved_onto_foreign_owner_row` (pass `--corpus default` to keep it under the old owner).
