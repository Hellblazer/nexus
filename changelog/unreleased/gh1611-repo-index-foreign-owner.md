### Fixed

- **`nx index repo` no longer writes chunks for a file another owner's document holds in another collection** (GH #1611). When a file inside a repository was already catalogued by another owner (`nx index pdf <file> --collection ...`, say), the repo run resolved onto that document and wrote its chunks into the repository's collection under the other document's id, where the document's own collection did not have them: search scoped to that collection missed the file and its live count fell. The repo run now looks up the other owner's row and, when it holds a collection other than the one the run writes the file to, skips the file: it gets no document id, is named in a warning (`catalog_register_skipped_foreign_owner`, with both collections) and in the run's summary, does not count as a failure and does not flag the other owner's document for `--sensitive-glob`. The skipped file is no longer in the repository's own collection, so a search scoped to that collection does not return it; the other owner's collection still has it. A row that holds the run's own collection, or none, is adopted as before (the file keeps its tumbler and is counted `reconciled`), and a row that cannot be read fails the file for the run (`register_refused`) so the next run retries it.
