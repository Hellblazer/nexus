### Fixed

- **A resumed session keeps its identity when the machine's hostname has changed (#1679).** Bindings named their machine by `socket.gethostname()`, which on a laptop follows DHCP and VPN, so a restart on a new network met its own old binding as "held on another host", judged it by its lease alone and, the lease still being live, bound a new ephemeral identity instead of rebinding the one whose holder pid had died on this very machine. The host a binding carries is now `nxh1-` plus an HMAC of an identifier the OS keeps for the life of the install: the hardware UUID on macOS, `/etc/machine-id` on Linux (only in the initial pid namespace and only when it is a valid initialised id), `MachineGuid` on Windows. With no such identifier, or where two process tables could share one, it stays `gethostname()`. A row written under the machine's current `gethostname()` still counts as this host, so this upgrade strands no live seat; a row written under a name the machine no longer has is judged by its lease once, as before. A process bound under its old hostname keeps speaking under that name on `clear`, `fork`, `refresh` and a self-release, because the engine compares the host as a string. The ephemeral identity a refused session falls back to now keeps the display name instead of dropping it.
