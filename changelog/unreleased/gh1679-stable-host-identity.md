### Fixed

- **A resumed session keeps its identity when the machine's hostname has changed (#1679).** Bindings named their machine by `socket.gethostname()`, which on a laptop follows DHCP and VPN, so a restart on a new network met its own old binding as "held on another host", judged it by its lease alone and, the lease still being live, bound a new ephemeral identity instead of rebinding the one whose holder pid had died on this very machine. The host a binding carries is now `nxh1-` plus an HMAC of an identifier the OS keeps for the life of the install: the hardware UUID on macOS, `/etc/machine-id` on Linux (only in the initial pid namespace and only when it is a valid initialised id), `MachineGuid` on Windows. With no such identifier, or where two process tables could share one, it stays `gethostname()`; a failed probe is retried and logged (`host_key_unavailable`), never cached for the life of the process, and the key is never written to disk. A key names exactly one machine. A row written under a plain hostname (before this release, or by a machine with no key) counts as this machine's only on local proof: a token file in this machine's identity directory for that process, recording that host. So a session bound under `.102` whose machine is now `.105` is still its own, live or dead, and another machine that happens to share the hostname is never judged by this machine's pid table; the proof can be wrong only when the identity directory is shared or copied between machines, and only for rows under a plain hostname. A process bound under its old hostname keeps speaking under that name on `clear`, `fork`, `refresh` and a self-release, because the engine compares the host as a string. `nx identity` messages show the hostname with the key in parentheses for this machine's holders (`<hostname> (nxh1-...)`) and `another machine (nxh1-...)` for others. `lab-remote` `labrun` work rows are judged against the machine's short hostname as before. The ephemeral identity a refused session falls back to keeps the session's display name (the held identity's own when it is this session's, else the name Claude records), never a seat's alias or another session's name.

  Not fixed here: the seat of a row under a name this machine has no token file for (another host's, or this machine's after its identity directory was cleared) is judged by its lease, as it always was. A leased binding frees 15 minutes after its holder stops renewing (5 minutes to lapse, then the 10-minute reservation); an unleased (Desktop) binding does not lapse, and a refused session does not retry, so it needs `nx identity claim <seat> --take-over`. A binding's lapse and revive rows, one pair per renewal gap over 300 seconds (a sleeping laptop writes many), are the engine's lease design and are unchanged.
