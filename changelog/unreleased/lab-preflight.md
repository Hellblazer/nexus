### Added

- **`scripts/lab-preflight` tells `lab-remote` before dispatch that a pytest run would be refused at once (labrun-0uy.2.4).** Run as `python3 scripts/lab-preflight -- <argv...>` in the host copy, it exits 75 with one line when the command is one simple pytest command that can boot the engine substrate (`NX_TEST_T2_SUBSTRATE` is not `none` or a retired value; `-m lint` and `--collect-only` still count) and `service/target/nexus-service-1.0-SNAPSHOT.jar` is not built. The line says to run `scripts/build-gate-jar.sh --lab-run <class>` in the copy as its own step first, or to set `NX_TEST_T2_SUBSTRATE=none`. A `lab-remote` copy has no `service/target/`, so the first engine-substrate run used to queue for a hand grant and then exit 75 within seconds: labrun-0uy.2.4 counts 151 such rc=75 hand grants on chas since 10-18, and of the 9 it read, 6 were "service jar not built", 2 a held build lease and 1 a held suite lease. The lease refusals remain: a held suite or service build lease in the copy only warns on stderr and exits 0, since it can be gone by the time the run leaves the queue. A stale jar and a lease held by another copy are out of scope. A compound command (`&&`, `;`, `|`), a command that only mentions pytest (`uv pip install pytest`), and any error of the script's own exit 0. Stdlib only, no network, no engine.
