### Added

- **A CI board notice carries the commit its result is for** (nexus-1d6pz.11.3). The channel's notice for a `board/ci/<repo>-<branch>--done` post has `sha="<40 hex>"` in its meta (a batch has `shas`, aligned with `tuple_ids`, `-` where no sha could be vouched for), so a session can tell which push a wake is for without a `tuple_rd`; `nx tuple wait` renders the same notice. The sha comes from the row's `sha` dim once the adapter writes it (engine v0.1.184), else from the row body, and only when it is exactly 40 lowercase hex digits; it is kept out of the notice text, which stays built from identifiers the server controls. `scripts/git-push-develop.sh`'s `PUSH_WAIT` channel line names the sha a wake for the push carries. A notice for another sha is not to be ignored on that alone: in a push window, beads close on the window tip's result, which is often a peer's sha.
