### Added

- **`nx ci wait <sha>`: one wake for a pushed sha, with the result, in a session launched without the channel** (nexus-1d6pz.11.4). It parks on the CI board's `--done` topic (`board/ci/<repo>-<branch>--done`) until the sha's row is there (a row already there counts and the newest wins after a rerun; `--fresh` counts only a row that arrives after the wait starts, for a wait on a rerun), prints one line with each run's workflow and conclusion and the run URL, and exits 0 on success, 1 on a failure, 3 when runs were cancelled or stale, 2 on timeout, 4 when a conclusion could not be read or disagrees with the board's outcome, and 5 when the wait could not run (not a sha, or the board unreadable to the deadline; a failed read is retried every 5 s). The wait reads the tuple space only; a row written before the board carried conclusions gets them from one `gh api` read per run attempt, and at the deadline a full sha's push runs are read from GitHub once, so a dropped board wake still reports finished runs. A row capped by the adapter's 1024-byte limit (its `n` counts more runs than it lists) is never read as success from the runs it lists: a listed failure settles it, and otherwise the sha's push runs are read from GitHub once and used only when they are the board's runs by identity (exactly `n` runs, the listed ids at the attempts the row names, every dropped run on its first attempt); anything else, a rerun since the row included, is unknown (exit 4). `scripts/git-push-develop.sh` prints, on stderr after `PUSH_OK`, both waits: the `tuple_subscribe` call for a session with the channel and `nx ci wait <tip>` to run as a background command.
