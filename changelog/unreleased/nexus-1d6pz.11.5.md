### Added

- **The Stop-hook wake guard counts a covering CI wake as armed** (nexus-1d6pz.11.5). It blocked a turn ending "I'll read the CI result" while the session was subscribed to `board/ci/nexus-develop--done` with the channel loaded, a wake that worked, which pushed sessions back to a polling Monitor. The nexus MCP server's channel status record (`<config>/tuple-watch/channel-status.d/<session id>`) now carries the channel launch flag, whether the client's initialize handshake was seen, and the subscribed board topics, and is rewritten when a subscription changes. A closing develop-CI wait (a clause about CI, checks, runs, a workflow or the push, not a PR, release, reviewer or deploy) is allowed when that record shows a live, fresh, unstalled waiter, the handshake, the flag and a `board/ci/*--done` topic; any other clause in the message is still read, so a covered CI wait never hides a later promise. A live waiter with the subscription but no flag is not a wake: the block then names `nx ci wait <sha>` as the background command to run, and every CI-wait block now offers it. Accepted limits: the board wake is best effort, a present flag does not prove Claude Code registered the channel, and the record names topics, not shas.
