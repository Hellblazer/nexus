### Changed

- **Engine: `POST /v1/memory/search` takes a page and stamps only the rows it returns (RDR-209 Phase 0b).** With a `limit` in the body (and an optional `offset`, default 0), the engine returns rows `[offset, offset+limit)` in the same order as before, bumps `access_count` and `last_accessed` on only those rows, and answers `{"rows": [...], "matching_total": N}`. `N` is counted in the same SQL statement as the page, so a page past the end answers empty rows with the right total, stamps nothing and does not raise the "no searchable terms" error; a query with no searchable terms that matches nothing still raises it (a 400, `no_searchable_terms`), and a real miss answers an empty page with `matching_total` 0. A `limit` below 1 or not an integer and an `offset` below 0 or not an integer are a 400, and a `limit` above 10,000 is clamped to 10,000 as `/v1/memory/list` clamps its own. A request with no `limit` is unchanged: the bare list of every match, every match stamped, `offset` ignored. The client and the `memory_search` tool send their page in a later change.
