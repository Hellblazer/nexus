### Added

- **The 2-week check review and the step 7 batches have a script (RDR-258 Phase 1).** `scripts/check_review.py record --since D --until D` writes the review record. For each class-A check in report mode it gives the clock (the oldest commit of the current unbroken report-mode stretch, dated by the first develop push CI run that holds it), the failing items per run from the `class-a-items` artifacts (read through `gh api` or a local directory), the guard catches, a numeric check's value, headroom and trend, every test quarantined over 14 days, and every check whose count rose. A guard catch is an item that failed in one run and not the next (line numbers ignored) across a range that touched a `guards:` path and no ledger, ceiling or allowlist file, with the failing count falling or the failing path fixed. A check is due at 60 days with no catch, `disposition: delete` by default, only when the artifacts cover at least 80% of the days with no gap over 3 days: a run that did not examine the check is no evidence, and expired artifacts or a capped run list are holes. A check with no `guards:` header, or stuck on evidence past 75 days, is listed for a decision instead. `check_review.py deletion-plan RECORD` works at the level of tests: it lists the class-A tests to remove and the unmarked ones that stay, removes a whole module only when every test is class-A (or `module_whole` with a reason), cross-checks the record (every due check has an entry, nothing is planned from a check that is not due), and refuses a `retire-early` without a full ancestor cause-fix sha that touches the guards, its written statements and its evidence. `check_review.py batch --report FILE` proposes the next review batch from the Phase 0 baseline: class-A checks not yet demoted and not owned by Phases 2 to 4 (an explicit list), largest red-run count first, each with the tests to mark, the push-gate and CI lines to change and, for a numeric check, a proposed alarm line, stopping at the exact 30% share and printing the bound from the current extraction beside the RDR's. A check with no `class:` header is listed as unclassified and never batched (nexus-2jomg.2).
