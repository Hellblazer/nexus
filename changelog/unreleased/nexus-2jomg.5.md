### Added

- **`NX_LEDGER_MODE=report|block`: one switch for the three class-A ledger checks (RDR-258 Phase 4).** The plugin ledger (`tests/test_plugin_release_drift_ledger.py`), the changelog fragments (`scripts/changelog_fold.py check`, also `--mode`) and the cloud-leg route ledger (`tests/scripts/test_cloud_leg.py`) list a finding instead of failing it when the variable is `report`: one `LEDGER-FINDING <ledger>: ...` line each (a `::warning::` annotation too under GitHub Actions) and one `LEDGER-REPORT <ledger>: N finding(s), M item(s) examined` line. A check that examined nothing still fails. Unset or `block` is today's behaviour, and any other value is an error. `NX_LEDGER_REPORT_FILE` also collects the lines, since a pytest-xdist worker's output is lost. The push gate runs the three in `block` (`Spec.default_mode`) unless `--ledger-report '<reason>'` puts them in report mode on the record; it ignores `NX_LEDGER_MODE` in the environment, prints each check's mode and relays a passing report as `PUSH_CHECK_REPORT` lines (eight per check, then `+N more`). Nothing is turned to `report` yet. Helper: `scripts/ledger_mode.py`.
- **`scripts/changelog_coverage.py`: lists each commit of a range that changes shipped code and has no changelog fragment naming its bead.** `changelog_fold.py check` sees a fragment's format and could not see a missing one. Shipped code is `src/nexus/`, `service/src/main/`, `mcpb/src/` and the two install programs; the plugin trees stay with the plugin ledger. A bead counts as covered by a fragment name, by a `(nexus-...)` citation in a fragment or `CHANGELOG.md`, or by a sibling under the same epic that an entry in the range cites; a comment- or docstring-only change and a `Changelog: none` trailer are exempt. It runs under the same `NX_LEDGER_MODE`, over `merge-base(origin/main, HEAD)..HEAD` by default. Nothing runs it yet.
