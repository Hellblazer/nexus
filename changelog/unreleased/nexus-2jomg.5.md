### Added

- **`NX_LEDGER_MODE=report|block`: one switch for the three class-A ledger checks (RDR-258 Phase 4).** The plugin ledger (`tests/test_plugin_release_drift_ledger.py`), the changelog fragments (`scripts/changelog_fold.py check`, also `--mode`) and the cloud-leg route ledger (`tests/scripts/test_cloud_leg.py`) list a finding instead of failing it when the variable is `report`: one `LEDGER-FINDING <ledger>: ...` line each (a `::warning::` annotation too under GitHub Actions) and one `LEDGER-REPORT <ledger>: N finding(s), M item(s) examined` line. A check that examined nothing still fails. Unset or `block` is today's behaviour, and any other value is an error. `NX_LEDGER_REPORT_FILE` also collects the lines, since a pytest-xdist worker's output is lost. The push gate runs the three in `report` (`Spec.default_mode`; a default is not an override, so nothing is recorded), and `--ledger-report '<reason>'` also asks for it, on the record; it ignores `NX_LEDGER_MODE` in the environment, prints each check's mode and relays a passing report as `PUSH_CHECK_REPORT` lines (eight per check, then `+N more`). The three report on develop (a push, or a pull request into develop) and block on the release pull request into main and anywhere else CI runs them (RDR-258 Phase 4 step 2, Sam 2026-11-28); CI's lint leg collects the report lines of its xdist workers in `NX_LEDGER_REPORT_FILE` and prints them in a step of its own. Helper: `scripts/ledger_mode.py`.
- **`scripts/changelog_coverage.py`: lists each commit of a range that changes shipped code and has no changelog fragment naming its bead.** `changelog_fold.py check` sees a fragment's format and could not see a missing one. Shipped code is `src/nexus/`, `service/src/main/`, `mcpb/src/` and the two install programs; the plugin trees stay with the plugin ledger. A bead counts as covered by a fragment name, by a `(nexus-...)` citation in a fragment or `CHANGELOG.md`, or by a sibling under the same epic that an entry in the range cites; a comment- or docstring-only change and a `Changelog: none` trailer are exempt. It is a fourth check under the same `NX_LEDGER_MODE` (`block` unless a caller says `report`), over `merge-base(origin/main, HEAD)..HEAD` by default. Wherever it runs it only reports (Sam, 2026-11-28): on the release pull request into main (a step of `release-ledger-gate`, where the fragment format check `changelog_fold.py check` still blocks), on a develop push (the push gate's `changelog-coverage` check: `PUSH_CHECK_REPORT` lines over the outbound range; a crash, an exit 2, a missing script, a timeout or a range that examined no commit still refuses; `--skip-changelog-coverage '<reason>'` overrides it on the record) and in a step of CI's `changes` job on a push to develop or a pull request into develop. A push range of merge commits only (a release back-merge) and a range of release-preparation and revert commits only pass with a `PUSH_CHECK_NOTE ... examined nothing` line instead of a refusal; the suite pins that a range with real commits is examined and that an exit 10 with no vacuous line refuses. It moves to block once its findings stay clean.
