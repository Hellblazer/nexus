### Added

- **Text `search` hits carry a short chunk id, and `store_get_many` takes it.** Each hit prints `id=<8 hex>`; `store_get_many` expands a short id this session's searches showed to the full chunk id and, for a flat id list with `collections` at its default, looks it up in the collection the hit came from. An ambiguous id, one never shown, or one missing from an explicit scope is reported with what to pass instead.
- **A superseded document says so in text search.** A hit whose owning documents are all the target of a catalog `supersedes` link is annotated `superseded by <title> (linked <date>)` and ranked lower; a chunk a current document still holds is left alone, and a sensitive successor is named only as "a withheld document". Only the MCP `search` tool applies it (its structured result carries the note as `superseded_by`, aligned with `ids`), and not when a server rerank orders the page.
