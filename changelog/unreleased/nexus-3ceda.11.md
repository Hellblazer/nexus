### Fixed

- **A search `where` with two or more clauses, one of them an operator, no longer fails every collection with HTTP 400** (nexus-3ceda.11). `content_type=pdf,bib_year>=2020` used to become `{"$and": [...]}`, which the engine refuses; clauses on different fields now go as one filter, which the engine ANDs. A range on one field (`bib_year>=2020,bib_year<=2024`) has no form the engine accepts yet, so it is refused up front, with a message naming both clauses and a workaround, instead of a 400 from every collection. The legacy span fallback in `catalog_spans` sent `$and` too and now sends one filter. The in-memory vector store that unit tests read through accepted `$and`, which is why no test caught this; it now refuses what the engine refuses and supports `$nin`. A new seeded differential test, `tests/test_where_filter_differential.py`, asks the in-memory store and the engine's get and search paths the same filters and names the side that disagrees.
