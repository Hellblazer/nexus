### Added

- **A swallowed hook crash saves its input, and `nx hook replay` runs it again.** A hook never fails the session, so a crash was swallowed and the input that caused it was lost. The input now goes to a bounded local ring under `~/.config/nexus/hook-failures/` (50 entries, 2 MiB, 128 KiB an entry), and the hook's stderr line names the file. Prompts and commands are kept as they were apart from credentials, which are masked (authorization headers, `NAME_TOKEN=` assignments, PEM private keys, cookies, URL userinfo, known token prefixes, credential-named keys); the environment is cut to nexus and Claude Code variables without credential names. `nx hook failures` lists the entries; `nx hook replay PATH` runs the recorded verb on the saved input outside the never-fail boundary, so the crash raises with its traceback; it refuses a module that is not a hook verb, and applies the recorded environment flags and working directory only with `--recorded-env`. `NX_HOOK_FAILURE_RING=0` turns the capture off (nexus-3ceda.3).
