### Changed

- **Engine: one bad label in a collection import refuses that row, not the batch (RDR-229 item 10, nexus-3ptnh).** `POST /v1/catalog/import/collection` used to answer 400 for the whole batch when a new row's label broke the P3.6 rule (or held a NUL or a lone surrogate). It now imports every other row and answers 200 with a new `refused` list beside `imported` and `state_corrected`: one `{name, rule, reason}` per refused label, in the order sent. `rule` is one of `non_empty`, `valid_utf8`, `no_control_character`, `within_byte_limit`, `no_slash`, `no_comma`, `no_edge_whitespace`; `reason` is the message the 400 carried. `imported` counts the rows sent that were not refused (a label repeated in the batch is one `refused` entry, and every row sent under it is left out of `imported`). A lone surrogate in a refused label is written as its `\uXXXX` escape. A body with no `rows` key is one row and is reported the same way (it was a 400). An existing row is still skipped whatever its label, and the minted-form clause (`c` and digits) is still not applied on import. Other refusals of the route (a blank `content_type`, a supplied `collection_id`, a state that disagrees with the name) still refuse the whole batch, except for a row already refused for its label, which no other check judges. An older engine omits `refused`, which reads as none; no current client calls the route.
