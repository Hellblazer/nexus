### Changed

- An index rebuilt by hand is now seen by the engine. `REINDEX INDEX CONCURRENTLY` carries an index's anchor (its comment) across the swap, so the anchor kept describing the old build and the deletes-since-build rule and the 24 h floors counted from it. The anchor is now version 2 and records the index's `pg_class.relfilenode`, read on the same session right before the COMMENT. A pass that finds a version 2 anchor whose relfilenode differs from the index's re-anchors the index as built now (current rows and bytes, `built_at` now, origin `built`) and logs `event=pci_anchor_rebuilt_detected` with the old and new relfilenode; a leaf's own HNSW index with a version 2 anchor is handled the same way. A version 1 anchor (no relfilenode) stays valid and is left alone until the engine next writes it, when it becomes version 2. Anything else that rebuilds an index (a migration's REINDEX, pg_repack, VACUUM FULL) is detected too. Nothing for an operator to do: no recipe step, no hand-written anchor.
