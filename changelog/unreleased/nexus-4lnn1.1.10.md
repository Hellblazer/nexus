### Added

- **The engine reindexes a per-collection index when it has degraded, not on a timer** (nexus-4lnn1.1.10, RDR-230 Phase 2; engine only, rides the next engine tag). After each pass's drops and builds, the engine that holds the builder lock runs `REINDEX INDEX CONCURRENTLY` on at most two indexes, one at a time, largest first, when one of four events has happened: its bytes per row reached 1.4 times the build's (for an adopted index, 1.4 times the install's median for its dimension, or 8.2 KB per row at 1024 dimensions when no index was built here); deletes since the build reached 25% of its rows; its row count fell by 10% since the engine's previous check (which is followed by `VACUUM (ANALYZE)` of the leaf); or the recall canary is red on ten ring queries (a red on fewer is shown and triggers nothing), at most once a day per index. The old index serves until the swap and keeps its name, so the router never loses the collection. After each REINDEX the index gets a fresh anchor and the canary measures it again, with the red run's own queries when there were some; a re-measure that is still red is logged as `red_after_reindex` and not rebuilt until a green run or a day. A failed REINDEX gets the build backoff; one cut off by a migration is not charged. Pure ingest never triggers it. The thresholds are constants in `PciReindexPolicy`.
- **`NX_SEARCH_PCI_REINDEX`** (`1`, the default, or `0`; any other value refuses boot) stops REINDEX and the post-delete VACUUM alone: builds, drops and the canary continue. `NX_SEARCH_PCI=0` stops all of it.
- **`GET /v1/status` `per_collection_indexes.this_engine.maintenance`** now reports the REINDEX half: `reindex` (`on` or `off`), `reindexing` (`"in_flight"` while one runs, else null; the index name is not on this unauthenticated route), `last_reindex_at`, `reindexes`, and a new `unanchored` count (leaf indexes whose size rule has no install reference). [additive]

### Changed

- The reconciler recounts an index's rows when its size changed, not only when deletes moved, so the size rule divides bytes by a current row count.
