### Fixed

- **The subagent git-write guard no longer denies read-only git or text that spells a verb.** In the three weeks to 2026-11-25 it denied 2,199 subagent Bash calls, and 97% were not the harm it exists for: `git merge-base A $m`, `git stash list | head`, `git log --grep=commit`, `grep push scripts/git-push-develop.sh`, `cd <worktree> && git add`, a fetch chained with other text. It now reads the command with a strict lexer and judges each segment: a read-only git shape or a text command (`grep`, `cat`, `echo`, `ls`) may spell any verb word in its arguments, and a segment it does not recognise must pass the old rule on its own text. `git stash list` and `git stash show` pass; every other stash form stays denied. A command that holds a heredoc, a backtick, a comment, a brace, a backslash outside double quotes, an interpreter (`python`, `sed`, `eval`, `xargs`), a `git config` segment (apart from a scratch repository's `user.name` and `user.email`), or text that reaches a command through a pipe, a file, a variable or an alias is not admitted, and the old verdict stands. `checkout`, `restore`, `reset --hard`, `clean`, `rebase --abort` and any write in the primary checkout stay denied. Read-only options that run a program are refused: `ls-remote --upload-pack` and `--exec`, `grep -O` and its prefixes, `help -m` and `-w`.
- **A subagent may chain writes in a worktree git proves, push its own branch, and take three more shapes.** `git -C <worktree root> <verb> ...` calls chained with `&&`, and `cd <worktree root> && git <verb> ...`, pass with the same verbs and flags as the single `git -C` shape, plus the long spellings `--quiet`, `--verbose`, `--dry-run` and `merge --no-commit`. A command that admits a write may hold nothing else that could change the cwd, a path, the environment or HEAD before the write runs: besides its git segments it may carry only a plain `cd <literal>`, an inert text command or a plain assignment, and no `;`, `||` or newline separates the worktree writes. `git push [-u] origin HEAD` (or the branch name) passes for the branch that worktree has checked out, never `develop`, `main` or `master`, never with `--force`, `--delete`, `--mirror` or a refspec naming another branch, and never beside a `switch`, `rebase`, `reset`, `merge`, `cherry-pick` or `revert`. `git worktree add --detach <absolute path outside every repo>` passes. A scratch repository the same command creates under a temporary directory (`git init`, `git clone`, then `config user.name|user.email`, `add`, `commit`, and `fetch --depth`) passes.
- **The deny text is under half as long (2.9 KB to 1.4 KB).** It says what was denied, the one allowed shape and who to ask, and keeps the `isolation: worktree` remedy. The long config and side-effect addenda are unchanged and still appear only for those denials. The orchestration skill's reference says what a brief gives a subagent about git: the worktree root, provisioned before dispatch; the one shape, with no heredocs (write the message with the Write tool, then `git commit -F <file>`); and who pushes (by default the orchestrator).
