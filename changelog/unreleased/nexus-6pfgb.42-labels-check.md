### Added

- **Engine routes for a CHECK on `nexus.catalog_document_chunks`: a row that holds a section label must be a written row** (nexus-6pfgb.42, RDR-236; engine only, additive, no client verb; rides the next engine tag). `POST /v1/admin/manifest-labels-check/census` (read only, per tenant), `/add` (the CHECK `catalog_document_chunks_labels_written_check`, `labels_written OR (section_title IS NULL AND section_type IS NULL AND page_number IS NULL)`, NOT VALID) and `/validate` (reads `convalidated` first), root credential only, on the admin connection, never a Liquibase changeset and never at boot. Nothing calls them. Same refusals and answers as the manifest chunk-index routes (`admin_cannot_see_all_tenants`, `admin_probe_undercount`, `tenant_violates_constraint`, `constraint_run_in_progress`; `present`, `already_valid`, `absent`, `violating_after_add`), with its own run-lock key. A writer audit (in the runbook) found no engine writer that stores a label with `labels_written` false; the one way to is a request that says `labels_written: false` beside a label, which no client in this repository sends and which the CHECK then refuses with SQLSTATE 23514 (a single-document write route answers 409 with the constraint name and a `remedy`; a batch route answers 200 with the document in `failed_doc_ids`). The census is expected to read zero. The chunk-index and labels steps are one parameterised class pair (`ManifestCheckAdmin`, `ManifestCheckHandler`, over a `ManifestCheck`), mounted and bound by `ManifestCheckWiring`; the chunk-index wire shape is unchanged. Runbook: `docs/operations/manifest-labels-check.md`.
