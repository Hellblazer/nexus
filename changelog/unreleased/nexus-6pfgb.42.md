### Added

- **Engine routes for a CHECK on `nexus.catalog_document_chunks`: `chunk_index` must equal `position`** (nexus-6pfgb.42, RDR-236; engine only, additive, no client verb; rides the next engine tag). `POST /v1/admin/manifest-chunk-index-check/census` (read only, per tenant), `/add` (the CHECK `catalog_document_chunks_chunk_index_position_check` NOT VALID) and `/validate` (reads `convalidated` first), root credential only, on the admin connection, never a Liquibase changeset and never at boot. Nothing calls them. No writer in this repository sets the two columns apart (`chunk_index` is NOT NULL and a trigger fills it from `position`), so the census is expected to read zero; the engine does not force them equal, so after `add` a write that sends a different `chunk_index` (an older client, a tenant import) is refused. The count is every tenant's: a tenant with no token row is counted, an admin role that cannot see every row is 503 `admin_cannot_see_all_tenants`, and a census below a tenant-scoped count is 503 `admin_probe_undercount`. `add` and `validate` answer 409 `tenant_violates_constraint` naming each tenant while a row has `chunk_index` different from `position`; `add` answers `present` and `validate` `already_valid` or `absent` from the constraint's state without a count. Same machinery and wire shape as the catalog TTL CHECK routes, which are unchanged. Runbook: `docs/operations/manifest-chunk-index-check.md`.
