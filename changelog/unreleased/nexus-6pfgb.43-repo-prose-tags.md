### Fixed

- **`nx catalog backfill-meta` stamps `tags` on a non-markdown prose or rdr document in its repository's own docs or rdr collection.** The tag is the file's extension, as `nx index repo` writes it. Such documents were residue `ambiguous_indexer`, and since the RDR-236 sweep removed the chunk-row fallback a `tags=` filter missed them (up to 2766 on the nexus tenant). The rule is a policy, not proof of which indexer ran: a markdown-path write to the same file (`nx index md`, or `nx collection reindex` before nexus-rmp2p) would have tagged it `markdown`. Fill-only as before; an absolute, Windows or URI path, a document outside its repo's collections and a `.pdf` path stay residue, and a file there with no extension is now residue `no_extension`. The report and `--json` carry how many repository owners the run saw (nexus-6pfgb.43).
