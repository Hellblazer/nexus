### Added

- **A chunk write the engine refuses for its metadata keys now fails with one message that says what to do.** When the engine's chunk-key check is enforcing (RDR-236 Phase 4), a write whose chunk metadata names a key a chunk row does not carry gets HTTP 422 `chunk_metadata_key_refused` on `upsert-chunks`, `update-metadata` or the combined manifest writes (`append`, `append_many`, `write_many`). The client raises `ChunkMetadataKeyRefusedError`, which lists each refused key with its class and where the value lives instead (the first 10, then "and N more"), says the engine reported the request refused and that retrying will not help, and tells you to upgrade nx if it is older than the engine and otherwise to report the message. It is never retried and never turned into a re-registration. `nx` and the MCP `store_put` tool print it as one message, not a traceback, and `nx store put` and `store_put` no longer add "retry is safe" to it. A note write's failure text also no longer prints a doubled period when the engine's reason already ended in one.
- **`nx index repo` names the refused keys once and does not promise a retry.** A batch the engine refuses for chunk keys fails once, not halved and resent (halving a batch of F files used to send up to 2F-1 refused requests). The summary says how many files were refused, lists the distinct keys and their homes, and says a re-run is refused the same way; those files are no longer described as "retried automatically". They still hold the `--since-head` base back.
- **`scripts/chunk_key_enforcement_smoke.py`** exercises each client kind's write path against a local engine started with `NX_CHUNK_KEY_CHECK_MODE=enforce`: `nx store put`, the MCP `store_put`, `nx index repo`, `nx index pdf`, `nx index md`, a repo file big enough to be written as several requests, and `nx dt index` for a record you name. After its first write it sends each of the five refusing routes one deliberately bad request, requires the 422 (and stops if any route answers otherwise), counts each kind's chunks from the collections that moved, and exits non-zero on any refusal, failure, or kind that wrote too little. A kind it did not run is printed as `NOT PROVEN` and exits 4 unless you pass `--accept-unproven`. It refuses a URL that is not loopback, an engine that does not report `chunk_key_check_mode: enforce`, and any `nx` other than this checkout's, and gives its children an allowlisted environment.
