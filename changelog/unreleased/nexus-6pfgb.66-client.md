### Added

- **A chunk write the engine refuses for its metadata keys now fails with one clear message.** When the engine's chunk-key check is enforcing (RDR-236 Phase 4), a write whose chunk metadata names a key a chunk row does not carry gets HTTP 422 `chunk_metadata_key_refused` on `upsert-chunks`, `update-metadata` or the combined manifest writes (`append`, `append_many`, `write_many`). The client raises `ChunkMetadataKeyRefusedError` naming each refused key, its class (document, position, legacy or unknown) and where the value lives instead. It is never retried and never turned into a re-registration, and `nx` and the MCP tools print it as one message, not a traceback.
- **`scripts/chunk_key_enforcement_smoke.py`** exercises each client kind's write path once (`nx index repo`, `nx index pdf`, `nx store put`, the MCP `store_put`, and `nx dt index` for a record you name) against a local engine started with `NX_CHUNK_KEY_CHECK_MODE=enforce`, and exits non-zero on any refusal, any failure, or a run where every kind skipped. It refuses a URL that is not loopback and an engine that does not report `chunk_key_check_mode: enforce`.
