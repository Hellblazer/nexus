### Added

- **The engine now logs and counts client chunk writes that name a metadata key a chunk row will not keep, and names who sent them.** On `upsert-chunks`, `update-metadata` and the `write_many`, `append` and `append_many` writes that carry chunks, a request whose chunk metadata names any key other than `chunk_text_hash` and `embedding_model` gets a `chunk_metadata_key_would_refuse` log line. The line carries the route, tenant and collection, the offending keys (the unknown `other` keys first and in full, then the known classes `document`, `position` and `legacy`, each listed or collapsed to `class:+N`), the counts of offending and requested chunks, the client's `User-Agent` and `X-Nexus-Client-Version`, and the `source_agent` of the first offending chunk. It is limited to one line per route, tenant, collection, key set and client per minute, so a second writer in the same collection logs its own line. `GET /v1/status` gains `chunk_metadata_key_would_refuse_total` (one per request, never rate limited) and `chunk_metadata_key_would_refuse_by_route_class` (`route`, `key_class`, `count`; the labels are route names and the four classes, all fixed by the engine). Status carries no key name and no client text, because it has no tenant scope and any caller sees the whole engine's status: those strings are one tenant's. The per-key and per-client detail (key names, `User-Agent`, client version) is in the log line, which is rate limited per route, tenant, collection, key set and client and so names every distinct writer while its limiter has room (past 10,000 keys, new writers share one overflow line, so the log is a sample). The count is of requests that offered a key, taken before the write: it includes requests a later step refuses and chunks the append routes later drop, and does not see the engine's own writers (re-embed, gc restore) or a PDF row staged before an upgrade until a client uploads it. The write proceeds unchanged: this is the log-mode window before the engine refuses such writes (RDR-236 Phase 4 Step 2). `taxonomy__` and `quarantine-` collections are skipped (nexus-6pfgb.66).
