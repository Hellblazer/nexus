### Added

- **Engine: `topic_route` on `POST /v1/vectors/search-per-collection` (RDR-134 Step 3).** An optional `{"mode": "top1" | "band", "width": <similarity, band only, >= 0>, "min_coverage": <0 to 1>, "collections": [...]}`. For each collection it names (all of the request's but the code ones when `collections` is absent), the engine ranks the collection's topic centroids against the query vector it already computed, keeps the nearest topic (or every topic within `width` of it), and searches only the chunks assigned to those topics, with the same k, thresholds and sensitivity exclusion as the unscoped search. A collection with no centroids, no chunks or coverage below `min_coverage` (default 0.9, so a threshold under study is a request value, not an engine release) is searched unscoped. A code collection (by its registered content type) is never routed, whether `collections` names it or is absent: it is searched unscoped and reads `skipped`. Each `per_collection` entry then carries `topic_route_status`: `routed`, `no_topics`, `fallback` (the kept topics returned nothing, or the topic search failed) or `skipped` (not named, or the request carries `chash_allow` or `where`); the key is absent for a collection whose `error` is set. Three additive keys appear only when they have a value: `topic_route_error` (short text when the coverage reading, the centroid ranking or the topic search failed and the collection was searched unscoped), `topic_route_coverage` (the coverage ratio read) and `topic_route_topics` (topics kept); `topic_route_min_coverage` echoes the threshold used on every entry that carries a status. A routed search that returned rows is `routed` even when the client's `thresholds` then drop every one of them (the collection contributes no rows and `dropped` equals `raw_count`); only a routed search with no rows at all is `fallback`. A routed collection's `min_raw_distance` is over its routed subset. Failures that degrade a collection to an unscoped search: a coverage lookup that throws or answers nothing, a coverage count or centroid ranking cut by its share of the arm's budget, a centroid ranking that fails, a topic search that fails or times out under the search bound. Failures that do not: a spent fan-out budget is isolated to the collection as `fanout_budget_exhausted`, as for an unrouted arm; an expired request budget, pool exhaustion and any transient database failure (SQLSTATE class 08, 53, 57P, 40001, 40P01, 55P03) fail the request with 503, except inside the coverage count, which reads any failure as no coverage (`no_topics`). A request without `topic_route`, or with an empty `collections` list, is unchanged byte for byte. A bad `mode`, a `band` without a `width` of at least 0, a `min_coverage` that is not a number from 0 to 1, or a name not in `collections` is a 400. The `/version` capability flag follows in a later change.
