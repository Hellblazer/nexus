### Added

- **Client: `topic_route` on `search_per_collection` and `search_cross_corpus` (RDR-134 Step 5a-i).** Off by default: a caller that does not pass it sends the same request and gets the same result, and spends no capability probe. With `{"mode": "top1"}` or `{"mode": "band", "width": w}`, and an optional `"min_coverage"` (a number from 0 to 1, forwarded as given; the engine's default is 0.9; a value outside that range or not a number is a `ValueError` before any request), the client asks the engine to search each prose collection (knowledge, docs, rdr, paper) inside the topic nearest the query, but only when `GET /version` reports `vector_topic_route_supported` (new `HttpVectorClient.supports_topic_route()`, cached five minutes; an outage or a missing flag reads as unsupported and the request goes unrouted). `topic_route.collections` is always an explicit list of the prose names, so a code collection never carries the field, including on a local bge install where code and docs share one request; a request with `chash_allow` or a metadata `where` is left unrouted, as the engine would leave it. `per_collection` entries now keep the engine's `topic_route_status`, `topic_route_error`, `topic_route_coverage`, `topic_route_topics` and `topic_route_min_coverage`.
- **Client: the `search_topic_route` log event.** One event per `search_cross_corpus` call that asked for routing, with each prose collection's status, the counts of `routed`, `no_topics`, `fallback` and `skipped`, `unreported` for a collection that came back with no status (its arm errored, or the engine does not route), `unrouted_reason` when the whole request went unrouted, the `min_coverage` in force (the engine's echo when it sent one, else the value the caller asked for, `None` for the engine default), and per collection the `raw_counts` and `dropped` maps (rows the arm's top-k returned and rows the client's threshold removed, for the collections that carry a status), so a routed collection whose rows all fell to the threshold can be told from a short page. A request left unrouted by `chash_allow` or `where` counts every prose collection as `skipped`. A collection with `no_topics` or `fallback` that keeps reading so shows in the logs. The status set is a checked table, `src/nexus/tables/topic-route-status.toml`, held equal to the engine's enum by a test.
