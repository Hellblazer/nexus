### Added

- **`search.topic_route_nx_answer`: nx_answer can search prose inside the nearest topics (RDR-134 Step 7).** Values: `off` (the default), `top1`, or `band:<width>` (a similarity width greater than 0). When it is not `off`, every `search` and `query` step of an nx_answer plan whose scope is `taxonomy_domain: prose` asks the engine to search each prose collection (knowledge, docs, rdr, paper) inside the topic nearest the query, or every topic within the band. Code collections are never routed; neither is a `query` step on the catalog route (`author`, `content_type`, `follow_links`, `subtree`), a step that names a `topic`, or a combined-query step. A routed search takes the per-collection route by itself, whether or not `NX_SEARCH_PER_COLLECTION` is set, when the engine reports `vector_topic_route_supported` (on an engine that does not, the search keeps the default path), because it is the only route that can route; that route was measured about twice as slow as the default batched path on the cloud (nexus-tu8wp.3), so routed steps can be slower. Searches that are not routed are unchanged. The setting is read once per plan run. An unreadable value logs `topic_route_setting_invalid` and is treated as `off`. It takes effect only on an engine that reports `vector_topic_route_supported`; setting it back to `off` turns routing off without a release.
