### Changed

- **MinerU's pipeline weights now come from a nexus release asset, not Hugging Face.** A fresh install downloads about 1.2 GB (the 20 files the pipeline loads, each checked against a pinned size and sha256) from the immutable `mineru-pipeline-ed6b654c` release on Hellblazer/nexus into `~/.cache/nexus/mineru/`, as the same visible step before the first page that F34 added; one file per asset, so an interrupted download resumes at the file it stopped on. An existing install whose Hugging Face cache already holds the pinned snapshot (`opendatalab/PDF-Extract-Kit-1.0` at `ed6b654c`) is seeded from it with no download, and fetches only the files that do not match. Every MinerU process nexus starts (the server, the per-batch worker, the `nx doctor --check-mineru` probe) is pointed at that copy through `MINERU_MODEL_SOURCE=local` and a nexus-owned `mineru.json` that copies yours and sets `models-dir.pipeline`; your own file is never written. `MINERU_MODEL_SOURCE` is bypassed for nexus's processes (unset, `huggingface` and `modelscope` all use the nexus copy), except `local`, which still means your own models and is left alone. The `MINERU_FORMULA_CH_SUPPORT` formula model is not in the pinned set and keeps F34's Hugging Face fetch. Release assets carry the AGPL and Apache-2.0 texts and per-model notices (nexus-7t3w1, F35).
