### Changed

- **The per-collection route's lexical leg runs its text-gate probe once for all the request's collections instead of once per collection** (nexus-bbtc2; engine only, no client change; rides the next engine tag). The trigram and tsvector GIN indexes are per leaf (tenant x model), so each one-collection probe rebuilt the leaf-wide bitmap for the pattern before it ANDed it down to its collection: about 65 ms an arm for an identifier, 120 arms. The engine now runs one `text_gate_probe_<dim>` statement over every collection of the request as the first fan-out task, overlapping the vector arms. At 5,000 chashes or fewer each collection's lexical arm ranks that set with `text_gated_search_by_chash_<dim>` and skips its own probe. Above 5,000 (an unselective query such as `advisory lock` or `serialization`) one new statement, `nexus.text_gate_probe_by_collection_<dim>` (changeset `vectors-060-1`, three functions, same posture as the existing probes), returns the chashes per collection, or marks a collection dense when it holds 5,001 or more gated rows, and a dense collection ranks HNSW-first as before. Every arm ranks exactly the rows its own probe would have returned, in the same order, and any failure of the shared probe (a timeout, a spent budget) makes the arms run their own probes as they did. A request with one collection, or with `chash_allow`, shares nothing. `NX_SEARCH_ROUTE_SHARED_PROBE=0` turns the sharing off. `NX_SEARCH_ROUTE_LEXICAL` stays opt-in: this entry does not change that default. The request's `event=search_per_collection_lexical` log line gains `shared_probe=<selective|per_collection|fallback|off>` and `shared_probe_ms`.
