### Changed

- **The per-collection route's lexical leg runs its text-gate probe once for all the request's collections instead of once per collection** (nexus-bbtc2; engine only, no client change; rides the next engine tag). The trigram and tsvector GIN indexes are per leaf (tenant x model), so each one-collection probe rebuilt the leaf-wide bitmap for the pattern before it ANDed it down to its collection: about 65 ms an arm for an identifier, 120 arms. The engine now runs one statement over every collection of the request as the first fan-out task, overlapping the vector arms: `nexus.text_gate_probe_by_collection_<dim>` (changeset `vectors-060-1`, three functions, same posture as the existing probes) returns the chashes per collection, or marks a collection dense when it holds 5,001 or more gated rows. Each collection's lexical arm ranks its chashes with `text_gated_search_by_chash_<dim>` and skips its own probe, and a dense collection ranks HNSW-first as before. The function gathers the gated rows with a plan the planner may run in parallel (on a leaf where the trigram half names many candidates, as `advisory lock` does, the word-similarity recheck of each candidate is nearly all the cost), then applies the liveness test and the per-collection cap. Every arm ranks exactly the rows its own probe would have returned, in the same order, and any failure of the shared probe (a timeout, a spent budget) makes the arms run their own probes as they did. A request with one collection, or with `chash_allow`, shares nothing. `NX_SEARCH_ROUTE_SHARED_PROBE=0` turns the sharing off. `NX_SEARCH_ROUTE_LEXICAL` stays opt-in: this entry does not change that default. The request's `event=search_per_collection_lexical` log line gains `shared_probe=<per_collection|fallback|off>` and `shared_probe_ms`.
