### Changed

- **A one-word lexical query matches by exact substring instead of trigram similarity** (nexus-bbtc2; engine Liquibase `vectors-058` and `PgVectorRepository`, no client change, no wire change). For a query of 8 words or fewer the text gate admitted a chunk when its full-text lexemes matched or when `word_similarity` with the query reached 0.6. The trigram index lets through any chunk holding 60% of the query's trigrams anywhere, so an identifier made of common subwords got through on a large share of code chunks, and each of those was then compared in full at about 0.13 ms: `resolve_active_session_id` took 19-23 s on the live corpus. For a single token that half mostly admitted near-spellings and neighbouring identifiers rather than rows holding the token: over 20 identifiers in a 20,000-chunk check it added 5,731 rows, 5 of which contain the identifier. The engine now sets `nexus.lexical_trgm` to `substring` for a gate text that is one token after trimming, and the gate is then the full-text half or a substring match (`ILIKE`, so case-folded, with `\`, `%` and `_` escaped), which the same trigram index prunes. Known loss: a one-word query no longer returns a row that only resembles the word: a near-spelling, a neighbouring identifier (`resolve_active_session` for `resolve_active_session_id`), or the right identifier under a typo in the query. Every row containing the query string is still returned, so a partial identifier still finds its full forms; in the same check, 20 partial identifiers kept 821 of the 3,188 rows the trigram half had added. The evidence is one repository's 20,000 chunks and 20 identifiers. A one-word query is taken literally, punctuation included (`self.foo` or `foo()` must appear as written), and a CJK sentence written without spaces counts as one word. Queries of 2 to 8 words keep the trigram half, and a query separated by any whitespace, Unicode spaces included, is not one token. The rank functions that gate rows another scan produced (the HNSW-first plan, a request confined to a chunk set with `chash_allow`, the manifest paths) read the same setting for the one-token case, so every branch admits the same rows for it; above 8 words they still evaluate the trigram half, as before.
