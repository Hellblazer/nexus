### Added

- **`nx catalog repair-note-uris --merge` merges the stale-URI notes that have a live twin, and the stale notes that share one target, choosing the survivor by chunks** (nexus-bivz3.24, Sam's ruling "Chunks decide", RDR-231 Decision 6; client and engine, additive). For a stale note S and the twin W holding its target, W wins by default; S wins only if it holds chunks and W holds none, or both hold chunks and S's `indexed_at` is strictly newer; ties go to W (stale siblings tie to the lowest tumbler, and a twin shared by two stale rows is one group, so nothing chain-merges). "Holds chunks" is the catalog row's `chunk_count` column (what `nx catalog merge` reads for its chunk refusal), not a manifest recount, and the pass reads both rows' count again just before each merge and refuses a pair that would fold a chunk holder into a chunkless winner. W winning is one `merge(S -> W)`; S winning merges S's stale losers first, the twin W is merged last, then rewrites S alone at once, so the window in which nothing holds the new URI is one request, and a refused or failed earlier merge leaves W in place and S unrewritten; a run that stops inside the window is finished by `nx catalog repair-note-uris --apply`, which rewrites S. The loser's aspects and highlights stay behind the alias, and so do its chunks and meta (tags, ttl) when both rows hold chunks. A merge refusal (self, not found, already aliased, cycle) is reported per pair and the run continues; any other engine error, or a connection that failed or dropped (the request may have been applied), stops it with the ledger written: an intent line goes down before each merge, and a rewrite response the pass cannot read is kept raw. The pass has no `--force`. Dry run by default (each group's winner and why); `--merge --apply` performs it in rounds of up to 500 listed pairs, prints the census first and after, and writes the ledger (the same owner-only file as `--apply`, `--ledger PATH`): per pair an intent line, then the winner, the loser, the loser's URI before and after, the rule, the outcome and links remapped, then whether the rewrite followed. Engine: `POST /v1/catalog/note_uri_repair` takes an optional `tumblers` list (at most 1000) that restricts what `apply` rewrites to those candidates (an empty list rewrites none; the census stays the tenant's), and a merge entry carries `twin_source_uri`, the twin's actual spelling. See `docs/cli-reference.md`.
