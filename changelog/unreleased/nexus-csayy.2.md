### Added

- **The engine serves a tenant export as a session of short requests over one snapshot** (nexus-csayy.2, RDR-248). `POST /v1/tenant/export` opens the caller's tenant's session: a dedicated connection holds a `REPEATABLE READ READ ONLY` transaction that calls `pg_export_snapshot()` and nothing else, so it takes no table lock and tenant create is not blocked. The response is the session id and a header (format version, engine version, `schema_changeset_count`, tenant, UTC times, the bounds, every data and derived table's columns and types, the tenant's `embedding_models` rows; no row counts). `GET /v1/tenant/export/{id}/rows?table=T&after=K` reads one page in its own transaction that imports the snapshot, as a complete binary COPY stream cut by bytes at about 16 MB, with the page's last key, row count, SHA-256 and, on a table's first page, the table's row count in the snapshot. The keyset is a row-value comparison on the whole primary key; `table` must be a registry data or derived table (400 otherwise); `after` is base64url of a JSON array with one text per key column (400 when malformed). `DELETE /v1/tenant/export/{id}` closes it. The engine closes a session idle for 10 minutes or older than 60 minutes (`NX_EXPORT_IDLE_SECONDS`, `NX_EXPORT_TOTAL_SECONDS`), allows one per tenant and `NX_EXPORT_MAX_SESSIONS` (default 2) per engine, and refuses past the cap with 503 and `Retry-After`. A tenant or data token of the owning tenant opens and reads a session (a fresh token of the same tenant continues it); a root token gets 403 and another tenant's token gets 404. A page's database time is bounded to 20 s (`NX_EXPORT_PAGE_BUDGET_SECONDS`) by `statement_timeout`, and a page or a header read that waits out its lock bound or the budget answers 503 `export_page_busy` with `Retry-After`. The tunables are range-checked at boot, and a session cap the pool cannot carry (`NX_EXPORT_MAX_SESSIONS` against `NX_POOL_SIZE`) refuses the boot. `/version` reports `tenant_export_supported` and `tenant_export_format_version`.
