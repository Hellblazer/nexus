### Added

- **`nx backup` backs up a cloud tenant, and `nx backup --check FILE` verifies the file offline** (nexus-csayy.3, RDR-248). In managed mode the verb used to refuse; it now opens an export session on the engine, pulls every data and derived table of your own tenant page by page from one consistent snapshot, and writes one `.nxtenant` file (`~/nexus-backups/nexus-<tenant>-<UTC stamp>.nxtenant`, or `--to PATH`; readable by you only; an existing file is refused, never overwritten). It needs a tenant or data token (the engine's root token is refused) and an engine that has the export routes (0.1.191 or later: an older engine is refused before any session opens, naming the version it needs, and the refusal notes that the public edge must relay `tenant_export_supported`; the export format is read from the session header, since the edge relays capability fields as booleans only). Each page is checked on arrival against the engine's SHA-256 and row count and asked for again from the same key when it fails, up to five tries, while an engine that answers busy is waited on for its `Retry-After` for up to two minutes without using them; a token that expires mid-export is refreshed and the same page asked for again; a session the engine forgot starts over, and one past the engine's 60-minute limit fails naming it; when the tries run out the session is closed, the partial file removed and the verb says to run it again. Ctrl-C, SIGTERM and SIGHUP remove the partial file first and then send a best-effort DELETE for the session, so even a second signal during the DELETE leaves no partial file. The finished file is checked from disk before it is moved into place. The run prints the size and time, row counts by class, how many sensitive documents the file holds, what the backup leaves out (tuples, in-flight jobs, session scratch, operational logs; the list is checked in CI against the engine's own excluded tables), and the only-copy sentence. `nx backup --check FILE` reads the file with no engine contact and checks every frame, every page's hash and row count, each table's count and SHA-256 against the trailer and the whole file's hash, then prints the header (tenant, engine version, export format, schema changeset count, snapshot time) and each table; a damaged file is refused naming the table. The local `pg_dump` arm is unchanged, and there is still no restore command for a cloud file (RDR-248 Phase 2). The runbook gains a cloud section.
