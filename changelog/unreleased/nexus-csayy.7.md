### Added

- **The restore's round trip, committed fixture, scale run and runbook** (nexus-csayy.7, RDR-248 Step 6). Engine tests restore an export into an empty tenant and check every table's count and contents, every foreign key and soft reference resolving to the new tenant's rows, two generations (restore, export, restore), and that the checks fail on kept ids. A real `.nxtenant` backup written by this code is committed under `service/src/test/resources/fixtures/`, pinned by SHA-256, and loaded on every later engine, so a migration that drops or retypes an exported column fails there. `tests/e2e/import_scale_run.py` restores a 500,000-chunk tenant with every table seeded: the load took 33 minutes on a fast test database (about 4 ms per chunk, most of it the vector index), against the default `NX_IMPORT_LOAD_MAX` of 60 minutes, so an operator restoring a tenant that size sets the bound to at least twice the expected load first. `docs/operations/backup-restore.md` gains the operator's order, recovery after an engine restart or a lost connection, and what each refusal means.
