### Fixed

- **A tenant export page cut at its byte target no longer hangs on a TLS database connection, and no page holds its session's page gate past 25 s** (nexus-csayy.9; engine; rides the next engine tag). Over TLS, the first chunks page of an export spun at full CPU for good: the cut left the rest of the COPY in the stream, the pool's close of the discarded connection rolled it back by skipping those rows while the pool's close thread closed the same socket, and the driver's skip loop never ends on the end of stream a closed TLS socket reads as. Every later page of the session then answered 409 `page_in_flight` until the session ended. The page now reads the COPY itself, never cancels and drains it, and closes a discarded connection at the network level before the pool sees it, so nothing reads that stream again. Each page also runs under a 25 s wall: past it the engine interrupts the page's reader, waits up to 1.5 s for it, and answers 503 `export_page_over_budget` with the wall (25000) in `page_budget_ms` (logged as `event=export_page_wall_deadline`), or the usual exhausted-pool 503 when the page's pool connection had not been borrowed by then. A reader that ignores the interrupt (logged as `event=export_page_reader_stuck`) makes the session answer 503 `export_page_busy` with `Retry-After` until it ends, so a session never has two page reads at once. `NX_EXPORT_PAGE_BUDGET_SECONDS` is now capped at 20 (a larger value refuses the boot, naming the variable), so the database budget always ends before the wall.
