### Added

- **`nx backup restore` on a local install mints its own tenant token** (nexus-csayy, RDR-248, ask `rdr248-local-root`). A local install holds only the supervisor's operator token, which the import routes refuse, so the restore used to stop and tell you to issue a `default`-tenant token and export it. When the token the client would send is the supervisor's, it now asks the engine's token route (the one `nx service token issue` uses) for a four-hour `default`-tenant token and sends that; the operator token goes to the token route and to nothing else, and the minted one is replaced before it expires (and up to twice more if the engine rejects it) and revoked when the restore ends. A token you export as `NX_SERVICE_TOKEN` that is not the supervisor's still wins, and the manual step stays as the message when the mint fails. The cloud path is unchanged.
- **The engine refuses, at the open, a file whose Voyage embedding model it cannot serve** (nexus-csayy, RDR-248, ask `rdr248-cloud-to-local`). The `embedding_models` table is seeded the same on every engine, so a cloud file restored into a local engine with no Voyage key passed the existing missing-model check and loaded collections the engine could not then embed for. The open now answers 422 `embedding_model_not_served`, naming the model and the key (`NX_VOYAGE_API_KEY`), before any part is sent. A cloud file restores into a local engine that holds a Voyage key and whose embedding profile is `voyage` (a keyed engine on `NX_EMBED_PROFILE=bge` opens it and fails the load on the profile rows, which are data the open cannot read); a model of another provider is not gated.
