### Added

- **With `-v`, the client logs an `engine_request_failed status=<code> path=<route>` line carrying the invocation's `correlation_id` whenever the engine answers a request through the shared HTTP store client (`RefreshableHttpStoreMixin`: T2, catalog, pipeline and the other stores built on it) with a non-2xx status.** It is DEBUG because it is written on every attempt, before a 401 re-mint and before callers that handle a 400, 404 or 409 themselves; the T3, scratch and token clients do not write it. The engine's `event=request_failed` line for the same request prints the same id as `cid=`, so one `grep` on that id finds both sides. A test (`tests/test_correlation_cross_tier.py`) runs `nx -v memory list` with a bearer the engine never minted and checks that the 401 leaves the same id in the client's stderr and the engine log (RDR-167, Phase 1).
