### Fixed

- **A client-chosen value in an engine log line can no longer pass for a schema-migration marker.** The supervisor's readiness wait, its migration-failure root cause and `nx doctor`'s boot-failure detail matched `event=schema_migration_failed` and the other markers anywhere in a line. So a tenant name, a collection name or a request path printed in an ordinary line could stop a starting engine as a failed migration, mark a migration complete, or name a changeset in the doctor line. The markers now count only as the first token of the message of an engine line from the logger that emits them: `dev.nexus.service.db.SchemaMigrator` for start, pending and complete, and `dev.nexus.service.Main` at ERROR for failed. Both the current line form and the older one with no `[cid=... tenant=... session=...]` block are read. Liquibase's `Running Changeset:` and `Waiting for changelog lock` count only at the start of a line. `nx doctor` reads `Migration failed for changeset` only in the trace of that failed line, and takes its first match there. This anchoring relies on the engine's escape of control characters in log messages, exception text and Liquibase's records, which ships in the same release: against an older engine, a client value carrying a newline can still start a forged line (RDR-167, Phase 1).
