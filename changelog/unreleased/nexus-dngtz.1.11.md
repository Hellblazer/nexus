### Fixed

- **The session and tenant values in the engine log prefix are escaped, so a client-chosen session id cannot forge a line or a field.** `/v1/sessions/start` takes any non-blank `session_id`, and the engine printed it raw in `[cid=... tenant=... session=...]` and in the `session_token_minted` line: a newline wrote a second log line, and a space, `]` or `=` added fields a supervisor reader could match by substring. The tenant and session values in the engine log line prefix, and in the `session_token_minted`, `session_token_closed` and `t1_session_closed` lines, are now printed escaped: control characters print as `\xNN` (or `\uNNNN` above 0xFF), as do space, `[`, `]` and `=`, and a backslash is doubled. The stored id, routing and comparisons keep the raw value. RDR-167, Phase 1.
- **The engine's log escapes control characters at the sink, so no logged value can start a new line.** Every log message and every exception message (the exception, each `Caused by:` and each suppressed one) now prints control characters as `\xNN` (or `\uNNNN` above 0xFF; carriage return, U+0085, U+2028 and U+2029 included), whether the text came from our code, from PostgreSQL error text or from a library that logs through logback or java.util.logging. Liquibase's records, the JDK HttpServer's, Liquibase's error messages and an uncaught exception (which now goes through the log pattern, not the JVM's stderr handler) are covered the same way, and so is the thread name in the `[...]` block, which also escapes space, `[`, `]` and `=`. A multi-line exception or Liquibase message, such as a PostgreSQL error with a `Where:` or `Detail:` line, now prints on one line with `\x0a` in place of each line break. The sink does not double a backslash, because call sites have already escaped their own values: a literal `\x0a` typed in a value reads the same as an escaped newline. A normal line and a normal stack trace keep their shape. RDR-167, Phase 1.
