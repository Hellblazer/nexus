### Changed

- **The docs now say how to join a client log line to an engine log line with the correlation id.** `docs/configuration.md` (Logging) and `docs/architecture.md` (Request correlation) describe the `correlation_id` an `nx` command or MCP tool call carries, the `[cid=... tenant=... session=...]` block the engine prints, and the `event=request_failed` line that an authenticated route leaves for every response of 400 or above (a path with no route and the five unauthenticated routes leave none). To get the id from a command that failed at the default level, rerun it with `nx -v` (the client's `engine_request_failed` line is DEBUG, and only the shared HTTP store clients write it), then grep the id in the engine log. They also name what carries no id: boot lines, the five unauthenticated routes, the engine's fan-out threads, and the client's search fan-out pools. The `HealthHandler` comment now says `/health` is readiness and `/livez` is liveness. RDR-167, Phase 1.

- **The engine release smoke now proves the log sink escapes a value no call site escapes.** `service/native-smoke.sh` sends a collection name with a newline to `/v1/vectors/search`, whose warning prints the name raw, and requires one escaped svc.log line and none that starts with the forged text; the earlier path probe only showed that `AuthFilter`'s own escape survives. `docs/configuration.md` (What the engine log escapes), `docs/architecture.md` and RDR-167 describe the sink and its residuals, including output written straight to `System.out` or `System.err`. nexus-dngtz.1.11, nexus-dngtz.1.12.
