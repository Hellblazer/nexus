### Fixed

- **The correlation id now reaches the worker threads of the four engine-bound pools on the `nx index repo` path.** These are the per-file "nx-index" pool, the chunk batcher's "nx-flush" pool, the PDF pipeline's three stage threads and the "aspect-enqueue" pool that writes one aspect task per document. Each submitted its work bare, and a bare `ThreadPoolExecutor.submit` does not carry a `ContextVar` into the worker. Each submit now runs in its own copied Context, so a log line emitted in a worker carries the id the invocation bound. Two thread starters are left as they were on purpose. `nx-routing-listing-prefetch` is a one-shot daemon thread that makes a single call; a lost id there falls back to one the engine generates. The long-lived daemon threads (the aspect worker and the search telemetry sink) get no copy, because a copy taken when the thread starts would stamp every later line with the first invocation's id. RDR-167, Phase 1.
