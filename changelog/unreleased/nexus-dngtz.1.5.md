### Added

- **Engine log lines logged while an authenticated request is handled carry that request's correlation id, tenant and session.** `AuthFilter` takes the id from the `X-Correlation-ID` request header (or generates an `nxe-` id), sets it on the response before any response can be sent, so a 401 echoes it too, and puts it in the logging MDC as `correlation_id`. Once the bearer token resolves it also puts `tenant`, and `session` when the session token is verified. The token and its hash are never put in the MDC. The MDC is cleared on every exit from the filter, the early 401 and 403 returns included. `logback.xml` prints the three fields as `[cid=... tenant=... session=...]` between the logger name and ` - `. Only lines logged on the thread that handles a request `AuthFilter` serves carry the ids. Boot lines, the unauthenticated routes (`/health`, `/livez`, `/version`, `/v1/status`, `/v1/install-ping`, which send no `X-Correlation-ID` back either) and the fan-out worker threads print `-` in all three fields. A line's timestamp, level and message are where they were, so readers that match on those still match (RDR-167, Phase 1).
