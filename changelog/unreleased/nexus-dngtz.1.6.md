### Added

- **The engine logs one `event=request_failed` line for each request that fails or is never answered: WARN, except a sent 404 with nothing thrown, which logs at INFO.** `AuthFilter` writes `event=request_failed method=GET path=/v1/... status=503 exception=none duration_ms=12` when the response status is 400 or above, when no response was sent (`status=none`), or when the handler threw (`exception=` is the class name; the message and stack trace are never written, because they can carry client text). The line is written before the logging context is cleared, so it carries the request's `correlation_id`, `tenant` and `session`. `tenant` is now set as soon as the bearer token resolves, so a 403 scope refusal and a 401 for a cross-tenant or unminted session print it too; a 401 for a missing, non-Bearer or unknown token prints `-` for the tenant (the pattern's default), because no tenant was found. The path has no query string. A logging failure cannot skip the clearing of the request context (RDR-167, Phase 1).
