### Fixed

- **The engine escapes client-supplied text in these log lines, so a `%0A` in the request path or a control character in the method cannot forge a second line.** `exchange.getRequestURI().getPath()` is the decoded path, so a request to `/v1/x%0Aevent=forged` put a real newline into the `event=request_failed` line; the JDK server also passes some control characters (a tab, a C1 character) in the method token through. `LogText.escapeControl` writes a backslash as two backslashes and each control character (C0, 0x7F, C1 0x80 to 0x9F, U+2028, U+2029) as `\xNN` (or `\uNNNN` above 0xFF), and null as `-`. It is applied to: in `AuthFilter`, the method and path of the `request_failed` line, the path of every `auth_rejected` line, the method of the board-ci refusal line, and the path and claimed `X-Nexus-Tenant` header of the `tenant_header_ignored` line; the `value` of `event=catalog_handler_tumbler_grammar_violation`; and the path in the `request_handler_no_tenant`, `whoami_no_tenant`, `session_token_bad_request` and `session_token_error` lines. Other log lines are not changed. Routing, comparisons and the JSON response body are unchanged (RDR-167, Phase 1).
