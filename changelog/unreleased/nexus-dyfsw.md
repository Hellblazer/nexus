### Fixed

- **`nx daemon service stop` no longer signals a process whose command line it cannot read** (nexus-dyfsw follow-up). The stop re-checks a legacy service lease's recorded pid before signalling its process group, because the pid may since have been reused. When the pid's command line read empty, the stop signalled the group anyway. On Linux `/proc/<pid>/cmdline` reads empty while a just-started process is still in `execve`, so under load the stop could terminate an unrelated process that had taken the pid. It now signals only a readable command line that is this config directory's service stack. A pid it cannot read is left alone and named in the warning that `nx daemon service stop` prints, with the stop reported as unverified, and the stale lease is still released. The process-table sweep that follows still stops the real stack. The re-check is one helper in `service_registry.py`, shared with the teardown stop (`stop_tier_holders`), which already treated an empty command line as not ours.
