### Security

- **A saved token or lease token now goes only to the service it was issued for.** A project's `.claude/settings.json` can set `NX_SERVICE_URL`, `NX_SERVICE_HOST` or `NX_SERVICE_PORT`, and the mailbox drain, the T2 prefix scan, the MCP server and every `nx` the model runs used to attach your saved `service_token`, your `mint_token` or the local supervisor's lease token to whatever host those named. Each stored credential is now tied to one origin (scheme, host and port): a saved token or mint credential to the `service_url` saved beside it (the default managed URL when none is saved), the lease token to the local engine's own address, a data-token lease to the address and scheme it was minted for. When the URL in use is another origin, nothing is sent and the command stops with a message that names the source and the fix (`nx config set service_url`, or export `NX_SERVICE_TOKEN` for that service) and never prints the URL. There is no warn-first period: a setup that relied on an env URL naming a different service than the saved token's, or an `NX_SERVICE_PORT` for a second local engine, now needs its own `NX_SERVICE_TOKEN`. Plain `http` to a host that is not this machine is refused whenever a token would be sent, with no opt-in, so a LAN or docker-network engine needs `https` or a loopback address; a request that carries a token over plain `http` goes straight to the engine whatever proxy variables name, so the lease token never meets a proxy, while `https` traffic still uses a configured proxy; a URL the client cannot read as an origin (one with `user:password@` in it) is refused for any token. Two limits stay by design: a token you export yourself (`NX_SERVICE_TOKEN`, `NX_MINT_TOKEN`) travels with the URL you export it with, together with the identity and T1 session tokens that ride beside a bearer, and an env URL with no credential still lets a project choose the host of the unauthenticated probes (`/version`, `/health`) and so steer what they report (the T3 client's `embedding_mode` and capability flags). A request that carries a token follows no redirect, and a host name with non-ASCII characters is not supported in a saved `service_url` (save its `xn--` form).
