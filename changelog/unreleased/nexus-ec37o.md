### Security

- **A saved token or lease token now goes only to the service it was issued for.** A project's `.claude/settings.json` can set `NX_SERVICE_URL`, `NX_SERVICE_HOST` or `NX_SERVICE_PORT`, and the mailbox drain, the T2 prefix scan, the MCP server and every `nx` the model runs used to attach your saved `service_token`, your `mint_token` or the local supervisor's lease token to whatever host those named. Each stored credential is now tied to one origin (scheme, host and port): a saved token or mint credential to the `service_url` saved beside it (the default managed URL when none is saved), the lease token to the local engine's own address, a data-token lease to the address and scheme it was minted for. When the URL in use is another origin, nothing is sent and the command stops with a message that names the source and the fix (`nx config set service_url`, or export `NX_SERVICE_TOKEN` for that service) and never prints the URL. There is no warn-first period: a setup that relied on an env URL naming a different service than the saved token's, or an `NX_SERVICE_PORT` for a second local engine, now needs its own `NX_SERVICE_TOKEN`. Plain `http` to a host that is not this machine is refused whenever a token would be sent, with no opt-in, so a LAN or docker-network engine needs `https` or a loopback address; a request that carries a token over plain `http` goes straight to the engine whatever proxy variables name, so the lease token never meets a proxy; a URL the client cannot read as an origin (one with `user:password@` in it) is refused for any token. Two limits stay by design: a token you export yourself (`NX_SERVICE_TOKEN`, `NX_MINT_TOKEN`) travels with the URL you export it with, and an env URL with no credential still lets a project choose the host of an unauthenticated read. [Configuration § A saved credential goes only to the service it was issued for](docs/configuration.md#a-saved-credential-goes-only-to-the-service-it-was-issued-for) has the detail. (nexus-ec37o)

- **A request that carries a token no longer reads a proxy or CA from the environment; `nx config set network.https_proxy` and `network.ca_bundle` name them instead.** A project's `.claude/settings.json` can set `HTTPS_PROXY` and `SSL_CERT_FILE`: a proxy that terminates TLS with the project's own CA would read the saved token on its way to the right host. Every request that sends a token (the stores, the T3 client, the mint request, both mailbox drains, the telemetry poster, the cloud backup commands, the `nx doctor` token probes) now ignores `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`, `SSL_CERT_FILE`, `SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`, a `.netrc` and `SSLKEYLOGFILE`, and takes a proxy (`https` only) and extra CA roots from `network.https_proxy` and `network.ca_bundle` in your own `config.yml`, which a project cannot write. A request that carries no token is unchanged. **If you reach the service through a corporate proxy or a private CA** and had set `HTTPS_PROXY` or `SSL_CERT_FILE` for it, move them: `nx config set network.https_proxy=http://proxy.corp:3128` and `nx config set network.ca_bundle=/etc/corp/root-ca.pem`, then restart a running Claude Code session; until then those requests go direct and a TLS-inspecting proxy shows as `CERTIFICATE_VERIFY_FAILED`. [Configuration § A proxy or CA for the managed service](docs/configuration.md#a-proxy-or-ca-for-the-managed-service) has the detail. (nexus-ec37o)
