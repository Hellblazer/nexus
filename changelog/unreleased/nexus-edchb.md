### Security

- **The `nexus_diag` role can no longer read chunk text** (nexus-edchb; engine and client; rides the next engine tag). `nexus_diag` is the read-only diagnostic role and bypasses row-level security, so it sees every tenant. To make the security-invoker counts view `nexus.diag_chash_conformance` work, the runAlways changeset `grants-nexus-diag-3` granted it SELECT on whole tables: `nexus.chunks`, `nexus.catalog_document_chunks`, `nexus.topic_assignments` and `nexus.relevance_log`. With that grant the role could read every tenant's `chunk_text` and the other content columns. It now holds SELECT on only the one column of each table that the view reads: `chunks.chash`, `catalog_document_chunks.chash`, `topic_assignments.doc_id` and `relevance_log.chunk_id`. The narrowing takes effect at the engine's next boot, which revokes the table grant (`grants-nexus-diag-2`) and grants the columns back (`-3`). Local provisioning (`nx init --service` and its re-run) also stops granting `nexus_diag` SELECT on every table of `nexus` and `t1` once the counts view exists. In the view era it grants the same four columns instead, so the role can read the view at once. Before, the bulk grant held until the engine's next boot. `nx doctor`'s chash check reads through the view and is unchanged. The role still holds whole-table SELECT on the five tables `grants-nexus-diag-4` and `-5` name, the tuple-space tables among them.
