### Added

- **Two read-only catalog routes for the upgrade ladder and the doctor, so they stop reading chunk metadata one batch at a time** (nexus-f3yqd; engine change, ships in engine-service-v0.1.188). `GET /v1/catalog/sensitive?limit=N` lists the tenant's live sensitive documents (`tumbler`, `physical_collection`) in tumbler order, with the exact `count` and a `capped` flag when more than `limit` exist; it uses the partial index on live sensitive documents. `GET /v1/catalog/manifest/fillable?kind=labels|spans&limit=N` answers, in one statement, how many manifest rows the section-label rung or the span rung would fill (`kind`, `fillable`, `limit`, `capped`, `rule: "title rule 2"`, `stamp: "strict"`). The new count is strict about the chunk's `indexed_at`: a stamp it cannot read is not counted, where the older `/manifest/section_label_fillable` count (which stays for old clients) counts it; a label value that is not a string or an integer, and a span or page number of more than nine digits, are left out too. Both run under the same 10 second statement bound as the older count and answer 503 with no partial body when they outlast it; `/version` gains `catalog_sensitive_list_supported` and `catalog_manifest_fillable_supported`. The client half is a separate change; until it lands the routes have no caller, and the public edge's `/version` allowlist must add the two flags before a cloud client can read them.
