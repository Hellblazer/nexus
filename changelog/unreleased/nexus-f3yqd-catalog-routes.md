### Added

- **Two read-only catalog routes for the upgrade ladder and the doctor, so they stop reading chunk metadata one batch at a time** (nexus-f3yqd; engine change, ships in engine-service-v0.1.188). `GET /v1/catalog/sensitive?limit=N` lists the tenant's live sensitive documents (`tumbler`, `physical_collection`) in tumbler order, with the exact `count` and a `capped` flag when more than `limit` exist; one statement, so the count and the list come from the same snapshot, and it uses the partial index on live sensitive documents. `GET /v1/catalog/manifest/fillable?kind=labels|spans&limit=N` answers, in one statement, how many manifest rows the section-label rung or the span rung would fill (`kind`, `fillable`, `limit`, `capped`, `rule: "title rule 2"`, `stamp: "strict"`, `edge`). The new count is strict about the chunk's `indexed_at`: a stamp it cannot read is not counted, where the older `/manifest/section_label_fillable` count (which stays for old clients) counts it; a label value that is not a string, null or integer, and a page number outside the INTEGER range of the manifest columns (above 2147483647), are left out too (a span value outside that range is simply unrecorded, as the rung also treats it). Because each of those exclusions could hide work the Python rung would do, `edge` counts the rows that pass every other guard but hit one of them (an unreadable stamp, a label or page value SQL cannot decide, an out-of-range page number): a client reads an uncapped `fillable` 0 with `edge` above 0 as "scan once to see", and an uncapped `fillable` 0 with `edge` 0 as converged. The fillable count stops at `limit` candidate rows (rows that pass every guard but those exclusions); when it does, `capped` is true and both `fillable` and `edge` are at least these numbers, and a client must read `capped` as pending whatever the numbers say (including `fillable` 0 with `edge` equal to `limit`); only an uncapped answer is exact. A row that stays an edge row (a date-only stamp, say) keeps a small-limit answer capped, so a client ends the pending state with the rung's own completion record after a scan, not with this count alone. A converged tenant has no early stop and scans every candidate. Both routes run under the same 10 second statement bound as the older count and answer 503 with no partial body when they outlast it, so a very large converged tenant can answer 503 ("cannot say"). `/version` gains `catalog_sensitive_list_supported` and `catalog_manifest_fillable_supported`. The client half is a separate change; until it lands the routes have no caller, and the public edge's `/version` allowlist must add the two flags before a cloud client can read them.
