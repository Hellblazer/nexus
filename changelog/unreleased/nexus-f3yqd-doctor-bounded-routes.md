### Added

- **Two read-only routes so `nx doctor` stops scanning for its chash and PDF-metadata rows** (nexus-f3yqd; engine change, ships in engine-service-v0.1.189). `GET /v1/admin/chash-conformance` (root token only, as the other `/v1/admin` reads; a tenant token is a 403) answers `{constraints: [{table, name, present, validated, partitions, partitions_not_validated}], all_validated}` from `pg_constraint.convalidated` in one catalog statement, with no table scan and no tenant predicate. It reports the two width CHECKs (`chunks_chash_octet_check` on `nexus.chunks`, `catalog_document_chunks_chash_octet_check` on `nexus.catalog_document_chunks`, both `octet_length(chash) = 32`), which are the client's poison tables and which the migrations add NOT VALID until the chash re-key rung validates them. A fresh install therefore answers `all_validated: false`. `validated` for the partitioned `nexus.chunks` is true only when the parent's own row and every partition's copy are valid, so a parent valid over a copy that is not valid reads not validated; `partitions` and `partitions_not_validated` count the copies. A constraint that is missing is `present: false, validated: false`, never a vacuous true, and a same-named constraint on another table (the retired `chunks_retired_225` has one) is not read. The debt tables (`topic_assignments`, `frecency`, `relevance_log`) carry no width CHECK and are not listed. `GET /v1/catalog/stub-metadata?limit=N` answers `{collections: [{collection, stub_chunks, capped, examples}], limit}` for the tenant's knowledge and docs collections (by the collection registry's content type): the PDF chunks that still carry the pre-RDR-236 upload placeholder (the chunk row holds a document, position or legacy metadata key and no truthy `title`, and its live owning document is a PDF by `nexus.catalog_source_format` whose catalog metadata records no truthy `extraction_method`), counted per collection up to `limit` (1 to 10,000, default 1,000; `capped` true means more exist and the count is a lower bound), each collection stopping at `limit + 1` stub rows, with up to ten owning-document names (`source_uri`, else `file_path`, else `content_hash <first 12 characters>`), the documents with the most stub chunks first. A collection with no stub is listed with 0. It runs under the same 10 second statement bound as the fillable count and answers 503 `reason: statement_timeout` with no partial body when it outlasts it. The rule is the client's `_is_pdf_stub_metadata` as `nx doctor` applies it, held to one shared case table (`service/src/test/resources/pdf-stub-metadata-cases.json`) read by a Java test of the SQL and a Python test of the client function. `/version` gains `chash_conformance_constraints_supported` and `catalog_stub_metadata_supported`. The client halves are a separate change; until they land the routes have no caller, and the public edge's `/version` allowlist must add the two flags before a cloud client can read them (a cloud tenant token also cannot read the admin route).
