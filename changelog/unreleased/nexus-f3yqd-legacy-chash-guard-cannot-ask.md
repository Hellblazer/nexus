### Changed

- **A start that cannot ask Postgres its questions now waits and asks again.** While Postgres is still recovering from an unclean shutdown, or the superuser password is missing, the supervisor does not start the engine unasked and does not exit; it retries every few seconds and records no refusal. An install the guard has already seen past the deleting migrations (or a fresh one it saw start healthy) is remembered in `legacy-chash-guard-seen.json`, keyed to its data directory, and goes on. A healthy install that has no such file yet and cannot be queried will wait until it can be.
