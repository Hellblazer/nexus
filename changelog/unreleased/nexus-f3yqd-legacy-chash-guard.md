### Added

- **The engine is not started on a store whose 16-byte chash rows its first boot would delete, until you take a backup** (nexus-f3yqd). An engine since 0.1.100 deletes chunk rows that still carry 16-byte chash keys when its `hygiene-001-5` migration runs; a store that last ran an older engine can still hold them. Before the supervisor starts an engine on the bundled Postgres it counts those rows (as the cluster superuser, because the chunk table enforces row-level security even for its owner). If any exist and the migration has not run, the start is refused with exit 75: the message gives the counts and says to run `nx backup`, and Postgres is left running so the backup can read it. The next `nx daemon service start` or `nx upgrade` goes on once a dump in `~/nexus-backups/` newer than the refusal lists the chunk table's data under `pg_restore -l`; a dump written elsewhere is named with `nx daemon service start --legacy-backup PATH`. Nothing runs the backup for you. The refusal and the backup that cleared it are kept in `legacy-chash-guard.json` in the config directory.
