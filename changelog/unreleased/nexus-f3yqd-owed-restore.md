### Fixed

- **An engine that dies right after a manifest write no longer costs a document its timestamp** (nexus-f3yqd.5). The engine restamps a document's `indexed_at` on every manifest write, and the two manifest data steps write the old value back after each write. When the engine died between the write and the write-back, the document kept the run-time stamp, and the guard that skips rows whose chunk is newer than the document stopped working for it. Now each step records, in a T2 note made before every write while the engine still answers, the stamp each document will need back. The note clears once the write-back succeeds; what is left is written back before the step next reads the store, in the same `nx upgrade` or a later one. A write-back that finds the engine away waits for it with the rest of the step; one that keeps failing for another reason (the document was deleted) is dropped after three tries and logged.
