### Fixed

- **A restart no longer ends the index build because a self-retrying changeset is unrun** (nexus-f3yqd.3). `aspects-005-2` drops `nexus.aspect_extraction_queue` only when the table is empty, and until then it is skipped without a `DATABASECHANGELOG` row, so a store whose queue still held rows had one unrun, non-`runAlways` changeset on every boot and the migration walk ended the build every time (`pci_builders_terminated reason=schema_changesets_pending n=1`), and once more after the queue drained. A pending changeset whose precondition is `onFail="CONTINUE"` no longer counts as schema work: its body cannot conflict with a build, and a changelog lint (`tests/test_changelog_continue_precondition_chunks_lint.py`) holds every such body off `nexus.chunks`, chunk leaves, the partition helpers and the builder. The boot logs what it left out: `event=pci_builders_kept ... retrying=N` and, per changeset, `event=pci_build_kept_for_retrying id=<file>::<id> reason=self_retrying_precondition` (a different event name from `pci_builders_kept`, so a substring search for the keep line does not count these too; `count=` and `reason=only_run_always_pending` on the keep line are unchanged and now also cover the self-retrying changeset). Any other pending changeset, and a partition access repair, still end the build; `schema_migration_pending changesets=` still counts a self-retrying changeset, `n=` on the terminate line does not. The lint also holds the census of such changesets to an explicit allowlist (a new one fails until it is reviewed and added), refuses `<sqlFile>`, `<customChange>` and `<executeCommand>` in one, and refuses a changeset that can stay unrecorded through `onError="CONTINUE"` or `failOnError="false"` without an `onFail="CONTINUE"` precondition, which the boot would count as schema work.
