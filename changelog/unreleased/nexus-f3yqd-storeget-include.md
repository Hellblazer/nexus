### Changed

- **`POST /v1/vectors/store-get` reads only what the caller asks for** (nexus-f3yqd, engine half of nexus-mjmjl). The by-id read accepts an optional `include` array of `"documents"` and `"metadatas"` (`"embeddings"` is accepted and never returned, as before). With it, the statement selects only the named columns, so a metadata-only read no longer detoasts and ships the chunk text, and the response omits the key of a column it did not select. `ids`, `count`, `chashes`, `spans` and `sensitives` are always returned, and `spans` stay correct when `metadatas` is excluded (the statement still reads the three span keys). A request without `include` is unchanged, byte for byte; any other `include` value is a 400, except with `include_non_live`, which answers before `include` is read and ignores it (200). Additive: an old client sends no `include`, and a new client against an older engine gets the full envelope, which its stub already reads by key.
