### Added

- **A running chash CHECK validate job can be cancelled** (nexus-f3yqd; engine change, ships in engine-service-v0.1.190). `DELETE /v1/admin/validate-constraints/{job_id}` (root token only; any other credential is a 403) cancels the job's statement in flight on the server, a VALIDATE mid-table included, cuts a retry or lock backoff short, and starts no later statement. A 202 with the job's status (`stopping: cancelled`) says the cancel was accepted. The job then ends `failed` with `reason: cancelled` and `http_status` 409, wherever in its run the cancel landed. Key a client on `reason`, never on the 409, which a start's conflict also uses. A VALIDATE is atomic, so the table it was on stays NOT VALID, every constraint validated before it stays validated, and a new start resumes at the next one. A start sent while the cancelled job is still ending is a 409 with `reason: cancelling` naming it: poll that job until it ends, then start again. A DELETE of a job that has already ended answers 200 with its status, unchanged, and an unknown id is a 404. The cancel names its job, so it never touches a job started after that one ended. Before this, the route answered 405 and stopping the engine was the only way to end a running job.
