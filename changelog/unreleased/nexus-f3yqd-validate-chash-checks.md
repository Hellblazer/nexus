### Added

- **`nx t3 validate-chash-checks` and `nx doctor --fix` validate the chash width CHECKs, which the engine no longer does at boot** (nexus-f3yqd; engine-service 0.1.190). The command starts the engine's VALIDATE job and polls it to the end, showing the table it is on; it is safe to stop, and a CHECK it validated stays valid. A finished job is read by its verdict, with each refused or deferred CHECK's own next step. It needs the engine's operator credentials, so on a managed install the operator runs it. `nx doctor` shows a row offering the job whenever the engine reports a CHECK not validated. An engine older than 0.1.190 is named as too old; nothing falls back to direct SQL.
- **`nx t3 repair-chash`** removes a document's bad 16-byte manifest rows and marks it for re-index, the step a refused manifest CHECK needs. It needs an engine with the repair route, which no released engine has yet; until then it says so. A dry run unless `--apply`.
