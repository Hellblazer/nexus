### Added

- **A data move now verifies and completes (RDR-246).** Once every run of a move is complete, the worker reads the move's row again (a pause stops it there) and runs the move's verification query once per tenant on a dedicated connection that carries that tenant's setting, then once table-wide on a separate connection that carries none, each in a READ ONLY transaction under the move's `statement_timeout_ms`. Only when every run returns no rows does it read the row once more and run `on_complete` (if any) and the update that sets `completed_at` in one transaction, so a stop between them leaves neither. `on_complete` runs under a `lock_timeout` below `statement_timeout_ms`, and a move over the chunk family (`nexus.chunks`, its leaves and the tables with a foreign key into it) ends the per-collection index builders first, with the same query the migration walk uses. A verification that finds old-shape rows fails the move with the count per tenant and leaves `completed_at` NULL. No move is registered yet, so nothing changes for an existing install (nexus-f3yqd.2.14).
