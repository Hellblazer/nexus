### Added

- **A data move now verifies and completes (RDR-246).** Once every run of a move is complete, the worker reads the move's row again (a pause stops it there) and runs the move's verification query once per tenant on a dedicated connection that carries that tenant's setting, then once table-wide on a separate connection that carries none, each in a READ ONLY transaction under the move's `statement_timeout_ms`. A verification text with a `?`, or a `$` followed by a digit other than a standalone `$1`, is refused rather than rewritten. Only when every run returns no rows does it read the row once more and run `on_complete` (if any) and the update that sets `completed_at` in one transaction, so a stop, a pause or a superseding row between the last read and the commit leaves neither. `on_complete` runs under a `lock_timeout` below `statement_timeout_ms`, and a move over the chunk family (`nexus.chunks`, its leaves and the tables with a foreign key into it) ends the per-collection index builders first, once the completion is certain, with the same query the migration walk uses. A verification that finds old-shape rows is reported with the count per tenant and leaves `completed_at` NULL; until the failure-class bead (nexus-f3yqd.2.15) lands, the move is held blocked and retried rather than failed. No move is registered yet, so nothing changes for an existing install (nexus-f3yqd.2.14).
