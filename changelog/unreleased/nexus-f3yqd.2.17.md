### Added

- **Each open or failed data move is a `boot_work` entry, and `nx doctor` shows a red row for a blocked or failed one (RDR-246).** `/v1/status` `boot_work` lists one entry per open move and per failed move no row supersedes, id `data-move:<label>`, with `done` and `total` summed over the move's dml_utils runs in chunks (`done` never falls and never exceeds `total`), `safe_to_stop: true` and `on_stop: "resumes from the last committed batch"`. `what` begins `blocked:`, `failed:`, `paused:`, `stalled:`, `working:`, `queued:` or `runs complete:` and carries the move's label, a fixed class and an SQLSTATE, never a run label, tenant, leaf, backend pid or server message (the status is unauthenticated); the full text is in the engine log and, for a failed move, in `nexus.data_moves.failure`. A library install that failed on a checksum names the changeset and the recovery. A CALL that has completed no chunk for 15 minutes (`NX_DATA_MOVE_STALL_MINUTES`, 1 to 1440) is reported `stalled:`, since the CALL connection has no socket timeout. A blocked move whose retry is running reports `working:` with the time it was first blocked, not its old reason. An engine whose move worker or boot_work reporter did not start says so, and `nx doctor` shows it red. `nx doctor` adds one red row per `blocked:` or `failed:` move, a warning for `stalled:`, a note for `paused:`, and nothing for a move that is working (nexus-f3yqd.2.17).
- **`nexus_svc` holds no privilege on `nexus.data_moves` after a rollback and roll-forward (RDR-246).** `grants-nexus-svc-1` now revokes every privilege `nexus_svc` holds on the registry (a table or column ACL entry) at a boot where the migrating role owns the table and is not `nexus_svc` itself, and runs no statement when it holds none; a rollback to engine-service-v0.1.194 re-grants it, and the loop's exclusion alone did not take it back. The move worker reports every open move `blocked:` while `nexus_svc` holds a granted privilege on the table in the two-role posture (nexus-f3yqd.2.17).
