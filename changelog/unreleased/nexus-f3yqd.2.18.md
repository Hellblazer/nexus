### Added

- **The move worker logs an `event=data_move_*` line for each transition (RDR-246, Failure Modes, Diagnosis).** `data_move_started` (a pass begins on a move that was not already working; a retry of a blocked move is a new pass), `data_move_run_complete` (label, run, tenant: one per run whose CALL completed it), `data_move_blocked` (label, stage, tenant, retries, sqlstate, reason), `data_move_failed` (label, stage, tenant, sqlstate, error) and `data_move_completed` (label, on_complete). `data_move_verification_failed` (label, the count per tenant and table-wide; it renames `data_move_verification_nonempty`) is a detail line, not a transition: a verification that finds rows logs it first and then the `data_move_failed` line with `stage=VERIFICATION_NONEMPTY`. A value that is absent is `-`, and a double quote in a value becomes a single quote, so a quoted field stays one field. `data_move_failed` and `data_move_blocked` used to log `reason=` without the SQLSTATE or tenant, and `data_move_failed` now names its text `error=`. The lines carry the move's label and a tenant id, never the template, verification or `on_complete` text. The first line of a server error message is passed through, and PostgreSQL can quote a value or an identifier in it, so a line may hold a fragment of what the server said, not the statement the worker sent (nexus-f3yqd.2.18).
- **The engine keeps its database passwords out of its logs, the data-move registry and `boot_work`.** The admin password and the application password the engine resolves at startup are replaced by `<redacted>`, case-insensitively and in the forms a driver or server echoes (as is, with a quote doubled or backslash-escaped, URL-encoded), in every engine log line, stack traces and their causes included (the log encoder does it, on the pattern-layout appenders `logback.xml` defines), in every failure reason (removed before a text is cut to one line, so a password straddling the 300-character cut leaves no prefix), in what the failure handler writes to `nexus.data_moves.failure` and `last_transient`, and in the state a move reports. A password under four characters is redacted too, and also masks any unrelated text that contains it; the engine logs one `event=secret_mask_short_secret` warning at startup and boots. Not covered: a password the engine does not hold, a form of one not listed (a Base64 or hashed echo), and output that bypasses the logback appenders. The native image is untested here: the encoder is installed in code at startup, with no reflection entry, and a failure to install is logged and never stops the engine (nexus-f3yqd.2.18).
