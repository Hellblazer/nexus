### Changed

- **The engine release's smoke now boots the native binary on the released PostgreSQL bundle, with and without pg_background, and checks its log (RDR-246).** A new job, `smoke-native-data-move`, runs on both linux arches and gates promotion of the draft release. It provisions a two-role cluster from the `nexus-pg-<arch>` bundle the same run built (the code `nx init --service` runs), boots the `nexus-service-<arch>` binary the same run built, and hands the boot log to `scripts/check_native_data_move_boot.py`. With pg_background the log must show both `event=data_move_library_applied` lines (`ddl_utils` and `dml_utils`); with its control file removed it must show `event=data_move_libraries_skipped reason="pg_background is not installed"` at WARN, the schema walk completing and the engine serving. Both boots also check `event=log_masking_installed masking>=1` and that a request whose path carries each database password is logged as `<redacted>`, with the raw password nowhere in the log. The native build had never loaded the vendored library changelogs, and the existing smoke boots on one database role, where the engine skips them by design (nexus-f3yqd.2.22).
