### Fixed

- **`nx daemon service stop` no longer signals wrappers that only carry the supervisor's command, or another install's engine on the same jar, and a pid it cannot signal no longer blocks `--with-pg`.** Three siblings of the jar-match fix. The supervisor match now needs an nx entry point at the head of the command, so `sudo -n lab-hand-exec ... nx daemon service start --config-dir X`, `lab-run -- ...`, `ssh h ...` and `bash -c "..."` are left alone (a root-owned one met EPERM on both signals and the stop exited 1 before its PostgreSQL step). A `NEXUS_SERVICE_JAR` engine is now placed by its own `NEXUS_CONFIG_DIR`, as a bare `nx daemon service start` already was, so two installs sharing one jar path no longer sweep each other; one whose environment cannot be read is left alone and reported. A pid that both signals fail on with EPERM (another user owns it) is reported as not signalled, with the stop's other unverified pids, instead of failing the stop with "survived SIGKILL". Only installs that set `NEXUS_SERVICE_JAR`, or that run under a wrapper, were affected.
