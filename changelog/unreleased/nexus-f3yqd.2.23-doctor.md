### Fixed

- **`nx doctor` no longer fails on a data move that is only waiting for the `pg_background` extension.** A registered data move (RDR-246) that is blocked because the database lacks `pg_background` now shows in `nx doctor` as a warning, and doctor exits 0. The hint says the engine checks for the extension only at boot: on a bundled local install run `nx daemon service install-binary <tag>` (it installs a bundle that carries `pg_background` and restarts the engine); on a self-managed PostgreSQL install `pg_background`, then restart the engine. Once the engine has retried such a move to its cap ("needs an operator", about four hours), the row turns red again. Any other blocked reason, including a missing `dml_utils` entry point, and every failed move stay red, as before. The engine marks the waiting entry with the additive `reason_class: "missing_prerequisite"` in `boot_work` on `/v1/status`; against an older engine the row stays red (RDR-246, nexus-f3yqd.2.23).
