### Fixed

- **A background job now repairs catalog collections whose `model_version` is empty.** Some collection rows carry an empty `model_version` although their name says it (`code__1-2__voyage-code-3__v1` is `v1`). The engine registers one data move, `repair-catalog-collection-model-version`, which sets the version from the name for each tenant's rows where it is empty and the name has the `<type>__<owner>__<model>__v<N>` form. It runs in batches after the engine serves and resumes from the last committed batch after a restart; a row already set and a name that is not in that form are left as found. While it runs it shows under `boot_work` on `/v1/status` and in `nx doctor`, and the upgrade boot itself writes only the one registry row. It needs the `pg_background` install that `docs/configuration.md` lists under background data moves: on a database without it the move shows as blocked in `nx doctor` and changes nothing (RDR-246, RDR-229 D2, nexus-f3yqd.2.23).
