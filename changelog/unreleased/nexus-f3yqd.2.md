### Added

- **The bundled PostgreSQL carries the pg_background extension on all four platforms** (nexus-f3yqd.2). `scripts/build_pg_bundle.sh` (Linux x86_64 and arm64, macOS arm64) and `scripts/build_pg_bundle_windows.py` build pg_background v2.0.4 against the bundle's own `pg_config` and install its library, control file and SQL scripts into the bundle's `lib` and `share/extension`, so relocation still works. It needs no `shared_preload_libraries` and no `postgresql.conf` change. Both builders refuse a tag that does not resolve to the pinned commit. Every contrib completeness check now lists `pg_background.control` beside `vector` and `pg_trgm` (the build's `verify_and_mark`, the Windows `verify_layout`, the release and cache-seed workflows), the release relocation gate runs `CREATE EXTENSION pg_background`, the relocation tests launch a background worker that returns `SELECT 1`, and the Windows smoke does the same. The Windows cache key gains a `-pgbg<version>` segment; the shell bundles' keys already hash `build_pg_bundle.sh`, so every cached bundle misses once. Nothing uses the extension yet: dml_utils will run its chunked rewrites in it.
