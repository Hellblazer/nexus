### Added

- **`nx backup [--to PATH]`: a backup of the local engine's database, run by you and by nothing else** (nexus-f3yqd.4). There is no automatic backup; this file is the only copy besides the live database. Copy it to another disk or machine. It writes one `pg_dump -Fc` file with the bundled Postgres binaries, against the running local cluster: an online, consistent snapshot of every tenant while the engine keeps serving. The bundle is built without zlib, so the dump is not compressed; the verb prints the database's size on disk, then the bytes written and the rate, and warns when the destination disk has less free space than the database occupies. The default destination is `~/nexus-backups/nexus-<UTC timestamp>.dump`, outside the engine's data directory; an existing file is refused, never overwritten, the finished file is checked with the bundled `pg_restore -l`, and a failed, unverified, interrupted (Ctrl-C, SIGTERM, SIGHUP) run leaves no partial file. `pg_dump` waits at most 60 s for a table lock; when it gives up, the verb fails saying something holds locks, most likely a schema migration, and to run it again afterwards. Managed (cloud) mode is refused (cloud backups are on the conexus side), as is a box with no running local database. No upgrade, doctor, init, self, hook or daemon runs it: a test fails on a Python import, a subprocess command line, or a hook or script line under the repository's code directories that would (it cannot see a command assembled at run time). There is no `nx restore`; `docs/operations/backup-restore.md` restores into a fresh database and swaps names in one transaction, with an undo, and commands for macOS, Linux and Windows. The tests run the macOS and Linux command blocks from that page against a real dump with the bundled binaries; the Windows blocks are compared with the code that renders them but have not been run.
