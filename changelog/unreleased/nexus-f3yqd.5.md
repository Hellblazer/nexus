### Added

- **A release gate that upgrades from the user's seat** (nexus-f3yqd.5). `tests/e2e/upgrade-rehearsal.sh` installs a previous published conexus with a sizeable local store in a throwaway HOME, upgrades the package the way a user does, then runs `nx upgrade`, `nx doctor` and `nx search`, and fails any step that prints nothing for more than 10 seconds (our reading of "a few seconds"), runs past its ceiling or exits non-zero. It starts from the newest published version below the candidate, the last published 7.x and 7.76.0 (the last release before per-collection indexes), each with its own step table; two starts when the first two are the same release. It also checks that the store's rows survive and that `nx --version` names the candidate, and on 7.76.0 it restarts the engine while `nx upgrade` is still building the `pci_` indexes and judges each build by backend pid. The `nx upgrade` ceiling is per start: 120 s for the other two starts, and PENDING for 7.76.0 until nexus-f3yqd.5 sets it from a develop run after the rung-scan fix (nexus-mjmjl, conexus 8.1.1) lands, so that start cannot pass and the gate reports NOT RUN until then. The last line is `UPGRADE REHEARSAL GATE: PASSED | FAILED | NOT RUN | NOT THE RELEASE GATE` and the exit code says the same: 0 only for a pass with every default setting, 1 for a breach, a failed step, a non-vacuity finding or a surviving postmaster, 2 for a pending ceiling, a harness that could not start, a candidate already published on PyPI, or a run under a non-default flag. SIGTERM and SIGHUP run the cleanup. The release skill's Step 6e carries the procedure (run it in the background; about 50 to 75 minutes). The driver is `scripts/upgrade_rehearsal.py`; its judgement, its wrapper and a fake-world run of its wiring have offline self-tests.
