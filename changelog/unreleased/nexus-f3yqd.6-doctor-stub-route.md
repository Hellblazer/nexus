### Changed

- **`nx doctor`'s PDF chunk metadata row reads a bounded count when the engine has one** (nexus-f3yqd.6, F30). Against an engine that advertises `catalog_stub_metadata_supported` (0.1.189), the row asks `GET /v1/catalog/stub-metadata` for each knowledge and docs collection's count of PDF chunks still carrying the upload placeholder, instead of reading each method-less document's chunks (about 5 s on a laptop tenant). A count the engine capped reads "at least"; a collection the route does not list is still scanned; a collection the engine's bound cut off, or a 503 for the whole read, is reported as not checked, and why, rather than running the slow scan. An older engine or a failed read gets the scan as before.
