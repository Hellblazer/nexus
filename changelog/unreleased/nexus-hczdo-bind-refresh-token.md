### Fixed

- **A session's refresh and fork send its own identity token (engine 0.1.198).** In cloud mode the MCP server's `refresh` and `fork` binds carry the identity token being refreshed, as the engine now requires of a data credential; start, resume and clear are unchanged, and the tenant credential still sends none. When the token has expired (a laptop asleep past its hour) the engine answers `403 identity_token_required`: the server logs once that the token expired while the session slept, stops refreshing until a SessionStart bind writes a fresh token into the file, keeps renewing the seat, and leaves the token file for that bind. The server refreshes a token once it has under 50 minutes of life left, so a sleep under about 50 minutes never lapses it; a longer sleep may. After a wake it refreshes on its first tick while the token is still live, and retries while the network is not back, at 5 seconds and then at growing intervals up to a minute. A refused fork row never stops the seat's renewal, and a delegated child whose refresh is refused for want of a live token stops refreshing while its renewal continues. The SessionStart hook's fork (a `/branch`, a `/clear` or an unindexed `/resume`) carries the token in the process's own token file when that file names the identity it holds; a refresh or fork never borrows the token of the nearest Claude ancestor, which may be another identity's. A hook fork that the engine refuses for want of a live token falls through to a start of the same identity the process already holds, so the session stays bound to it with the new session id indexed, instead of becoming a new ephemeral or going unbound. `nx identity create` in cloud mode says one line for `409 seat_limit` (the sixth seat one identity creates through a session; no route removes a seat, so it says to reuse one, or to make a new one with the uncapped tenant credential).
