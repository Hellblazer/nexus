### Fixed

- **A session's refresh and fork send its own identity token (engine 0.1.198).** In cloud mode the MCP server's `refresh` and `fork` binds carry the identity token being refreshed, as the engine now requires of a data credential; start, resume and clear are unchanged, and the tenant credential still sends none. When the token has expired (a laptop asleep past its hour) the engine answers `403 identity_token_required`: the server logs once that the token expired while the session slept and rebinds on the next start, stops refreshing for that process, keeps renewing the seat, and leaves the token file for the next SessionStart bind. After a wake the server refreshes on its first tick while the token is still live, and retries within 5 seconds if the network is not back yet. A refused fork row never stops the seat's renewal, and the SessionStart hook's fork (a `/branch` or an unindexed `/resume`) that the engine refuses for want of a live token falls through to a start instead of leaving the session unbound. `nx identity create` in cloud mode says one line for `409 seat_limit` (the sixth seat one identity creates through a session; no route removes a seat, so it says to reuse one, or to make a new one with the uncapped tenant credential).
