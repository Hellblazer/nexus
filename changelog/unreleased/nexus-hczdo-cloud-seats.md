### Changed

- **In cloud mode a session makes, promotes and delegates seats through its own identity token (RDR-253, client half).** A box that holds the data credential (it mints data tokens, no static service token) now sends `X-Nexus-Identity-Token` on `nx identity promote`, `nx identity create` and the delegated identity a tool-granting `claude -p` child gets; the token is the session's own (`nx identity promote --token-file <file>` names another session's, which is what `claude-restart-sessions` does for the session it is about to restart). A tenant credential sends no token and behaves as before. A create from a process with no live identity is refused at once with one line, and each engine refusal (`identity_token_required`, `not_owner`, `generation_superseded`, `identity_not_held`, `not_ephemeral`, `unknown_identity`, `forbidden`) is one clear line. Against an engine older than 0.1.197 every seat call says `seats need engine 0.1.197 in cloud mode`, and the restart script says it once per run, not once per session. The engine half ships in engine-service 0.1.197; until it is deployed, seats stay unavailable in cloud mode.
