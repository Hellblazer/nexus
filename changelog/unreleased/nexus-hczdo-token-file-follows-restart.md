### Fixed

- **A long-lived process (the MCP server) follows its Claude process's registry file to the new token file after an in-place `/restart`.** The restart keeps the Claude pid and gives its registry file a new `startedAt`, so the next generation's identity token is written to a new file. The token reader kept the file name it found first, so the server went on sending the superseded generation's token: identity-scope scratch writes were refused as `generation_superseded` while the old token lasted, and the identity scope stayed unusable until a fresh server started. The name is now looked up from the registry on every call (nexus-hczdo).
- **Identity-scope scratch reads no longer carry the identity token, and a write's 401 re-reads the token file once.** The engine answers an identity-scope read to anyone, but sends a token it cannot resolve to a 401 before any handler runs, so a read that carried an unresolvable token from the file failed with `unauthorized T1 session (HTTP 401)` on `/v1/t1/list` while the session scope worked. Only writes carry the token now, and a write refused with a 401 re-reads the token file and resends once when it holds a different token, before the session-token and bearer heals run. A registry or token file that cannot be read is read once more after about 10 ms, and `scope_owner` says "token file not readable yet" for a process that has a Claude ancestor and no readable file (nexus-hczdo).
