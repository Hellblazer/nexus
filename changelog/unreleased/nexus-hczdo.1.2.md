### Added

- **Identity tokens and the four fences of session identity (RDR-253 Step 2).** A bind that leaves the caller holding an identity (`start`, `resume`, `takeover`, `clear`, `fork`, `refresh`, an ephemeral or delegated create) now returns an `identity_token` that names the identity and its generation and lives one hour; a bind with event `refresh` at the same generation mints another. Tokens are rows of a new table `identity_tokens` (schema only, nothing migrated at boot), each mint an insert, so a restart, a `/clear` or a refresh never invalidates a token that is still within its hour. The token travels in the `X-Nexus-Identity-Token` header; an expired or unknown one is a 401. Four families now refuse a write from a process that no longer holds the seat: the owner's `in`, `inp`, `ack`, `nack`, `renew` and `release` on `mailbox/i<n>` (a send stays open to any caller); a join, role change or leave on `/v1/identity/<id>/memberships`; every `put`, `put_or_merge`, `merge`, `import`, `import_batch`, `delete`, `restore` and rollup `summaries` that touches an entry in project `threads` carrying an `identity: <id>` line (the stored entry decides, a write may not drop or change the line, a new entry may name only the writer; `expire` and `reap` leave such entries alone; `put_or_merge` keeps its similarity merge but never picks such an entry as the target); and writes to a new T1 identity scope (`session_id` of `identity:<id>`), which `session/close` and the sweeps never touch. A token of the right identity but an older generation is refused with 409 `generation_superseded`, a different code from every other 409; a token for another identity is 403 `not_owner`; a token whose identity has let go of the seat (state `unheld` or `ended`, or `lapsed` with its holder recorded gone, as after `end`, `release` or a purge) is 409 `identity_not_held`, while a `lapsed` seat that a client has not reported gone still writes; a write with no token is 403 `identity_token_required`, except to a seat whose binding is `unleased`, which is accepted and marked with the response header `X-Nexus-Unattested`. `bind` events `clear`, `fork`, `refresh` and `end`, and `renew`, from a superseded generation answer `generation_superseded` rather than `generation_conflict`; a `clear`, `fork` or `refresh` that names any field of a process (host, pid, `started_at` or `proc_start`) that differs from the holder's is 409 `holder_mismatch`; a request that names none is unchanged. A parked `in` rechecks the fence when it returns a claim, and a claim the fence now refuses is released with no attempt counted. With an identity token a tuple's `sender_session` is the identity's current session id (the newest binding row under the token's generation), a T2 row records the token's identity in a new `memory.identity` column (an overwrite or merge with no token clears it), and the T1 session scope accepts every session id the session index maps to the token's identity and generation, so a write after `/clear` is not refused; reads of the session scope are not checked against the index. No client sends the header yet.
