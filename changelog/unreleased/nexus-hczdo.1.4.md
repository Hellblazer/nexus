### Added

- **A session now binds to an identity at start, and the MCP server keeps the binding alive (RDR-253 Step 3, the client half; the engine half is Steps 1 and 2, in the engine release that must precede this one).** The SessionStart hook applies the RDR's policy table against `/v1/identity`: a seat named by `NX_SEAT` or by an exact `-n` match is bound at a new generation when it is unheld, ended, or its holder no longer exists, and the session runs as an ephemeral identity (the hook prints the holder, and the take-over remedy only in an interactive session) when it is live in another process, lapsed with a running holder, or reserved after a lapse on another host; a launch that names no seat, or a `-n` that is no seat, gets an ephemeral identity whose display name is the `-n`; `resume` rebinds the resumed id's identity, switches a process that holds a different seat when the resumed one is free, and treats an id in no index, or of an ended ephemeral, as a start; `clear` and `fork` keep the generation and change the session id; `compact` changes nothing; an empty in-place `/restart` rebinds the identity the process held, whatever its state. The holder check is the client's: a registry file naming the holder's pid with its `startedAt`, a pid probe, and the process's OS start time against the binding's `proc_start`, both as UTC instants (`ps` under `TZ=UTC`); it is sent as `holder_gone`. A holder it cannot judge (Windows has no start time to read) is never reported gone. Every SessionStart also sweeps the bindings on its host and reports crashed holders to `gone`, skipping its own process and delegated identities, and deletes token files and pending files of processes that are gone.
- **`resolve_identity()` and the per-process token file.** One function answers "which identity is this process" from an explicit token file (a delegated child), the hook payload's session id, `CLAUDE_CODE_SESSION_ID` and the token file of the nearest Claude ancestor, maps an unknown id through the live registry entry's pid and `startedAt`, and refuses, naming both, when two inputs disagree (which is also how a Bash child started before a cross-seat `/resume` is refused). The hook writes `~/.config/nexus/identity/<claude pid>.<startedAt>.token`, mode 0600, one file per process start. The T1 handoff marker now also carries the identity, generation and the token file's path (never the token) on `clear`, `resume` and `fork`.
- **The MCP server's identity lease.** On a new process start the server reads its Claude process's token file (once a second for up to 30 seconds), re-reads it on every heartbeat, renews every 60 seconds, refreshes the token at half life, appends the `/branch` `fork` row when its session id is unknown to the index, binds from the hook's pending file when the hook's registry wait timed out (`pending.<claude pid>.<OS start epoch>`, taken only by the server of that process, with the data credential, which needs no `clear`, `release`, `takeover` or `gone`), stops writing identity state and says so when its generation was superseded, and on a clean shutdown sends `end` (when its Claude process has exited) and deletes its token file. `NX_IDENTITY_LEASE=0` turns the lease off.
- **`nx` sends the identity token.** The shared T2 store client and the scratch store attach the token of the nearest Claude ancestor's token file in `X-Nexus-Identity-Token` (scratch only for the identity scope), re-read the file once and retry once on a 401, and stop with a typed error naming the holder on `409 generation_superseded`. A token the file records as expired is not sent, and a request that carried a token is never retried without it.
