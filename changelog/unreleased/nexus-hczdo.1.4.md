### Added

- **A session now binds to an identity at start, and the MCP server keeps the binding alive (RDR-253 Step 3, the client half; the engine half is Steps 1 and 2, in the engine release that must precede this one).** The SessionStart hook applies the RDR's policy table against `/v1/identity`: a seat named by `NX_SEAT` or by an exact `-n` match is bound at a new generation when it is unheld, ended, or its holder no longer exists, and the session runs as an ephemeral identity (the hook prints the holder, and the take-over remedy only in an interactive session) when it is live in another process, lapsed with a running holder, or reserved after a lapse on another host; a launch that names no seat, or a `-n` that is no seat, gets an ephemeral identity whose display name is the `-n`; `resume` rebinds the resumed id's identity, switches a process that holds a different seat when the resumed one is free (its holder gone, or its other-host reservation over), keeps the process's identity when the id is in no index rather than starting a second one beside it, and treats an ended ephemeral as a start; `clear` and `fork` keep the generation and change the session id; `compact` changes nothing; an empty in-place `/restart` rebinds the most recent identity the process held, whatever its state. The take-over remedy the hook prints names `nx identity claim`, which arrives with `nx identity` in the Step 4 change of the same release.
- **The holder check is the client's, and it judges only what it can see.** A holder is gone when its registry file is absent or has another `startedAt`, its pid is not running, or the pid's OS start time differs from the binding's `proc_start`, both as UTC instants (`ps` under `TZ=UTC`; on Windows the process creation time). The registry legs read one registry directory, `CLAUDE_CONFIG_DIR/sessions`, so the holder's own token file decides whether they apply: for a holder whose token file records that directory they do; for a holder whose token file records another directory, or that has no token file, the registry is not read (a leftover file of another process with the same pid cannot vouch for it) and only the pid probe and the start-time compare speak: a dead or reused pid is gone, anything else is unknown, and unknown is never reported gone. Such a holder that is running (or restarted in place, which needs the registry to see) is freed only by a take-over, not by lease lapse, which on its own host never frees a seat. The engine's binding row has no field for the registry directory, so it is recorded in the token file only. The verdict is sent as `holder_gone`. Every SessionStart also sweeps the bindings on its host and reports crashed holders to `gone`, skipping its own process and delegated identities. A token file of a gone process is deleted only after the sweep recorded the gone with the engine, or the engine no longer lists that process as the holder of the file's identity; pending files and stale temp files of dead processes are removed on every start.
- **A credential that may not clear, release or report gone still binds.** A mint-only install holds the data credential, which may not send `clear`, `release`, `takeover` or `gone`: `/clear` is then sent as a `fork` (the same session-id change), a cross-seat `/resume` keeps the seat and says the credential cannot release it, and the sweep ends quietly. The hook waits up to 5 seconds for its own registry file and ignores one that is not this process's (another `sessionId`, or a `procStart` other than the process's OS start time: a crashed earlier owner of the pid leaves one behind).
- **`resolve_identity()` and the per-process token file.** One function answers "which identity is this process" from an explicit token file (a delegated child), the hook payload's session id, `CLAUDE_CODE_SESSION_ID` and the token file of the nearest Claude ancestor, maps an unknown id through the live registry entry's pid and `startedAt`, and refuses, naming both, when two inputs disagree. It is called where a write happens: a process whose session id indexes to a different identity than its token file names (a Bash child started before a cross-seat `/resume`) sends no token and fails with the resolver's message (the MCP server, which owns the binding and keeps the session id it started with, is not checked; an engine that cannot be asked is not asked again for 30 seconds). The hook writes `~/.config/nexus/identity/<claude pid>.<startedAt>.token`, mode 0600, one file per process start, under a file lock. The T1 handoff marker also carries the identity, generation and the token file's path (never the token) on `clear`, `resume` and `fork`.
- **The MCP server's identity lease.** On a new process start the server reads its Claude process's token file (once a second for up to 30 seconds), re-reads it on every heartbeat, renews every 60 seconds, refreshes the token at half life (a compare-and-swap under the file lock, so it never writes the old identity over a switch the hook made), appends the `/branch` `fork` row when its session id is unknown to the index, binds from the hook's pending file when the hook's registry wait timed out (`pending.<claude pid>.<OS start epoch>`, taken only by the server of that process, with the data credential, which needs no `clear`, `release`, `takeover` or `gone`), stops writing identity state and says so when its generation was superseded, and on a clean shutdown sends `end` (when its Claude process has exited) and deletes its token file, on a thread and a time budget of its own. It uses one engine client for its life, and the handoff marker is adopted off the event loop. `NX_IDENTITY_LEASE=0` turns the lease off. The pending bind is not verified on Claude Desktop, whose MCP server never sees the session id (JDR-002 F17): the pending file is found by process, not by session id, but that has not been tried there.
- **`nx` sends the identity token on the requests the engine fences.** The shared T2 store client attaches the token of the nearest Claude ancestor's token file in `X-Nexus-Identity-Token` on memory writes (threads entries), mailbox claim operations and mailbox sends (so the send is stamped from the identity's current binding), and the scratch store on the identity scope; no other request carries it, so an unknown token cannot 401 a read. A send that gets a 401 is resent once without the token. It re-reads the file once and retries once on a 401, and stops with a typed error naming the holder on `409 generation_superseded` (and one naming the state on `409 identity_not_held`). A token the file records as expired is not sent, and a request that carried a token is never retried without it. A process with no Claude ancestor looks for one once, not on every request.
- **Windows.** The process start time comes from the process creation time, so the pending file, `proc_start` and the in-place `/restart` rebind work there; the registry's `procStart` is not compared there.
