### Added

- **`nx identity` (RDR-253 Step 4, shipping with Step 3 in one conexus release).** `create NAME` makes a seat; `show [SEAT]` prints the identity, its state, generation, holder, client version and the five most recent binding rows (`--session ID` shows the identity a session belongs to, `--json` prints the engine's record); `show --all` lists the bindings held on this host with their client versions and the live Claude processes here that have none, leaving out `claude -p` children (entrypoint `sdk-cli`; their binding is their dispatcher's) and processes whose pid was reused (Phase 2's gate reads it; the engine has no route that lists unheld seats, so an identity with no holder here does not appear); `alive [SEAT|ID|PID]` runs the holder check and reports gone holders to the engine as the SessionStart sweep does (no argument: every binding on this host); `claim SEAT --take-over`, `release SEAT`, `rename OLD NEW`, `promote ID NAME` and `purge ID --operator`. The take-over remedy the Step 3 hook prints now names a command that exists.
- **Take-over, release and purge carry their guards.** `claim --take-over` binds the caller's own Claude process at a new generation, writes its token file and closes the identity it held before (`end` for an ephemeral, `release` for a seat); it is refused from a `claude -p` child (registry `entrypoint` `sdk-cli`; only `cli` and `claude-desktop` pass), when the seat's holder is an ancestor of the caller (the caller's own Claude process, which already holds the seat, is not refused), and when there is no Claude ancestor: a plain shell, and a registry file whose process is gone, whose pid was reused (the holder check's start-time compare) or whose command is not `claude`, since file presence alone never decides. A take-over that loses the compare-and-set reads the seat again and tries once more. `release` has none of those guards and runs from a plain shell: on the holder's host it is refused while the holder runs or cannot be judged, for a holder on another host while its lease is live. `purge` is refused for a live or unheld identity and for a lapsed one with no recorded `gone`; `promote` and `rename` refuse an id-shaped (`i<digits>`) name before asking the engine.
- **`claude -p` children of the operator dispatcher get delegated identities.** A dispatch that grants the child tools (`allowed_tools` or `mcp_servers`) and runs under a Claude session with a bound identity creates a delegated identity (`kind=delegated`, `parent` the dispatcher's own identity, generation 1, one `start` row), writes its token to `~/.config/nexus/identity/delegated/<id>.token` (mode 0600), and passes the child `NX_IDENTITY_TOKEN` naming that file in place of any token it carried. The dispatcher renews the binding every minute, refreshes the token at half life, and on every exit (success, harness failure, timeout kill, spawn failure) stops renewing, deletes the file and appends `end`. The child's SessionStart hook sees `NX_IDENTITY_TOKEN` and binds nothing. A dispatch with no parent identity, or one that grants no tools (a child that cannot reach nexus), makes no engine call; an engine that refuses the create is one warning and the dispatch runs. In each of those cases the child's `NX_IDENTITY_TOKEN` names a file that does not exist, so it acts as no identity and never walks up to the parent's Claude process and token file. No `claude` child inherits its parent's `NX_IDENTITY_TOKEN`. The end of a delegated identity runs off the MCP server's event loop (the token file goes at once, `end` runs in a thread that a cancellation does not interrupt, and the dispatcher waits for it at most 5 seconds), so a hung engine cannot stall other calls. A token file that cannot be written after the create ends the identity it made.
- **A dead dispatcher's delegated identity gets a `gone` row.** The binding records the dispatcher's pid and OS start time (a dispatcher has no registry file); the SessionStart sweep and `nx identity alive` check that process for delegated identities (the pid probe and the start-time compare, so a reused pid is gone) and record `gone` for a dead one, so retention's "lapsed with its holder gone" and `purge` can fire for it. The hook also removes the token files in `~/.config/nexus/identity/delegated/` whose dispatcher process is gone, and temp files there older than 10 minutes (as it does at the top level), except in a run whose sweep ended on a 403 (a credential that may not report `gone`), which deletes no token file. One failing row does not stop the rest of the delegated sweep; a cancelled dispatch that was creating the identity still ends it. The main sweep still skips delegated identities; the delegated check is separate.
- **The restart script keeps seats across a restart.** Before either restart path (the default in-place `/restart` and the exit-and-relaunch), `scripts/claude-restart-sessions` asks the engine what identity the session holds. A session that holds a seat keeps it: the relaunch carries `NX_SEAT=<that seat>` (Step 3 binds a seat named by `NX_SEAT`; a `-n` that names no seat would give the relaunch an ephemeral identity), and no second seat is made for a different display name. Otherwise, for a name the user set (the registry `nameSource` is `user`: `-n` or `/rename`), when no seat has the name: the session's ephemeral identity is promoted to the seat (its scratch and board entry stay), else a seat is created with `created_by=restart` (a session with no identity, or whose ephemeral has ended). A seat that already has the name is left alone. A generated name makes no seat and is no longer passed back as `-n` on relaunch (it would become a user-set name on the next restart). A session whose registry has no `nameSource` (an older Claude) is not taken for one with a user-set name, so no seat is made for it, but `-n` is still passed back as before; the rule is stated once (`name_kind`). Names reach `nx identity` after `--`, so a name that starts with `-` is not read as an option. The relaunch finds the old holder gone and binds the seat, so no release step is needed. A failure to reach `nx identity` is logged and never stops the restart. `--revive` has no registry entries and is not covered.
