### Added

- **Identity scratch, per-identity T2, memberships and background work (RDR-253 Step 6, nexus-hczdo.1.9).** `nx scratch --scope identity <verb>` (and the `scratch` MCP tool's `scope` argument) works in the scratch of the session's identity, the T1 scope `identity:<id>`: it survives `/clear` and a restart, a session's end never closes it, only the identity's own process can write it, and a `claude -p` child reads its parent's scope and cannot write it. A process with no identity gets an error, never the session scope. `nx memory put|get|search|list --mine` works in the project `identity/<id>`, keyed by id so a rename moves nothing. `nexus.identity.membership` joins, leaves and lists group memberships through the engine's fenced membership routes (a write by a non-owner is refused).
- **`nx identity work` and `nx identity may-stop`.** A session registers what it owns as `identity_work` rows: `register`, `done`, `forget`, `list [SEAT] [--session ID] [--running] [--json]`, `owners`, and `run --kind K --ref R -- COMMAND` (registers, runs, marks done, passes the exit status through). Kinds are `worktree`, `tmux`, `watcher`, `wait` and `labrun`. `may-stop --kind K --ref R` exits 3 naming the owner when another identity owns the resource with running work and a live holder, 1 on any other failure (it fails closed), and 0 otherwise; it reads ownership from the rows and liveness from the holder check, never from `ps`, a name pattern or a directory. The `git-worktrees` skill registers each worktree it creates and `finishing-branch` asks `may-stop` before removing one; `nx tuple wait` labels its wait; the restart sandbox registers its private tmux server and asks `may-stop` before `kill-server`.
- **A running row of an identity that is not alive is stale** and every reader ignores it, so a crashed session's work never reads as busy forever. `nexus.identity.ops.is_alive` is the one check (an unreadable holder counts as alive).
- **The restart script reports running work.** `claude-restart-sessions --status` lists each target's running work under its row, and `--ask-ready` tells each session its own list. A ready reply does not count while a running `wait`, `watcher` or `labrun` row of the session's live identity is listed, as with a background task in its process table, which is still checked.
- **Fix round 1 (stacked review).** `nx identity work run` runs the command whatever happens to its label (an engine that cannot be reached, a refusal or an unexpected answer), forwards SIGTERM and SIGHUP to it (a terminal's Ctrl-C reaches it through the process group; `run` itself ignores SIGINT so it can mark the row done) and marks the row done. `nx identity may-stop` exits 3 when a live identity owns the resource and 1 for any other failure, and the restart sandbox keys on the status; a worktree's ref is its real path on every `work` verb. `nx scratch --scope identity` turns engine and identity failures into messages and refuses `clear` and `flag` (the engine never closes the scope), the MCP `scratch` tool refuses `persist` for it, `scratch_manage` takes `scope`, and the per-call store is closed. `nx memory --mine` follows a delegated child to its parent's project. The `nx tuple wait` row is ended after the notice is printed, with a 2 s engine timeout, as the identity captured at the start, never over a successor's row, and on SIGTERM. `scripts/agent-worktree-preflight.sh` registers the worktree (best effort, silent). The restart readiness note says per kind what a restart cuts off, and `--status` bounds its engine call to 5 s. The compaction checkpoint lists the session's running work rows.
