### Changed

- **Engine: `POST /v1/identity/<id>/promote` retitles the identity's board entry (RDR-253, engine 0.1.198).** The promote moves the identity's threads entry to the new alias in its own transaction, on both routes (the tenant credential and the data credential's self-service promote), so it no longer matters which process runs `nx identity promote`: the old limit that the title moved only when the command ran inside the session that owns the entry is gone. An entry already titled with the alias is never overwritten; the promote still succeeds, the entry keeps its title, and the answer carries `board_retitle: "title_taken"`. The answer always carries `board_entries_retitled`, which is how a client tells this engine from an older one: the client's own best-effort retitle now runs only against an engine whose answer lacks that key. No migration; a promote of an identity with no board entry changes nothing else.
