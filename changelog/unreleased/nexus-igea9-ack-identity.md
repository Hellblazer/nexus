### Fixed

- **An ack of a develop red now carries the poster's identity id in `from`, and `nx group ack-times` counts it the way the engine does (RDR-252, nexus-igea9).** The engine counts an ack by the row's sender-session stamp mapped through the session index and never reads `from`; an ack posted by hand with `from=<session alias>` still stopped the hand-off, but `nx group ack-times` read `from` and counted that red as unacked. Every client write of a `kind=ack` row to a `board/ci/<topic>--owner` subspace (`nx tuple out`, the `tuple_out` MCP tool, an `ack` reply, `nx ci ack`) now stamps `from` with the caller's own identity id from its token record, logging one info line when it replaces what was typed, and refuses a caller with no identity. `nx group ack-times` maps each ack's sender-session stamp through the identity service's session index and reads `from` only for a row with no stamp (a name through the red's own `owner_alias`/`next_alias`, then the identity service); a lookup that fails for a reason other than "not known" is noted on standard error and not remembered.
- **New verb `nx ci ack <sha> [--topic nexus-develop--owner]`.** Posts the ack of a red develop as the caller's identity, resolving a 7-digit sha prefix against the tips of the current red, and refuses a caller who is not that red's owner (an ack from anyone else counts for nobody). The `ci_develop_red` aura's state line now ends `Ack: nx ci ack <sha7>`, which fits the 200-character line at every input.
