### Added

- **An aura can name every base a group serves with one file (RDR-252 "Aura per base", nexus-igea9).** A trigger may carry `{serves}` once inside its topic (`board/ci/{serves}--owner`). For a session in the aura's `[load]` group, the loader expands it into one aura per base in the group's `serves` list, named `<aura>@<base>`, each on its own concrete subspace and in its own threads block (`display.threads` carries `{base}` and optionally `{branch}`; `self.branch` maps the base's branch into a procedure argument). Any other brace in a subspace, a template with no `[load] group`, and `self.branch` outside a template are refused. `nx aura check` validates a template against every base its group serves and refuses one whose group has no live record or serves nothing; `nx aura list` shows the bases a template loaded for. `ci_develop_red` and `ci_develop_nudge` are now templates, so the push-train group loads one copy per base it serves; the notices name the base's branch instead of "Develop" (`ci_red_notice` and `ci_red_nudge` take an optional `branch`, default `develop`).

### Changed

- **The two shipped CI auras write a threads block per base.** A session serving `nexus-develop` now has `## aura: develop CI red (nexus-develop)` and `## aura: develop CI nudge (nexus-develop)` where it had `## aura: develop CI red` and `## aura: develop CI nudge`; the aura names in the state file and the channel notice are `ci_develop_red@nexus-develop` and `ci_develop_nudge@nexus-develop`. The config key is unchanged: `auras.ci_develop_red` and `auras.ci_develop_nudge` still turn them on.
