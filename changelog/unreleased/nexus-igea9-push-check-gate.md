### Added

- **The develop push runs the checks its diff reaches, against the pushed tree, and refuses a red.** `scripts/git-push-develop.sh` materialises the tip's tree as a detached worktree (removed on every exit path), always runs `file_size_ratchet.py check`, `changelog_fold.py check` and `context_budgets.py check` (the context-size ceilings, under a second), and adds the wire-pairing check for a wire or ledger diff, `tests/scripts/test_cloud_leg.py` for `docs/`, and the plugin release-drift ledger test (with `NX_REQUIRE_PLUGIN_DRIFT_CHECK=1`) for a plugin-surface diff, and `tests/test_integration_pg_cluster.py` (`-m "not slow"`, about 20 s, no engine) for a change to the throwaway-cluster setup; a pytest check that skips any test, bar the one opt-in cloud-leg skip, is refused as vacuous. A red is `PUSH_REFUSED_<CHECK>` (exit 14) with the command to reproduce it; a check missing from the tip, or one that passes without examining anything, refuses too, and a gate that cannot start is `PUSH_REFUSED_CHECK_GATE_ERROR` (exit 15). The docs-readers selection (when `docs/` changes) and the write-seam behavioural gate (when ci.yml's path filter matches) are not run live: each needs `--proof <status file>` from `scripts/watched_pytest.py --status`, which now records the tree sha it ran on, whether the checkout was clean, pytest's summary line, the start, the duration and the host (printed when a proof is accepted and recorded under `proofs`). `--skip-<check> '<reason>'` (flags only, no environment twin) overrides one check; the reason is printed as `PUSH_CHECK_SKIPPED` and written into the push record body by the new repeatable `nx ci record-push --skip CHECK=REASON` (under `skips`, inside the 1024-byte cap). The gate runs after the hold check and before the lock. Five develop reds on 2026-11-22 (write-seam 422, wire ledger, cloud-leg routes, plugin ledger, the context-size ceiling) are the cases it was built for.
