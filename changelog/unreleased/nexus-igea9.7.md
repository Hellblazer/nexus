### Added

- **An aura can load by group membership, take the session's own identity as an argument, and wake only when its result says so (RDR-252 Step 4).** A `[load]` table with one key, `group`, makes an aura load only in a session whose RDR-253 identity is a member of that group while the group is live (no `ended_at`, `ends` not passed, a record exists). The MCP server reads the identity's memberships once at start and each named group once; a server with no identity, a Desktop server that did not make the bind itself, or a read that fails loads no group-gated aura and says why. An `[args]` value of `self.identity` is the session's identity id (a source, not a reserved name; `nx aura check` accepts it for a declared string argument). `display.channel` may be the name of a boolean field of the procedure's result: the fixed notice goes out only when it is `true`, and a missing or non-boolean field is a failure like `when.field`. The server writes `~/.config/nexus/auras/loaded-<claude pid>.<startedAt>.json` (its identity, the identity the auras were loaded for, and each aura's load decision), rewrites it when its heartbeat sees an identity change, and removes it on exit. `nx aura list` shows loaded or not and why for each aura that is on, drops the file of a process that is gone, and says to reconnect the MCP server after a cross-seat `/resume`. `nx aura check` gains a warning level: an aura triggered on a `board/ci/<base>--owner` subspace whose `[load]` group does not serve `<base>` is warned about (a group that cannot be read is skipped by name). `IdentityClient.memberships(identity)` reads RDR-253's membership route.

- **`ci_develop_red` moves onto the owner post and loads only for the `push-train` group (RDR-252 Step 4).** The aura triggers on `board/ci/nexus-develop--owner` (`kind=owner`, cleared by `kind=clear`) instead of `board/ci/nexus-develop--done`, takes the session's identity as `me = "self.identity"`, and sets `display.channel = "wake"`, so only the owner, the next up and, on an escalation, the named or every member are woken. `ci_red_notice` shows one text per state of the owner row: the owner's own red, a red the leader takes (naming the `reason`), a hand-off (its own text, since the owner did not push the red), an escalation that asks for an ask to Sam, next up, and everyone else (hold your pushes). Names are the identity ids the row carries. It needs an engine that carries the owner doc block of nexus-igea9.1, so this conexus release pins that engine release. **Until `push-train` is formed and serves `nexus-develop`, a session with `auras.ci_develop_red=on` sees no develop reds at all**: the aura loads in no session, and the earlier `--done` red notice is gone.

- **`nx group` and `nexus.groups`: the client of the engine's group records (RDR-252 Step 4).** `nx group form NAME --serves TOPIC` makes the calling session's identity the leader of a new group (and re-forms a disbanded name); `set` changes the leader, `--ack-deadline`, `--ack-deadline-for TOPIC=MINUTES` (merged into the stored per-topic deadlines), `--ends` and `--serves`; `disband` ends it; `override` (tenant credential, no identity token) replaces the leader or ends the group while its leader cannot write. `join` and `leave` add and remove the caller's membership, refuse an ephemeral or delegated identity and a leader that has not handed the group on, and print that the MCP server must reconnect, because membership is read once when a server starts. `list NAME` shows the leader and the members in join order by alias, each with its RDR-253 state (`unheld`, `live`, `lapsed`, `ended`, or `unleased`), and `ack-times NAME` is the Day 2 calibration read: per red on the topics the group serves, the sha, the time its episode began, the time of the acknowledgement the engine would count (the owner's, never one from an identity the red was handed away from) and the minutes between. Group and membership writes carry the session's identity token, with the one-time resend on a 401 that a threads write already has. `nexus.groups` is the same client for the aura load stage: `read_group(client, name)` returns the group record or `None` when the name has no record.
