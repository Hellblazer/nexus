### Changed

- **Engine: the owner row names the owner and next up by alias (RDR-252, engine 0.1.198).** The owner stamper adds `owner_alias` and `next_alias` to the body of a `kind=owner` row on `board/ci/<base>--owner`, each the identity's live alias read at stamp time, beside the existing `owner` and `next` ids (which stay, and which every decision still uses). An identity with no live alias, an ephemeral one for example, gets no alias field, and a row an older engine stamped has none, so a reader falls back to the id. The alias is read inside the stamping transaction, and a failed read posts the row with ids alone (a warning, `event=board_owner_alias_read_failed`). The two fields count against the template's 1024-byte body cap: if they would pass it, listed suspects are cut, as before. `board-ci.yaml`'s `doc.body` lists both fields; the body has no schema or allowlist, so nothing else changes and no migration runs. The `ci_develop_red` aura's red notice now says "halcyon owns it" where it said "i12 owns it", and `nx group ack-times` shows `owner_alias` and `acked_by_alias` (`acked by halcyon`, the id when the row has none). The aura runtime no longer counts a missing body field as a failure for an argument the procedure marks optional: the argument is left out, and the procedure's own header still refuses a missing required one. Run `nx aura check` against engine 0.1.198 or later: it checks the aura's new body sources against the engine's `doc.body`.
