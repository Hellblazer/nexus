### Fixed

- **`nx upgrade` says what happened to the storage service it restarts** (nexus-mjmjl, first-run audit item 14). An upgrade restarts a running storage service on the new version, both in its precondition stage and at the end. It used to discard the output of `nx daemon service stop` and `start` and never read their exit codes, so a failed start left the service stopped with nothing printed. Now an interactive upgrade prints a line before the restart and one after it. A service that is still starting (the first start after an upgrade can migrate the database for minutes) is reported as still starting, and the upgrade succeeds. A failed restart ends the upgrade with what failed, the command to run and what `nx daemon service start` said, and exits 1. `--auto` and the lockstep hook's unattended run stay silent, log it, and exit 0.
- **`nx doctor --fix --dry-run` shows what `--fix` would delete, and deletes nothing** (nexus-mjmjl, item 27). Before this, `--dry-run` was ignored with `--fix`, so `nx doctor --fix --dry-run` deleted for real. `--fix` permanently deletes orphaned catalog links, documents deleted more than a day ago, and the chunks they left behind. Its help now says so, and the doctor row that suggests it offers the preview first.
- **Starting a Claude session no longer restarts a healthy storage service** (nexus-f3yqd). The SessionStart hook runs `nx upgrade --auto` at every session start. With two nexus clients installed, it saw a version mismatch every time and restarted a healthy storage service, which can throw away work the engine is doing, such as an index build. Under `--auto` an upgrade now only reports a stale service or engine; it never installs the engine or restarts the service. An MCP server's start behaves the same way, and the plugin's background `nx upgrade` after a version change never restarts the service on a version string (it still installs a new engine when one is due, and that install restarts the service). A service started by a newer client is never downgraded by an older one. Run `nx upgrade` yourself to converge; `nx doctor` shows anything pending.
