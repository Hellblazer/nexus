### Changed

- **A read of chunks by id tells the engine which fields it wants** (nexus-mjmjl). `HttpVectorClient`'s get by ids now sends `include` to `/v1/vectors/store-get`, as its get by filter already did. An engine that honours it can skip the chunk text a metadata-only read never uses, such as the upgrade ladder's manifest steps. An older engine ignores the key and answers as before. Every caller that passes `include` reads only what it asks for, so nothing changes until the engine projects.
- **Checks that a collection exists no longer count every collection's chunks** (nexus-mjmjl). `HttpVectorClient.get_collection`, `collection_exists`, the TTL expire sweep, `nx store get` and delete's collection scope, `nx store`'s reap typo check, and `nx t3`'s collection checks read the routing listing (`/v1/vectors/stats?fields=routing`). It lists the same registered collections that hold chunks, from the catalog, without the per-collection counts the full listing makes the engine compute: 55 ms against 469 ms on a 140k-row store, a cost that grew with the store. `nx store list`, `nx collection list` and the other verbs that print counts keep the full listing. An engine that predates the routing form answers with the full rows, so the answer is the same either way.
