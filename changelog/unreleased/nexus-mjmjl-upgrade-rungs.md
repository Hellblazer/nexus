### Fixed

- **`nx upgrade` reads the catalog fewer times per data step, and says how far it is** (nexus-mjmjl). A data step with no completion record used to scan every document three times in one `nx upgrade`: a dry run to decide, the fill, and a dry run to confirm. Only the elapsed-time heartbeat showed in between. Now the check answers pending without a scan, and the fill makes the first read. When the fill finds nothing to change, the confirm step reuses that read, so the step reads once. When it fills rows, the confirm step reads again to prove the fill, so the step reads twice. The fill prints a line at most every 5 s with its running counts (documents, rows, fillable, filled; notes examined and converted; a line per collection for the RDR-192 backfill). The line goes to stderr under `--auto` on a local engine. The two manifest steps look each collection up once per scan instead of once per batch (a lookup lists every collection) and read 200 documents per batch instead of 50, so a large store makes fewer, fuller reads. Each logs the collection lookups, chunk pages and owner pages it made. A note-tags step that is already recorded still lists the notes, so tags an older client wrote as a string since are still rewritten. `nx upgrade --dry-run` still makes the full read-only scan. `nx doctor`, the first command after a version change, and `--auto` against a managed service still make none.
