### Fixed

- **A collection label the readers misread can now be named by quoting it.** A label that passes the RDR-229 rule but is `all`, ends in `*`, `-*` or `-<8 hex>`, or starts with `$` was misread by a reader: bare `all` is the corpus wildcard, so it could not be named in a `corpus` argument; the others were stripped or read as a binding in a plan's scope tags and step arguments. Putting double quotes inside the value names that label exactly: the MCP search family takes `corpus='"all"'` (JSON `"corpus": "\"all\""`) for the collection labelled `all`, and plan scope tags and step `corpus` args read the same form. Unquoted parts read as before, `nx search --corpus` is unchanged, and the label rule is unchanged. A plan's `corpus` list is now read part by part when its scope tags are inferred, and the owner narrowing quotes a kept label the corpus reader would otherwise read as the wildcard (nexus-o5vbo).
