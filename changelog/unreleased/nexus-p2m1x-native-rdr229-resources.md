### Fixed

- **The native engine binary now carries the `db/rdr229/` resources, so RDR-229's boot-time completion work starts and a collection rename is no longer refused for a missing list.** `resource-config.json` had no pattern for `db/rdr229/`, so the native binaries of engine-service v0.1.200 to v0.1.202 lacked `p33a-fk-twins.tsv` and `p35b-continue-changesets.txt` (`p31-checks.tsv` was embedded only because another reader's `Class.getResourceAsStream` call registers it). On those binaries RDR-229's completion work never starts: `FkTwins` throws "is not on the classpath" from its static holder, `CompletionBootWork.atBoot` fails with `ExceptionInInitializerError`, the engine logs `event=rdr229_completion_not_started` and `GET /v1/status` never carries `rdr229_completion`. And with no P3.5b list, every collection rename reads as refused (`rename_refused`, `missing: p35b_list_missing`), on a fresh install too. JVM tests read the files from the classpath and never saw it. The pattern `db/rdr229/.*` is added; `ResourceConfigCensusTest` fails on any file under `src/main/resources` that no `resource-config.json` pattern, pom `-H:IncludeResources` buildArg or named not-read-at-run-time entry covers; `scripts/check_native_embedded_resources.py` (the native build's trip-wire on every release leg) now fails when `embedded-resources.json` does not name the three lists the engine reads at run time; and `service/native-smoke.sh` fails the native boot when `rdr229_completion` is absent from `/v1/status` after a 60 s poll or the engine log carries `ExceptionInInitializerError`, "is not on the classpath" or `rdr229_completion_not_started`.
