### Fixed

- **A collection is found by its catalog row, not by a rendered name (RDR-229 P2.8).** `nx index repo`, `nx catalog collection-name` and the RDR hook now use the collection a repo is registered under, a legacy slug included, instead of the conformant name a render would produce; only a new collection or a version bump still renders a name. A knowledge subject (`--collection field-notes`) now finds a collection registered for that subject under a label of any shape, including on `nx index md`, `nx index pdf` and `nx dt index`. When the catalog read fails, a read falls back to the name resolution as before, and a write refuses instead of writing under the rendered name. The engine half (0.1.200) makes `GET /v1/catalog/collections/for_tuple` answer a `legacy_grandfathered` row, so legacy slugs and non-conformant labels are found by their tuple; before, they answered 404. A registered row with no readable version (a blank `model_version` and a name that carries none) is answered as it is; only a version bump on it refuses, telling you to set the row's `model_version` or re-register the collection. The re-embed target selection follows `for_tuple` and no longer skips a grandfathered row.
