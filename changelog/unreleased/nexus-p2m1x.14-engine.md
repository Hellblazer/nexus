### Changed

- **The engine's stale-note repair tells file residue from notes by the collection's registry row, not by its name.** `repairStaleNoteUris` reads each live collection's `content_type` straight from `catalog_collections`, and a row is a rewrite candidate only when that type is `knowledge`. Content type docs, rdr or code is refused as `file_routed_collection` whatever the collection is called, a collection with no row as the new `unregistered_collection`, and any other type (`unknown`, a quarantine type) as the new `unproven_content_type`; `apply` re-reads the type under a share lock on the collection rows, so a concurrent retype waits for the repair to commit. The report gains `refused_unregistered_collection` and `refused_unproven_content_type`. `NoteUri.isFileRoutedCollection` is removed; the URI-string classifiers and `note-uri-corpus.json` are unchanged (RDR-229 P2.9, nexus-p2m1x.14).
- **`nx catalog repair-note-uris` prints the two new refused reasons.** The census breakdown now adds up to `refused`: file-routed, no title part, no registry row, content type not proven a note. Against an older engine, whose report lacks the two new counts, they print as 0 (nexus-p2m1x.14).
