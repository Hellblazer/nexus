### Fixed

- **A note put into a new collection, and an import into a new target, register the collection before the first catalog document.** Since RDR-229 P3.1 the engine refuses a document under a collection with no registry row (422 `unregistered_collection`). `nx store put`, MCP `store_put`, `nx memory promote` and the recovery-bundle import registered the note's document before the combined write that registered the collection, so the first put into a new collection answered "could not catalog"; `nx store import` did the same in its pre-pass, for every document of a new target. Both now register the collection first, through the registrar the write uses, so the write finds it registered and does not register it again. `nx index md` registers the collection before its first document the same way, and a registration that fails for any other reason is logged as a warning naming the error, since the engine's later 422 names only the collection. A refusal the client raises before it sends anything (an off-profile model, a retired name, a missing Voyage key) is still reported as the client's, with nothing minted (nexus-p2m1x.17).
