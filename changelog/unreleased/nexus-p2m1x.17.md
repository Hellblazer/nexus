### Changed

- **The engine reads, after every boot, whether the collection-id stamp has finished, and reports it in its own `/v1/status` field, `rdr229_completion`.** It reads again when a data move completes, at the end of each reconciler pass, and on a 60-second safety poll. RDR-229 P3.1's boot-time completion check (`CompletionCheck`, `CompletionBootWork`) runs after the schema walk on the admin connection, over a read-only session: it reads `nexus.data_moves`, the catalog and the CHECK constraints and writes nothing, so no boot rewrites user data. Three gates, in order: every stamp move (`rdr229-stamp-<table>`) complete, then the swap and validation moves a later release adds, then P3.4's id indexes (every collection the planner would index has a VALID id-predicate index; no release builds those yet, so gate 3 does not hold). A move is complete when it, or the move that supersedes it, has `completed_at`; a failed move on a table that no longer exists counts as complete; the retired `aspect_extraction_queue` stamp is not applicable while the table or its `collection_id` column is absent, and every other label with no row stays incomplete. A stamp is complete only with its table's CHECKs present and validated, and every gate refuses while `catalog_collections_superseded_by_id_check` is missing (nexus-p2m1x.17).
- **`nx doctor` shows the completion check.** One row for the three gates (never a warning, the gates wait by design across releases), a warning per missing CHECK (the `superseded_by` one says how many of this tenant's registry rows hold its changeset back and that the wait clears by itself), and a warning per table whose stamp is done and whose CHECK is still NOT VALID because rows violate it: the row names the table, this tenant's orphan and unstamped counts, and the operator step. An orphan row is write-frozen (any UPDATE of it fails with SQLSTATE 23514 until its collection is registered or the row is deleted); with orphan rows, register the missing collections or delete the rows, then run `SELECT nexus.rdr229_restamp('<table>');` as `nexus_admin`, which registers the table's stamp move again, stamps the newly resolvable rows and validates the CHECK (registering the collection alone stamps nothing); with no orphan row, that restamp step alone finishes it. The restamp reads the table for an orphan for at most 60 seconds (`nexus.rdr229_restamp_probe_ms`) and says so if that is not enough. The unauthenticated `/v1/status` carries no number that describes tenants: the doctor's counts come from the new authenticated, tenant-scoped `GET /v1/catalog/rdr229_completion_counts` (the caller's own, never another tenant's or a total), and an engine without it leaves the counts unread, never zero. The VALIDATE waits instead of failing a boot (nexus-p2m1x.17).
- **The roll back after RDR-229 P3.1 is the operator down-step first and the tag flip second.** A previous engine cannot write a row the new `NOT VALID` CHECKs guard (SQLSTATE 23514 on its chunk INSERT, supersede UPDATE and carrier INSERTs), so `docs/runbooks/rdr-229-p31-rollback.md` hands conexus the down-step (`DROP CONSTRAINT IF EXISTS` on every listed constraint, generated from `p31-checks.tsv` by `scripts/rdr229_p31_downstep.py` and shipped as `p31-downstep.sql`), the verification query, the window (only before a data-table stamp completes, the registry's own stamp not counting; otherwise PITR: hours on a large install, read from `data_moves` rather than the clock, and on the cloud open until pg_background is installed on its PostgreSQL) and the 23514 symptom an operator sees without it. A later deploy of the P3.1 engine needs the generated re-add (`docs/runbooks/rdr-229-p31-readd.sql`) first, because the changelog records the CHECKs as run (it holds back `catalog_collections_superseded_by_id_check`, with a notice, while a tombstone with a blank `model_version` has no `superseded_by_id`, the condition vectors-068-19 skips it on; run it again once D2's repair move has completed), and the 24 function bodies vectors-069 redefined stay in place after the down-step (nexus-p2m1x.44).
