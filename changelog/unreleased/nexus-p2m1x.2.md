### Added

- **`nx doctor` gains a `uri-residue` row, and `nx catalog doctor --uri-residue` prints the same row.** It counts, across `catalog_documents`, `document_aspects` and `document_highlights`, the `chroma://` source-URI rows whose collection segment has no `rdr__`, `docs__` or `code__` prefix (split by whether their collection has content type code, docs or rdr, and by whether the segment is the row's own collection), and the `nx-note://` rows of a code, docs or rdr collection with a prefix-free segment: the residue RDR-229's repair move will meet. It warns and never fails the sweep. The counts come from one engine read (`GET /v1/catalog/uri_segment_census`, engine-service 0.1.200): on an older engine the row reads "not checked" and the catalog is not walked instead (RDR-229 P1.2, nexus-p2m1x.2).
- **`nx catalog collections-census` reads the collection registry once and reports, per tenant, how many rows disagree with their names.** Read-only. It counts content-type, model, version and quarantine-prefix mismatches (owner differences apart), live label clashes, live `(content_type, owner_id, embedding_model)` tuples with more than one candidate row with and without the grandfathered filter, live names shaped `c<digits>`, and tombstones whose successor names no row. It also lists each tuple tied at its top version (with each candidate's model version), the tuples whose winner changes if the grandfathered filter is dropped, the tuples where ordering by `created_at` instead of name would pick a different winner, each non-conformant name's attributes, and the live rows whose `model_version` is empty or not `v<digits>`. `--json` prints the report to store; its tenant label is unverified (RDR-229 P1.2, nexus-p2m1x.2).
