### Fixed

- **The completion re-check of a data move no longer times out because the database is an RTT away or a store has many tenants, and the swaps' re-check no longer grows with the tenant count.** The re-check shares one `statement_timeout_ms` across the table-wide run and every tenant's run, and it kept that budget as a wall-clock deadline over every round trip: the catalog re-read, and for each tenant `set_config`, `SET LOCAL statement_timeout` and the count. The cost grew as RTT x (6 + 3 x tenants), so on bob's 0.1.203 fork walk through an SSM forward (78 ms RTT, 6 tenants) the 1400 ms budget ran out at the 4th tenant (57014, stage RECHECK, retried for ever) with every statement fast. The budget is now the time the database spends: each run's execute time and the catalog re-read, each less one round trip per statement (the smallest a trivial statement took on that session); a tenant's setup statements are not charged. Both bounds are the ones declared and unchanged: `statement_timeout` 1400 ms, never more than what is left of the budget, and `lock_timeout` 700 ms. A verification that reads only the catalogs declares it (`/* nexus:table-wide-only */`, `DataMove#tableWideOnly`) and the re-check then runs the table-wide run alone, with no re-read and no per-tenant statement; both swaps' leaf-key verification does, so a swap row registered from this engine on has a re-check of a constant number of round trips whatever the tenant count. A swap row registered by 0.1.202 or 0.1.203 keeps its unmarked text (the registration inserts only when no row has the label) and the per-tenant path, which is still correct and no longer spends the budget on round trips; no migration rewrites it. What no setting bounds is the wall time the transaction holds the registry row for a move that is not table-wide-only: each tenant's run still adds about four round trips (a few milliseconds each on loopback). Pinned by 30 tenants behind a relay that holds every packet 30 ms each way: the per-tenant case completes, which a budget that did not take the round trip off (or charged the tenants' setup) does not, and the table-wide-only case holds the row 0.55 s at that latency with nine client messages.
