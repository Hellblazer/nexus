### Fixed

- **The completion re-check of a data move no longer times out because the database is an RTT away or a store has many tenants.** The re-check shares one `statement_timeout_ms` across the table-wide run and every tenant's run, and it kept that budget as a wall-clock deadline over every round trip: the catalog re-read, and for each tenant `set_config`, `SET LOCAL statement_timeout` and the count. The cost grew as RTT x (6 + 3 x tenants), so on bob's 0.1.203 fork walk through an SSM forward (78 ms RTT, 6 tenants) the 1400 ms budget ran out at the 4th tenant (57014, stage RECHECK, retried for ever) with every statement fast. The budget is now the time the database spends: the catalog re-read, and each run's execute time less one round trip (the smallest a trivial statement took on that session); a tenant's setup round trips are not charged. The shared bound still holds (runs whose own time adds up past it still time out, and the bound sent to the server is what is left), and no bound or constant changed: the swaps keep 1400 ms. Pinned by a 20-tenant re-check behind a relay that holds every packet 15 ms each way, which timed out at tenant 10 before this change.
