### Changed

- `POST /v1/taxonomy/topics/persist_split` answers 400 for a topic that is not a topic of the named collection, and changes nothing (RDR-229 P3.5a). Before, the split acted on the topic whatever collection the request named. A topic filed under no collection, or under a label no row holds, is judged by its stored label.
- The re-embed start that re-enters a kept source (`POST` on the re-embed `jobs` route with the `source_collection` of a `done` job that kept it, `kept_tombstoned`) reads both ends' registry rows by the ids the job stored (RDR-229 P3.5a), and answers 409, naming the job, when an end's row is gone or the target is retired by the time it reads them; before, it re-entered a job whose ends it never locked. The body is `{"error": ..., "job_id": ...}`, and nothing is written.
- `POST /v1/chash/rename_collection` takes the registry rows of both names `FOR UPDATE` before it moves rows (RDR-229 P3.5a), so it waits for a writer of either name that is in flight and a writer that arrives later reads the renamed row. When a writer holds a row past the 10 s bound the route answers the typed 503 `rename_busy` with `Retry-After`, as the catalog rename does. No released client calls this route; a client rename goes through the catalog's cascade.
- `POST /v1/catalog/purge-trash` (with `dry_run` false) reads the registry rows of the collections its aged tombstones and their manifest rows reach, `FOR KEY SHARE` in id order, before it deletes (RDR-229 P3.5a), so it waits for a rename or supersede that holds one instead of running beside it. Rows of retired collections are purged as before.
