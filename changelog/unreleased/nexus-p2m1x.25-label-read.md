### Changed

- **A read by label of a retired collection that names no live successor now answers 409 `collection_superseded`.** RDR-229 R7, for the next paired cut with the client after 8.5.6 (which adds the typed read error). A tombstone whose successor was deleted names none. A request that names it by `collection_id` already answered 409; a request that names it by label answered 200 and read the retired collection. Now the label answers the same 409, with the same body: `error` and `reason` `collection_superseded`, `message`, `collection` (the retired label) and `collection_id`, and no `superseded_by` or `successor_collection_id`. It applies to 27 read routes: the vector reads (`/v1/vectors/search`, `query`, `search-per-collection`, `hybrid-search`, `search-metadata-scoped`, `search-topic-scoped`, `search-graph-hop`, `search-aspect-scoped`, `get`, `get-all-metadata`, `get-embeddings`, `store-get`, `store-list`), the taxonomy reads (`topics`, `topics/unreviewed`, `topics/resolve`, `top_topics`, `chunk_grounded`, `audit`, `rebuild/old_state`, `assignments/cross-preview`, `assignments/unassigned`, `centroids/query`, `centroids/by_collection`), the aspect reads (`/v1/aspects/get`, `list_by_collection`) and `/v1/catalog/resolve_span`. A request that lists several labels (`collections`) fails whole when any listed label is such a tombstone. A released client has no typed error for it and shows a generic 409 that it does not retry. A live label, a retired label with a live successor, the counts, `collections/get` and the other catalog reads, and every write route answer as before. The guard reads the registry once per request for all the labels its cache lacks.
