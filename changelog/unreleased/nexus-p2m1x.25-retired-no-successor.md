### Changed

- **A re-embed refusal of a retired collection no longer names a dead label as its successor.** RDR-229 R7. A tombstone whose successor was deleted names none, but its stored `superseded_by` text is its own dead label, and the re-embed plan and start (`/v1/vectors/reembed/plan` and `/jobs`) named that text. Now the successor is found by its id and named by its CURRENT label. A re-embed of a source that is retired with no successor answers 409 "collection X was retired and has no successor; a retired collection is not re-embedded", with no `superseded_by`; a retired target with no successor answers 409 "collection X was retired and has no successor; it cannot be this job's target" and is no longer revived or named. A retired source with a live successor still answers 409 "already superseded by", and its `superseded_by` is now the successor's current label, not the label the tombstone stored. The 409 has no `reason` and no released client reads its `superseded_by`; the CLI shows its `error` text.
- **The two cleanups of a label that has no registry row no longer reach a collection registered meanwhile.** The pdf pipeline cleanup (`deleteForCollection`) and the remap `clearLeg`, for a leg with no registry row, read the registry without a lock. From the collection-id latch (gate 3) they now delete only the rows whose id no live registry row holds, so a collection registered between that read and the delete keeps its rows. Before the latch they still match the label by name.
