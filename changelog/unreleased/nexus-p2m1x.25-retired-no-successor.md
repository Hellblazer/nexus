### Changed

- **A read by label of a retired collection that names no live successor is refused, and a re-embed refusal no longer names a dead label as a successor.** RDR-229 R7. A tombstone whose successor was deleted names none (its `superseded_by_id` is its own id). A request by `collection_id` for it already answered 409 `collection_superseded`; a request by label resolved to the tombstone and read it silently. The vector reads (search, query and its scoped variants, get, store-get, store-list), the topic reads and the aspect reads now answer the same 409 for that label, with the same body (the retired label and id, no successor field). A label that resolves to a live row, and a tombstone with a live successor, read as before; counts, the registry row itself and the catalog reads still show a retired collection. A re-embed start or plan whose source or target is retired with no successor now says "collection X was retired and has no successor" instead of naming the stored label as its successor, and a retired row with a live successor is named by that successor's current label, found by id.
