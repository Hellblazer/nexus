### Changed

- **Engine: a collection rename keeps the collection's id and rewrites one registry row (RDR-229 P3.7, nexus-p2m1x.27).** From gate 3 of the completion check, once the name-key drop move has completed and every P3.5b changeset has applied, `POST /v1/catalog/collections/rename` updates the registry row's label in place: the collection keeps its `collection_id`, and no chunk, manifest, taxonomy, aspect, highlight or telemetry row is rewritten. Only `nx-note://` URIs that classify as notes follow the new label (never `chroma://` residue), queued aspect tasks name the new label, and tombstones that named the old label name the new one. Before gate 3 the rename is the fourteen-table rewrite it was. From gate 3 until the one-row rename can run, a rename answers 409 `rename_refused` with `missing` set to `name_key_drop_move` or `restart`, and `GET /v1/status` carries `rdr229_completion.rename_missing` (`none`, `name_key_drop_move` or `restart`) with the same spelling. While every stamp move is complete and a P3.5b changeset has not applied, `boot_work` lists one restart entry (`rdr229-restart`). Additive; an older client reads the new status field as absent.
