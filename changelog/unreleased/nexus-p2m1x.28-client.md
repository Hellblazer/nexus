### Changed

- **A new knowledge subject is registered by its attributes, and the write goes to the label the engine mints (RDR-229 P3.8, client core).** The first `store_put` (MCP or `nx store put`) to a subject with no collection registers `(knowledge, <subject>, <model>, v1)` with no name; the engine answers the collection's `c<id>` label and the put writes there. No conformant `knowledge__<subject>__<model>__v1` name is rendered for it. A subject that already has a row, an existing conformant collection or a legacy two-segment collection with data keeps writing where it did, and a recovery-bundle restore keeps the name it restores. It needs the engine release that mints labels (0.1.201): an older engine answers the registration 409, and the client says which engine answered and which release it needs.
- **`HttpCatalogClient.register_collection` takes the label as optional and the four attributes as required.** `content_type`, `owner_id`, `embedding_model` and `model_version` are never read out of a name, a blank one is refused before anything is sent, `legacy_grandfathered` is no longer sent, and the call returns the registered row.
