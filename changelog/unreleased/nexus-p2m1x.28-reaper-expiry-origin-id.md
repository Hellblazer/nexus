### Fixed

- **The engine's two quarantine expiries no longer delete a chunk that a manifest row of its own origin still names.** `nexus.reaper_expire_quarantine` and `nexus.reaper_expire_client_quarantine` list rows by the origin label tag and guarded each row by the collection id resolved from that label. After a one-row rename, a quarantine move that committed after the rename's retag left a row tagged with the old label; the label then resolved to no collection (or to a new holder of it), the manifest guard missed the chunk's re-reference under the new name, and the referenced row was deleted. Each expiry now also treats a manifest row of the row's own `origin_collection_id` as naming the chunk, in the count, the select and the delete. Once the gate 3 latch is set, a row whose metadata has no `origin_collection_id` key is left alone (it stays in quarantine) instead of being deleted. A row whose key is the JSON null marker is unchanged. Changeset `vectors-086`, two function definitions, no data change.
