### Fixed

- **A `--corpus` name shaped like a repo owner segment (`1-20`, or `1_20`, which folds to it) is refused wherever it would be turned into a `docs__<corpus>` collection name.** The owner segment of a repo owner tumbler `1.20` is `1-20`, so `docs__1-20__<model>__v1` is that repo's docs collection and a corpus of the same name wrote into it by name. `nx index md` and `nx index pdf` refuse it when no `--collection` is given, `nx dt capture` refuses it for a markdown or html capture, and `nx dt index` refuses it at the first markdown record; a `--collection`, or a PDF going to `knowledge__<corpus>-papers`, never builds the docs name and is not refused. A date-shaped corpus such as `2024-05` is refused too, on purpose: the grammar cannot tell it from an owner segment, and the message says to choose a name with a letter in it. One builder, `nexus.corpus.docs_leaf_fallback_collection_name` (the check is `nexus.owner_segment_guard.require_corpus_name`), makes the docs name from a corpus, and a lint fails if `src/nexus` builds one anywhere else.
