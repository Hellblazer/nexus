### Added

- **The collection registry refuses a second live collection on one tuple (RDR-229 P3.8).** A partial UNIQUE index on `(tenant_id, content_type, owner_id, embedding_model, model_version)`, over rows that are neither superseded nor quarantined, makes `for_tuple` single-valued at a model version. The engine builds it at the first start where the re-own data move (`rdr229-reown-repo-stems-from-curator`) has completed and no live tuple is shared; until then the changeset waits without halting the boot or being recorded, so every start retries it. `nx doctor` names any live tuple held by more than one collection (the "Collection tuples" warning), which is what holds the index back; the row is absent when there is none. A new install takes two starts to get the index: the first registers the move, the second applies it.
