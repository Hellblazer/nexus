### Changed

- The recovery bundle is format 3 (RDR-229 P3.9). `nx catalog export` writes one `collection` record per collection that holds a note (its registry row: `collection_id`, label, `content_type`, `owner_id`, `embedding_model`, `model_version`, `lifecycle_state`), and each note carries its source `collection_id`. `nx catalog import` registers a collection from that row, never from its name, and treats the source `collection_id` as a key local to the bundle: the target mints or keeps its own id and never adopts the source's. A bundle of format 1 or 2 still imports through the name path. This release starts the count of minor releases that keep importing the old formats (RDR-229 Open Item O1); P4.4 reads this entry for the version.
- On import, a label that is live on this install with another `content_type` or `owner_id`, or a label the engine will not register, refuses that collection only: the summary names both sides, counts its skipped notes, and the command exits 1 after printing the whole summary. A row that is not `live` is skipped, counted and named (exit 0), never registered live. A label with no row here is registered under this install's embedding model and kept; the summary names each collection whose model changed.
