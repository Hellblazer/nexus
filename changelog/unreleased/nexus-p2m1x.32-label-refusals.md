### Changed

- **A delete by label refuses a retired label that has a live successor, and a label two collections hold.** A label that a rename or re-embed retired is refused when the collection it names as its successor is live; the message names that successor's label and ID and says the retired row stays as the history (it used to be removed). A retired label with no live successor (an empty tombstone, a kept source whose target is gone, retired or itself superseded) is still deleted, so the `nx collection delete SRC` that `nx collection re-embed --all` prints for a skipped re-entry keeps working. A label held by two live collections is refused and names both IDs, and `--id` deletes one of them. Both are read from the registry listing before anything is sent; a listing that cannot be read, or no catalog client, is always said on stderr and the delete goes on, the engine being the authority. An engine 409 `collection_label_ambiguous` is the same refusal, no longer reported as an unconfirmed delete. `nx collection delete LABEL` for an ordinary live collection is unchanged.
