### Added

- **`nx collection list` shows the collection's id (RDR-229 P3.12).** A new `ID` column, first among the catalog columns, reads the registry's `collection_id`; a row no stamp has given one yet prints `-`. The other columns are unchanged.
- **`nx doctor` gains three collection-identity rows.** "Collection ids" counts this tenant's rows that name a collection and have no id yet, per table whose name/id CHECK is not yet validated, from the same `rdr229_completion_counts` read the RDR-229 completion rows use. It warns while any are left: unstamped rows (including registry tombstones awaiting `superseded_by_id`) clear when the stamp move runs, and orphan rows (a name no registry row carries, write-frozen) point at the RDR-229 VALIDATE and completion rows. It fails only for a registry row with no `collection_id`, naming the labels. The four history tables keep NULL on old rows by design and are named, not counted. "Collection label clash" fails and names both ids when two live registry rows share a label; the primary key keeps that at zero until P4.1. "Live-label index" warns when the engine's unique index on live labels (`catalog-053`) is not built, harmless until P4.1, and names both causes (a lock timeout the next boot retries, or a migration role that no longer owns the registry table). An engine that does not answer, or a status without the field, gives a "not checked" row, never a pass.
- **`GET /v1/status` reports `live_label_index_present`.** One boolean, true when the partial UNIQUE index `idx_catalog_collections_live_label` exists and is valid; absent on an engine that predates it or when the probe could not run. It carries no tenant, collection or label text (nexus-p2m1x.32).
