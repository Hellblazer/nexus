### Fixed

- **`nx index repo` reads the next collection version from the registry row, not from the name the engine returns.** A tuple whose only collection is a legacy slug, or whose row version differs from its name's suffix, used to raise or give the wrong next version; it now resolves from the row's `model_version`. A non-empty malformed value (`v0` included) and a row answering for another content type, owner or model than the one asked for raise. An empty `model_version` (the column defaults to `''` and re-registering does not repair it) falls back to the returned conformant name with a `collection_for_row_model_version_empty` warning; that fallback comes out once the RDR-229 P1.2 census reads no such rows, and a row with an empty version and a name that does not parse raises. The engine keeps its tie-break by name; no wire or schema change (RDR-229 P1.4, nexus-p2m1x.4).
