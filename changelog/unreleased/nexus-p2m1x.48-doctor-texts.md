### Fixed

- **`nx doctor` no longer prints "The engine is restart the engine once: ..., running for 27 h 05 m", and `--check-search` no longer reads an empty quarantine twin as model drift.** The engine's restart notice is an instruction, not work in progress, and the client put every `boot_work` entry after "The engine is" and "running for". The restart notice now reads "The engine needs one restart: it applies the P3.5b changesets that a collection rename waits for (15 of 15 not applied yet), waiting for 27 h 05 m." and says "Nothing is lost: the restart is the step that applies them." in place of the interrupt advice; the standing-condition entry ("The engine has a standing condition: ...") and a data move's class lines (blocked, paused, queued, failed, runs complete) get their own lead-ins, and only entries that run say "running for". `--check-search` took the expected model from the collection's label, which names no content type for the engine-minted `c<id>` labels every new knowledge subject gets since 8.5.6 (so each read as drift against voyage-code-3), and which put a `quarantine-docs__...` or `quarantine-rdr__...` twin on the code model. `model_drift` is now a row-consistency check: the model the collection's own catalog row `content_type` calls for (`corpus.canonical_embedding_model`) against the `embedding_model` the same row registers. It no longer compares the label's model token, on purpose: once the one-row rename is live (8.5.6 and later, after the engine's restart), a rename changes only the label (RDR-229), so a label's model token is not authority. A collection whose row has no content type is judged by its label as before. A `c<id>` knowledge collection registered with the code model, and a live docs collection registered with the wrong model, are still `model_drift`. The check lists the tenant once. A blocked, paused or failed data move no longer prints "Interrupting this command does not stop it" or "Commands that need the engine wait until it finishes" (nothing runs for it), and a data move whose runs are complete says "listed for", not "running for".
