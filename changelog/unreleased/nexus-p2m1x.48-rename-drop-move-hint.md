### Fixed

- **`nx collection rename` says what the engine is waiting for while its name-key drop move runs.** From the latch of gate 3 (which the restart after an upgrade brings; before it a rename is the name path and is not refused) the engine refuses a rename (409 `rename_refused`, `missing: name_key_drop_move`) for as long as the move runs, about 10 s on an empty store and longer behind an index build. The client printed the generic "Fix the error and retry". It now says to run the rename again in a minute or two, and to run `nx doctor` and report the "RDR-229 collection rename" row if it still refuses after several minutes, since a stalled move gives the same refusal. `missing: restart` is no longer described as the fresh-install window: it appears only when a listed changeset fails to apply on its own (nexus-p2m1x.48).
