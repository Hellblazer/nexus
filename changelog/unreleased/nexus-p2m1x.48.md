### Fixed

- **`nx doctor` no longer warns "Collection tuple index ... waits for a reason nothing here names" on a fresh install's first boot.** The engine builds the live-tuple unique index (changeset `collections-001-2`) at the first boot after the re-own move completes, and on an empty store that move completes seconds after boot 1, so the index is absent until one restart. In that window the engine has either published its `rdr229-restart` notice (the restart that applies RDR-229's CONTINUE changesets builds the index too) or still has other RDR-229 moves open, and the row now treats both as the explanation. The restart instruction stays with the existing "RDR-229 collection rename" row, so there is one instruction, not two. Once those moves have finished and no restart notice is posted (a fresh install whose changesets all applied at boot 1), the row is still a warning, but now says the engine builds the index at its next start and names the restart command (`nx daemon service stop, then nx daemon service start`); the boot-log diagnosis stays as a second suggestion for an index still absent after a restart.
