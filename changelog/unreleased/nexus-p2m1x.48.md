### Fixed

- **`nx doctor` no longer warns "Collection tuple index ... waits for a reason nothing here names" on a fresh install's first boot.** The engine builds the live-tuple unique index (changeset `collections-001-2`) at the first boot after the re-own move completes, and on an empty store that move completes seconds after boot 1, so the index is absent until one restart. In that window the engine has either published its `rdr229-restart` notice (the restart that applies RDR-229's CONTINUE changesets builds the index too) or still has other RDR-229 moves open, and the row now treats both as the explanation. The restart instruction stays with the existing "RDR-229 collection rename" row, so there is one instruction, not two. The row is unchanged for the case it was written for: the index absent, no shared tuple, and no re-own entry, restart notice or RDR-229 move listed.
