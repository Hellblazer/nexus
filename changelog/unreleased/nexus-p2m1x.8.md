### Fixed

- **`nx index repo` takes each collection's embedding model from its catalog row, not from the name (RDR-229 P2.3).** The engine embeds by the row, and a rename keeps the source row's model under the new name, so a conformant name's model token and its row can disagree. The repo run used to stamp chunks and judge the unchanged-content skip by the token, and to register the row with it, which the engine's profile refuses when the row holds another model (`EmbeddingProfileMismatchError`). It now reads the row, with the three outcomes `nx index md` / `pdf` have: the row's model; no row or no model, the name's token; a row read that failed, the name's model flagged as a guess, so a listing outage re-indexes nothing whose content has not changed. A legacy name keeps the local embedder's model in local mode unless a row answers. The pre-index registration registers the model the run resolved; when the row read failed and the row's model differs from the name's, the engine can refuse that registration and the run stops loudly rather than skip it. A collection that is registered but holds no chunk yet is not in the listing the row comes from and still follows its name. A collection the run has no files for reads no row.
