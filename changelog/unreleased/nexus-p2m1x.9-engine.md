### Added

- **`POST /v1/taxonomy/assignments/prune_projection` takes an optional `match`, and `GET /version` reports `taxonomy_prune_exact_supported`.** `match: "exact"` deletes projection rows whose source collection IS the named one; `"prefix"`, and an absent or null field, keep the old behaviour (every source collection whose name starts with the string). Any other value is a 400. Pruning `..__v1` by prefix also reached `..__v10`, and `docs__art` also reached `docs__art-x`, deleting the longer name's rows below the shorter name's threshold; with a threshold per collection that is wrong, so the exact mode is the safe form. The reply is `{"removed": N, "match": "prefix"|"exact"}`, naming the mode applied. A client reads the flag before it sends `match`, because an older engine ignores the field and prunes by prefix, and confirms the echo, which an older engine does not send. Engine-service 0.1.200 (nexus-p2m1x.9, RDR-229 P2.4).
