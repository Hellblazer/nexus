### Changed

- **`nx taxonomy project`, `--backfill`, `--prune-below-threshold` and `nx taxonomy audit` read a collection's default projection threshold from its catalog row (RDR-229 P2.4).** A collection's `content_type` picks knowledge 0.50, docs/rdr 0.55, code and anything else 0.70, even when its name's prefix says otherwise; the name's prefix answers only for a collection with no catalog row, or when the row listing cannot be read (logged once per outage, and project, backfill and audit carry on with the name's value). An explicit `--threshold` is unchanged.
- **`--prune-below-threshold` without a source prunes each collection at its own threshold, by full collection name, instead of once per `code__`/`knowledge__`/`docs__`/`rdr__` prefix, and it never deletes on a guess.** A collection whose catalog row cannot be read is refused with a printed line and an `N refused` summary (pass `--threshold` to prune it anyway); a sweep that refuses every collection exits non-zero. The sweep covers the live catalog listing plus the collections that hold topics, so two things change: a collection outside the four prefixes (a legacy bare name) is now swept, and a non-live collection (quarantined, or a superseded rename tombstone) that holds no topics is no longer swept. The single-source form follows the same rules. The engine matches a prune by name prefix, so a collection whose name prefixes a lower-threshold collection (`...__v1` and `...__v10`) is pruned only down to that lower threshold, with a printed line and an `N skipped` summary; its own rows between the two thresholds remain until an engine with the exact-name prune mode is in use.
