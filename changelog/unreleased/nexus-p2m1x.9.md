### Changed

- **`nx taxonomy project`, `--backfill`, `--prune-below-threshold` and `nx taxonomy audit` read a collection's default projection threshold from its catalog row (RDR-229 P2.4).** A collection's `content_type` picks knowledge 0.50, docs/rdr 0.55, code and anything else 0.70, even when its name's prefix says otherwise; the name's prefix answers only for a collection with no catalog row, or when the row listing cannot be read (logged once per outage, and project, backfill and audit carry on with the name's value). An explicit `--threshold` is unchanged.
- **`--prune-below-threshold` without a source prunes each collection at its own threshold, by full collection name, instead of once per `code__`/`knowledge__`/`docs__`/`rdr__` prefix, and it never deletes on a guess.** A collection whose catalog row cannot be read is refused with a printed line and an `N refused` summary (pass `--threshold` to prune it anyway); a sweep that refuses every collection exits non-zero. The sweep covers the live catalog listing plus the collections that hold topics, so two things change: a collection outside the four prefixes (a legacy bare name) is now swept, and a non-live collection (quarantined, or a superseded rename tombstone) that holds no topics is no longer swept. The sweep also covers every collection named by the projection rows themselves (`get_projection_counts_by_collection`), so a retired collection with projection rows but no topics is seen when a shorter name's prefix match would reach it. A collection is refused too when a collection whose name extends it has an unreadable row, and a sweep that refused anything exits non-zero, because the recovery is incomplete. The single-source form follows the same rules. The engine matches a prune by name prefix, so a collection whose name prefixes a lower-threshold collection (`...__v1` and `...__v10`) is pruned only down to that lower threshold, with a printed line and an `N skipped` summary; its own rows between the two thresholds remain. Against an engine whose `GET /version` carries `taxonomy_prune_exact_supported: true`, the prune sends `match: "exact"` instead: each collection is pruned at its own threshold, with no guard, no floor and no `N skipped` line. The flag is read once per command through the shared catalog client's cached `/version` probe; an absent key, `false` or an unreadable `/version` keeps the guard. The flag and the prune can reach different engines (a rollback inside the flag's cache window, two instances), so the prune verifies it first: before any real prune the command sends one `match: "exact"` prune for a name no collection has (the fixed prefix `nexus-exact-probe-` and a random 128-bit suffix, so even a prefix match reaches no rows; the guarantee is the name, not the threshold), and requires the reply to echo `match: "exact"`. An engine that does not (missing or `prefix` echo, or a failed call) gets "the engine did not confirm exact matching; using the guarded prune" and the whole sweep runs the guarded plan. The real replies are checked too: if one stops echoing `exact` mid-sweep, the sweep ends at once with a printed line and a non-zero exit, and no further collection is pruned.
