### Added

- **`nx memory curate --cold` lists the stores with no write and no use in the window** (nexus-qo7ie.19, RDR-238 Phase 3 Step 3). Five kinds, each row giving the store, its last write where it has writes, its last use, its size and its owner: memory files, T2 namespaces of the repository, MCP tools of the `nexus` and `nexus-catalog` servers (the registry diffed with the calls, so a tool never called is listed, with its definition size in tokens), CLI verbs (the click tree diffed with the `nx` commands found in Bash text) and tracked nested `CLAUDE.md` files never loaded by a `nested_memory` or `instructions` attachment. Tools and verbs the plugin's hooks run are printed as invoked by a hook, not as cold; a T2 project counts as used when a row's `last_accessed` is in the window; each tools and verbs section prints what a transcript count cannot see. Per Sam's K6 decision, always-loaded items (the `MEMORY.md` index as a whole, the root `CLAUDE.md` and `AGENTS.md`, every `instructions` attachment file, tool definitions as injected text) are excluded with no "never used" claim, and the report says so. Counts come from RDR-240's `memory`, `tools` and `loads` queries over the repository's own sessions, through the page loop `--files` now shares. Without the runtime, on a failed query, with no session in the window or for a memory directory the query cannot recognize, the affected kinds print `not available` and the reason, never a cold list (a tools or memory query that returns no rows for sessions that did start included), and the command exits 0. Tuple subspaces wait for RDR-239's dictionary view.
