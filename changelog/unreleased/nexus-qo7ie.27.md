### Fixed

- **`nx memory curate` review gate B findings** (nexus-qo7ie.27, RDR-238 Phase 3). `--files` no longer loses its non-transcript rows when the runtime fails outside its known errors: the read-count rows say `not available: <type>: <message>` and the rest print. A `--cold` run stores `curation-report-<date>-files-t2-agents-cold`, so a later default run does not overwrite it. A deleted working directory or a failing repository identity exits 0 with a `not available` line. The session count (`--files` and `--cold`) reads each main transcript's first record through the transcripts verb's own `first_start` and `repo_main_transcripts` (one rule with `sessions()`, pinned by a parity test on an adversarial fixture), bounded to 8 MiB a file; transcripts whose first stamp lies past it are counted apart and the row says how many were not counted. It stays at about 0.5 s on 255 main sessions. `--cold`'s T2 row no longer counts an all-project `memory_search` as a use of every namespace (a project it hit is judged by `last_accessed`) and names the SessionStart prefix scan's own tracked reads in its limits line; the nested `CLAUDE.md` row says `never loaded (on demand)`; `--files` says files used in a cut record may be listed as unread. The SessionStart curation check skips the oversize `stat` and runs under a 2 s deadline: past it the guidance is still emitted and the curation line is skipped. Release Step 12a says to run the report with `run_in_background`.
