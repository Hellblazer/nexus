### Added

- **`nx run` and the MCP tool `procedure_run` run a library procedure** (RDR-240 Technical Design 2 and 3, nexus-qo7ie.31). Both call one function, `nexus.lua_runtime.runner.run_procedure(name, args)`, which calls RDR-242's `run_script` and passes its result and its errors through unchanged; until the runtime that provides `run_script` ships in the same build, a call answers `unavailable: ...` and runs nothing. `nx run NAME [--args-file F | -]` prints the JSON result; an error prints `<kind>: <detail>` and exits 1; `nx run --list` lists the library's procedures with their header summary. `procedure_run(name, args)` returns the result as JSON text, or the error as `<kind>: <detail>` with `isError` set; its description lists the procedures that ship with `nx`. The library has two roots (`nexus.lua_runtime.library`): the packaged `nexus/procedures/`, and `<repo>/.nexus/procedures/`. The repo root is OFF unless the environment variable `NX_PROCEDURES_REPO_ROOT` is exactly `1` (RDR-242 Open Question S5, answered on its safe side); a name found only there is refused with the reason `repo_root_off`. A name matches `[a-z][a-z0-9_]{0,63}` and is not a Windows device name (`con`, `nul`, `com1`, ...), the file must be a directory entry named exactly `<name>.lua`, its resolved path must lie inside its resolved root, a repo root that is a link out of the checkout is refused, a repo procedure named like a shipped one is refused, and a file that cannot be read is refused as `unreadable`. A refusal of the name or the library prints as `name: <reason>: <detail>`, the same kind `run_script` raises for the name rule. The conexus permission hook auto-approves `procedure_run`, which runs reviewed procedures in a sandbox with read-only verbs. The MCP server registers 47 tools, 45 for agents. Two lints pin the shape: the front doors call the runner and nothing else, and every shipped procedure parses, grants only version 1 verbs and passes the static check; a wheel test pins the procedures and the vocabulary table as package data.
