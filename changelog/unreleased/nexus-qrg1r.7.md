### Changed

- **A `dchash:` link span that does not parse is refused before any link write goes out.** The catalog client's `link`, `link_if_absent` (before its existence read) and batched `links_upsert_many` (every edge on every page is checked before the first page is sent), and the link dry run, raise a `ValueError` naming the span; `nx catalog link` shows it as an error and the MCP `link` tool returns it as an error. A span form other than `dchash:` is not checked. `nx catalog import` does not abort on such a link: it skips it, lists it under `links refused (malformed dchash span)` with its endpoints and span, and imports the rest; the exit status still counts documents only. The `nx catalog link` help, the MCP `link` tool's field descriptions and `docs/cli-reference.md` now name the `dchash:<hash>:<start>-<end>` form, and the false sentence that content-hash spans survive re-indexing is replaced: a `dchash` span survives re-chunking of unchanged text and a `chash` span does not (nexus-qrg1r.7, RDR-171).
