### Changed

- **Upgrading from 8.5.7: telemetry stops unless you turn it on.** The routing events the guards write and the agent-dispatch record are no longer sent to your engine. Set `"telemetry": true` in `~/.config/nexus/conexus.json` to send them again. They only ever went to your own engine, and a repository's settings cannot turn this on or point it at another host.
- **Two new settings files.** `.nexus/project.json`, tracked in a repository, can tighten the plugin or add text and cannot loosen a rule or turn telemetry on. `~/.config/nexus/conexus.json`, in your account home, holds your own choices. The keys, how two values combine and what a bad value does are in `docs/settings.md`; `nx settings show` prints what applies where you are and `nx settings check` lists the problems. A file that cannot be read gives `subagent_git: strict`, and a problem in one is reported on your first prompt of a session.
- **The subagent git guard stays the short deny list for everyone.** The Git row 8.5.7 added to every user's dispatch instructions now appears only where `"subagent_git": "strict"` runs the full guard, in a project's file or yours. The file that made 8.5.7 treat one maintainer's machine differently has no effect any more; to keep the full guard on a machine, write `conexus.json` with `"subagent_git": "strict"` (and `"telemetry": true` to keep telemetry).
- **The texts that stay no longer carry internal ids.** Every user keeps the search-scope row, the four implementer brief questions, the dispatch sentence and, for every agent type, the T1 reminder when an agent stops with nothing written (`"t1_nudge": false` turns it off). A project adds its own questions, preflight command, CI-wait command and credential-helper text in `.nexus/project.json`.
- **Auto-approve stays for the nexus tools, and your own `ask` rule now prompts.** The approver still allows every nexus and nexus-catalog tool without a prompt, the destructive ones included. It now answers only before the tool runs, so a `permissions.ask` rule in your Claude Code settings decides where 8.5.7's answer overrode it; a `deny` rule held a tool denied before as well.
- **The compaction checkpoint counts work not yet landed against your default branch.** It read `origin/develop` in 8.5.7. A project names its own branch with `integration_branch`; without one the order is `origin/HEAD`, then `origin/main`, then `origin/master`.
- **The strict-guard markers of earlier releases and the maintainer flag are not read.** `.nexus/dev-process.json`, `scripts/agent-worktree-preflight.sh` and `~/.config/nexus/maintainer-profile` change nothing; `nx settings show` lists a leftover `maintainer-profile` as having no effect. A project that relied on either marker writes `.nexus/project.json` with `"subagent_git": "strict"`.
