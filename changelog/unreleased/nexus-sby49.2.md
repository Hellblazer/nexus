### Changed

- **A subagent may run git commit, add, push, rebase and merge in your own repositories.** The plugin's subagent git guard used to deny every git write for everyone. Its full rule now runs only for the nexus maintainer (a `~/.config/nexus/maintainer-profile` flag file under the OS account's home, or a nexus checkout); anyone else gets a short deny list: force pushes, deleting a branch with `-D`, reflog and gc pruning, `filter-branch`, hook-path and global config writes, and discarding uncommitted work (`checkout -- <path>`, `reset --hard`, `restore`, `stash`, `clean`) when the checkout has something to lose.
- **The agents run `bd` only where a `.beads/` directory exists, and skip their nexus-tool steps when those tools are absent.** An agent's brief can now tell it to commit (the stacked-review sentence is unchanged), and `bd` is optional in the plugin README.
- **`NX_REMOTE_TEST_HOSTS` is no longer read.** The ssh hosts the maintainer's guard exempts come from `~/.config/nexus/remote-test-hosts` (one ssh host alias per line, or comma-separated; `#` starts a comment), because a project's settings `env` reaches command hooks and an environment variable could be set by any repository.
