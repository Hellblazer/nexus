### Added

- **Project settings and user settings, read by the plugin's hooks, in place of "who is the user".** A project's tracked `.nexus/project.json` (tighten-only) and the user's `~/.config/nexus/conexus.json` switch the plugin's optional behaviour: `subagent_git` (`strict` runs the full subagent git guard; the default stays the short deny list of 8.5.7), `preflight`, `ci_wait`, `credential_helper`, `brief_questions` and `advice_block` for a project, and `subagent_git`, `telemetry`, `t1_nudge` and `advice_block` for a user. A project file can add text or tighten a rule and never loosen one or turn telemetry on; one that cannot be read gives the strict reading. The 8.5.7 marker (`scripts/agent-worktree-preflight.sh`) and the Phase 2 file `.nexus/dev-process.json` are not read (nexus-sby49.20). `docs/agents/plugin-audiences.md` describes the settings. (nexus-sby49.3)
- **`conexus/hooks/audience.yaml`, its lint and a behaviour leg.** Every hook registration, module and injected constant declares whether it is for every user, behind a named setting, or removed; `tests/test_plugin_audience_lint.py` fails on one that does not, and `tests/e2e/plugin-out-of-repo-gate.sh` now runs the plugin's hooks in a plain repository, a repository whose tracked settings turn every key on and an account whose user settings do, with and without `nx`. (nexus-sby49.3)
