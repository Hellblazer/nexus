### Changed

- **The subagent git guard's full rule is a setting; the short deny list stays the default.** As in 8.5.7, a subagent may commit, add, push, rebase and merge in your repositories and the short list of irrecoverable forms is denied. A project turns the full rule on with `"subagent_git": "strict"` in its tracked `.nexus/project.json`, or a user in `~/.config/nexus/conexus.json`, in any repository. The full rule's deny text no longer cites internal ids. (nexus-sby49.4)
- **Advice rows warn; a row blocks only if you list it.** The destructive-action advice for `pkill`, bulk branch deletes, `git stash`, whole-disk scans and the like only advises. A project's `advice_block` or the user's lists the row ids that block instead; the telling of nexus's own incidents is gone from the advice. (nexus-sby49.4)
- **The Stop guard and the credential guard take their project's words from its settings.** The Stop guard's block reads the same for everyone, in neutral words, and names a CI-wait command only when the project's `ci_wait` sets one; the guard's sentence classifier keeps role words and no personal or peer names, and it no longer creates `~/.config/nexus/logs/hook.log` where that directory is absent. The credential guard's deny always refuses; it adds the project's `credential_helper` text when there is one and otherwise says to ask your operator. (nexus-sby49.4)
- **The destructive and other-party nexus tools are auto-approved for every user.** `memory_delete`, `answer_plan_delete` (and its old name `plan_delete`), `memory_consolidate`, `nx_tidy`, `tuple_in` and `mailbox_send` join the tools the approval hook already allows; add an `ask` rule in your own Claude Code settings to be prompted. (nexus-sby49.4)
- **The compaction text names the threads board and `bd list` only where they exist.** The board only when the checkpoint found an entry (with no checkpoint to read it is not named), `bd list` only in a project with a `.beads/` directory; the count of work not yet landed is measured against the repository's default branch, not `origin/develop`. The preflight failure marker names `bd` only in a project with beads. The mailbox's header carries no internal id, and its ask-answer frame says "the user" except in its opening phrase and its `sam-words` delimiters, which the drain tests and the maintainer's instructions quote. (nexus-sby49.4)
- **An unattended `nx upgrade` no longer writes the beads PRIME file.** The detached upgrade the lockstep hook starts after a version change skips that step; `nx init` and an interactive `nx upgrade` still write it. (nexus-sby49.4)
