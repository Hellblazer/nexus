### Changed

- **The plugin's hooks stop saying nexus-only things to other users.** The Stop guard's block reads the same way for everyone, in neutral words; `nx ci wait`, develop and main and the CI board are named only in a nexus checkout, and the guard no longer creates `~/.config/nexus/logs/hook.log` where that directory is absent. The credential guard's deny tells other users to ask their operator for an equivalent and names the nexus wrapper only in a nexus checkout. The destructive-action advice for `pkill` and for deleting branches no longer tells nexus's own incidents, and a deny mode set on any row applies only to the maintainer. The compaction text names the threads board and `bd list` only where the project has them (a `.beads/` directory; a board entry in the checkpoint). The preflight failure marker names `bd` only in a project with beads. (nexus-sby49.4)
- **Users are prompted for the destructive and other-party nexus tools.** `memory_delete`, `plan_delete`, `memory_consolidate`, `nx_tidy`, `tuple_in` and `mailbox_send` are auto-approved only on an account that carries the maintainer flag; every other allowed tool is unchanged. (nexus-sby49.4)
- **An unattended `nx upgrade` no longer writes the beads PRIME file.** The detached upgrade the lockstep hook starts after a version change skips that step; `nx init` and an interactive `nx upgrade` still write it. (nexus-sby49.4)
