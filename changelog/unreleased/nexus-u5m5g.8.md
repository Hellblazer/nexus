### Changed

- **`nx index repo` links documents through the engine, and the index path lists no type tenant-wide** (RDR-193 Step 7, nexus-u5m5g.8). The file-path linkers (RDR and prose) keep their regex scan of each new file but no longer list the repository's code documents to match a path against: each path goes to the engine as a `{owner, file_path}` edge in one `links_upsert_many` call (paged at 1000 edges), and the engine resolves it inside the named repository by the file's identity, or reports it unresolved. The RDR-dependency linker reads two scoped lists (the current owner's `rdr` and `prose` rows, and the rows under the repository's `docs/rdr/`, which finds the RDRs registered under a stale owner) and sends its edges in one call. The PDF linker is one `links_same_content` call, and the same-as maintenance of a run's changed documents is `links_same_content(changed, prune=true)`, so the engine retracts the stale links and re-joins the groups. The hook hands the generators its own rows (each new document's path and content type), so they make no catalog read to learn their inputs; a batch with no RDR file reads nothing. `nx rdr set-status` resolves RDRs through the same two scoped reads.
- **Declared behaviour change: a path resolves to the file of the named repository.** An RDR in one repository that names a path existing only in another repository no longer gets an `implements` link to it (the old client picked whichever listed document for the path came last, so the link could go to the other repository's file). A path matches a document of any content type at that path, where the old client matched only `code` documents; an `implements` link can now point at a markdown document a prose file names.
- **`nx catalog generate-links`** names, for each path edge, the owner of the repository whose root holds the source document, not the source's own owner, so the roughly 150 RDRs registered under a stale owner link into the repository that holds them. Its `--dry-run` counts path edges before the engine drops unresolved paths and existing links (an upper bound) and does not preview the same-as links, which the engine computes.
- New client calls: `HttpCatalogClient.links_upsert_many`, `links_same_content` and `list_scoped`. Needs an engine that serves `/v1/catalog/links/upsert_many`, `/links/same_content` and the combined `GET /list` filter (engine-service-v0.1.185).
