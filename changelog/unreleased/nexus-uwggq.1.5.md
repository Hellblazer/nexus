### Changed

- **`nx doctor --check-references` reads its candidates from the engine instead of walking the catalog (RDR-241 Phase 2).** It asks the engine's `GET /v1/catalog/docs/by-scheme` once per scheme a reader can stat (`obsidian`, `x-devonthink-item`, `nx-scratch`, `nx-note`, `https`), paging to the exact count, where it used to list every catalog document. A registered scheme written in capitals (`HTTPS://`) is still read as `https`. Documents whose scheme no reader can stat (a leftover `chroma://` row, a Windows drive path read as scheme `c`) are no longer listed: they could only ever report `unknown`, and `nx catalog backfill-source-uri` rewrites the `chroma://` ones. A row whose source URI Python's `urlparse` rejects (an invalid bracketed host) is reported as not stattable instead of aborting the check. On an engine that does not advertise `catalog_docs_by_scheme_supported` (every engine before the one that ships the route, and the cloud until its edge passes the flag) the check prints `[ ] Reference staleness: not checked` and exits 3, "could not check", as `nx catalog doctor --sensitive-with-aspects` does; nothing walks the catalog in its place. A `/version` probe that fails is an unreadable catalog, exit 1, as before.
