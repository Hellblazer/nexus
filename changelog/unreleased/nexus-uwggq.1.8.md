### Changed

- **`nx doctor` and `nx catalog doctor` report the sensitive-document rows as "not checked", with the cause, when the engine's sensitive list is unavailable or capped, instead of scanning the catalog.** The `sensitive_in_aspect_eligible`, `sensitive_with_aspects` and `sensitive_in_external_embedder` rows read the engine's bounded `GET /v1/catalog/sensitive` list once. Engine-service 0.1.188 adds that list. When it does not answer (the engine lacks it, times out, fails or sends an unreadable body) or the tenant holds more than 10,000 sensitive documents, each row reads "not checked", names the cause and says what to do. A "not checked" row never fails `nx doctor`, so on a tenant where the list is unavailable or capped, a leak the old walk caught with exit 1 now gives exit 0 there. The dedicated `nx catalog doctor --sensitive-with-aspects` now exits 3, "could not check", when its row reads "not checked" (it exited 0 before); 1 is still a fail and a fail wins over 3; 0 means the row did not fail and was not left unchecked. Over 10,000 sensitive documents the dedicated gate exits 3 until the list can be paged (RDR-241 Phase 2). When the list answers, the rows read as before (nexus-uwggq.1.8, RDR-241).
