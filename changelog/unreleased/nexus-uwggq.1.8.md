### Changed

- **`nx doctor` and `nx catalog doctor` report the sensitive-document rows as "not checked", with the cause, when the engine's sensitive list is unavailable or capped, instead of scanning the catalog.** The `sensitive_in_aspect_eligible`, `sensitive_with_aspects` and `sensitive_in_external_embedder` rows read the engine's bounded `GET /sensitive` list once. Engine-service 0.1.188 adds that list. When it does not answer (the engine lacks it, times out, fails or sends an unreadable body) or the tenant holds more than 10,000 sensitive documents, each row reads "not checked", names the cause and says what to do. A "not checked" row does not fail `nx doctor`, whose exit code is unchanged. The dedicated `nx catalog doctor --sensitive-with-aspects` now exits 3, "could not check", when its row reads "not checked" (it exited 0 before); 0 is still a pass, 1 a fail, and a fail wins over 3. The previous walk found a leaked-before-flagged document on these tenants and failed with exit 1; now they read "not checked" until the list answers. When the list answers, the rows read as before (nexus-uwggq.1.8, RDR-241).
