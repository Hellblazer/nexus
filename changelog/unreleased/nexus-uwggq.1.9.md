### Fixed

- **A blank or whitespace catalog filter is refused instead of widening the call to the whole catalog.** The engine reads a blank filter as "not given", so a blank value in a lookup returned (or, for the bulk delete, acted on) rows from every collection and owner. Whitespace-only values are now refused on every scoped call, before any request goes out. An empty string `""` is refused where the filter names the scope (path, owner, corpus, source URI, collection, and the content type of a by-type listing, the unlink pair and link type); on an optional filter (link filters, collection listing, gc-audit, coverage, the content-type filter of a search or document listing) `""` still means "not given".
  - `nx catalog link-bulk-delete` and the `catalog_link_bulk` tool: a whitespace filter used to be dropped, and with no other filter it deleted every link in the tenant. It is now refused.
  - Link filters (`links`, `link_query`), collection listing, gc-audit and coverage refuse a whitespace-only filter the same way. A link-type list entry made only of commas and spaces (`","`) is refused too, because the engine read it as no filter and returned every link.
  - **Behaviour change:** `nx catalog unlink` now refuses to run without `--type`, and the `catalog_unlink` tool refuses a blank link type. Previously a missing or blank type removed nothing silently (or, from the Python client, reached the bulk delete), although the docs said it removed every type. There is no remove-all-types mode, so name the type.
  - A subtree scope (the `subtree` of the MCP `query` and `search_metadata_scoped` tools, `descendants`) must be digits and dots such as `1.2`; `%` used to widen it to the whole catalog and `_` to sibling subtrees.
  - A recovery bundle link with a blank endpoint URI now lands in `unresolvable_links` instead of aborting the import, and a whitespace source URI no longer reads as sensitive in an import check.
  - `nx` commands answer with a usage error (exit 2), for example `Error: by_corpus: corpus is blank; a blank value is read as absent and widens the read to the whole catalog` or `Error: unlink: link_type is blank; name the link type to remove (there is no remove-all-types mode)`. MCP tools return the same text as an error result. `nx enrich` with no collection still resolves a path across all collections, through an explicit path lookup.
