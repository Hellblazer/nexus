### Changed

- **`nx catalog list --meta` and `--sensitive` ask the engine instead of reading every document (RDR-241 Phase 2, nexus-uwggq.2.14).** One request to `GET /v1/catalog/docs/by-meta` returns the requested page in tumbler order with the exact count, so the `Next page: --offset N` line comes from the route's count. A `-n` above the route's 1000-row bound is read as several pages. `--meta` with `--sensitive` sends `sensitive=true` on the same request, so it works past 10,000 sensitive documents. `--sensitive` without `--meta` keeps reading the engine's sensitive list where that list can answer; where it cannot (`--type`, or a page past its first 10,000 on a capped tenant) and the engine has the metadata route, the route answers the page through its `sensitive` clause instead of the command refusing. On an engine without the route those cases keep today's refusal, which now also says the route is missing. The client checks every clause it sent again (the meta pairs, `sensitive`, `--type`), so an engine fault cannot widen the page, and an answer whose rows cannot be read is reported as the route's malformed answer, not as `--meta` usage. `--meta` needs an engine with the metadata route (named in the error, with the release that carries it): on an older engine it exits non-zero naming the route, and when the engine times out it says so. It never falls back to a scan. A `-n` below 1, a negative `--offset` and an empty `--meta` value are usage errors with `--meta`.
