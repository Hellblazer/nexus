### Added

- **Engine: `GET /v1/catalog/docs/by-meta` reads documents by their own metadata (RDR-241 Phase 2).** `?content_type=&meta.<key>=<value>&meta_min.<key>=<n>&meta_default.<key>=<text>&limit=&offset=` answers `{count, limit, offset, documents}`: the live documents that satisfy every clause, in the engine's text order of `tumbler` (the database's collation of a text column, so `5.1.12` sorts before `5.1.2`), a page of at most `limit` (1 to 1,000, default 1,000) at `offset`, with `count` the exact number of matches whatever the page. At least one `meta.`, `meta_min.` or `sensitive=true` parameter is required (a 400 otherwise), so the route is never an unfiltered listing (`sensitive=true`, the only value of that parameter, is a clause of its own: alone, or with `content_type`, it pages every live sensitive document with an exact count, past the 10,000 cap of `/v1/catalog/sensitive`); a `meta_min` bound may be any integer up to 131,072 characters (PostgreSQL numeric's limit); a NUL byte or a malformed percent escape in a parameter is a 400; a `meta_min` that is not an integer, an empty key, a `meta_default` with no `meta` beside it, and an unknown parameter are each a 400. The rules are those of `catalog/meta_filter.py`: a value compares as text (a JSON boolean as `true` or `false`); an absent key or JSON null matches nothing unless the request sends `meta_default.<key>`, then absent, null and `""` read as the default; `meta_min` matches an integer text (`^-?[0-9]+$`) at or above the bound and nothing else, so a malformed value never fails the read. A read that outlasts its statement bound answers 503 with `reason: statement_timeout`. `GET /version` gains `catalog_docs_by_meta_supported: true`. No client calls it yet.
