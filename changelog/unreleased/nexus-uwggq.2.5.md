### Added

- **Engine: `GET /v1/catalog/sensitive/locators?limit=N` lists the files operator dispatch must deny (RDR-241 Phase 2).** It answers the tenant's live sensitive documents and the live documents whose `alias_of` names a live sensitive one (a merged duplicate holds the same content in its own file), as `{count, limit, capped, documents:[{tumbler, source_uri, file_path, alias_of, physical_collection, sensitive}]}` in the engine's text order of `tumbler` (the database's collation of a text column, so `5.1.12` sorts before `5.1.2`), the envelope of `/v1/catalog/sensitive`. A document that is both is listed once; empty strings come back as `""`; `sensitive` is the row's own flag (an alias row reads false unless it is itself flagged). A NUL byte or a malformed percent escape in a parameter is a 400. `limit` is 1 to 10,000 (default 1,000), anything else a 400; `capped` is true when `count` exceeds `limit`. A read that outlasts its statement bound answers 503 with `reason: statement_timeout`. `GET /version` gains `catalog_sensitive_locators_supported: true`. No client calls it yet.
