### Changed

- **The Windows gate driver can build and resume one running checkpoint taken after the standard user's first sign-in** (`tests/e2e/windows-guest/run-gate.sh --build-signed-in NAME` / `--signed-in NAME`, both with `--standard-user`), so a standard-user gate run skips the roughly 300 MiB first sign-in. Sam's exception of 2026-11-13 is enforced in code: one child checkpoint `stduser-signed-in-<8 digits>` of `clean-baseline-2026-10-06` on `nx-clean-win11`, a second build refused until Sam deletes the first by hand, no script removes, renames or replaces a checkpoint, and no script stores the account secret (the checkpoint's memory image holds the signed-in session). A `--signed-in` run does not exercise the first sign-in or the boot after a restore, says so in its output, and must not be cited as a run from the baseline checkpoint (nexus-y3y8d).
