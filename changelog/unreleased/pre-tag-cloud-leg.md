### Added

- **The pre-tag cloud leg: the release candidate through the real public edge, against a dedicated cloud test tenant, compared with a local engine** (`tests/e2e/cloud-leg.sh`; Sam, 2026-11-19, after 8.5.0 shipped two faults only cloud mode showed: the CDN stripped `X-Nexus-Identity-Token`, so identity-line board writes answered 403, and the laptop's data credential could not create seats). It installs the candidate wheel into a scratch HOME with `uv tool install`, then runs one step list twice, once on a local engine and once on the `release-test` tenant: an identity-line T2 write and read-back, seat creation and show, an identity bind, a mailbox send, claim and ack, T1 put and get, a T3 store and search round trip, and one client call for each route of the wire ledger's entries (`## Unshipped`, or `--release v<X.Y.Z>` for the release's `## Shipped` ones; an unmapped route or zero entries fails the run unless `--accept-skip` or `--no-ledger-entries-ok` says why). Every HTTP exchange is recorded at the client boundary (method, route and status; never a header, query or body), and a step FAILS on any 4xx or 5xx the cloud run returns that the local run does not, on a route the client never called, or on a tap that saw nothing. The run fails when fewer core steps passed than the fixed core holds, and a both-slots refusal fails a core step. `--expect-red <step>@<status>:<reason>` reports a step the cut itself fixes as EXPECTED-RED only when the cloud returned exactly the pinned status (any other failure on it stays red, and a pass on it fails the run). The report prints the ledger entries driven, the window id and the run id. It refuses, before any sandbox exists, without an announced window (a 0600 marker file `~/.config/nexus-cloud-windows/<id>.window`, at most 4 hours, that the releaser writes), on any credential but the test tenant's (1Password item `nexus cloud test tenant (release-test)` through `op-auto`, its own title read back; `mint_tenant` must be exactly `release-test`, and the token must not be the operator's own), and on any edge host but `api.conexus-nexus.com`. The credential reaches the client only through an `env -i` runner whose argv carries none. `--local-vs-local` proves the plumbing with no cloud, and `--core-only` skips the ledger routes for an engine whose routes are not deployed yet. The release and engine-release skills run it before the tag, and a red blocks the tag. `tests/e2e/lib/candidate_sandbox.sh` is the shared scratch-HOME helper (the RDR-253 seat harness sources it): a whitelist runner, the wheel install, a local or cloud client config from one field map, and a loopback engine on a fresh short `NX_TEST_PG_ROOT`.
