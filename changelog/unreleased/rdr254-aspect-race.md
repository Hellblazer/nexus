### Fixed

- **A document move no longer loses the moved document's aspects to an extraction that finishes after it.** When `nx catalog owners --execute move --document` absorbs the copy registered at the new path, an aspect extraction of that copy queued before the move could complete afterwards and re-point the surviving document's aspect row at the absorbed, trashed copy, so the old tumbler lost its aspects (RDR-254, found by the GH #1571 end-to-end validation). The engine now reads the incoming document's catalog row `FOR SHARE` in the upsert's transaction; an upsert for a trashed or alias document keeps the existing row's `doc_id` and still updates its aspect fields. The read takes locks in the reverse order of a collection rename or delete, so an unfenced `nx enrich aspects` running while another process renames or deletes the same collection can deadlock (accepted, Sam 2026-11-21). The aspect upsert now reruns its transaction when PostgreSQL aborts it with a deadlock, as the rename and delete already did, up to four attempts, so neither command shows the error unless the collision repeats every time (RDR-254).
