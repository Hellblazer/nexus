### Added

- **`nx index pdf` and `nx index md` print the move command when a file moved and was indexed again from its new path.** The run that registers the second document asks the engine's metadata route for an old document under the same curator owner, with the same file hash, whose file is gone from this machine (so a row of a catalog shared with another machine can be named too), and prints one line, the dry-run form of `nx catalog owners --execute move --document <old tumbler> --new-path <new path>`, after the run's own output. It only reads, drops itself on any failed query without changing the exit code, and prints nothing on an engine that does not report the move routes; an unchanged file re-indexed later asks nothing. A run that ends with an error message (a `--dir` batch that reports `N of M failed`) still prints the hints of the files it wrote, before the message. The hint asks about at most 50 files per run, spends at most 30 seconds in its own queries (the time inside them, summed; extraction and the time between files do not count), reads each owner's kind once, and stops after its first failed read; a run that did not check every file ends its hints with `move hints checked for N of M files; run nx index pdf --force on a moved file to check it again`. A document indexed before v7.95.0 and not since carries no file hash: run `nx index pdf --force` once before a planned move (RDR-254 Phase 3).
- **`nx index repo` prints the owner move command when a repository's documents still name an old root, or when the repository was renamed.** Two hints at the end of every run, read from the catalog so they repeat until the move is made. One when the owner's documents (first page of 200) include one the owner move would rewrite, by the engine's own rule (a Windows-shaped root derives nothing, as on the engine). One for each owner whose recorded root is gone and whose documents match at least two, and at least half, of the repository's first 20 file hashes (highest count first, ties in tumbler order; a spent 30-second budget keeps the matches found). Dry-run lines only, each read on its own and dropped alone on failure, including a malformed catalog entry (RDR-254 Phase 3).
- **`nx catalog owners --census` reports `docs_outside_root` for each owner and prints the owner move command where it applies.** The flag (true, false, or null when the owner's first page of 200 documents cannot be read or every entry on it is malformed) sits beside the root class and is neither a class nor an input to which owners `--execute deactivate` may act on. A flagged owner whose root is a healthy git work tree carries the move command with its own root (other classes keep the flag and get no command, which the move would refuse); each `path_vanished` row carries it with a `<new root>` placeholder next to the deactivate line it already has. The move lines are printed only when the engine reports the move routes; the flag is read either way, one `/list` request per owner with a root (RDR-254 Phase 3).
