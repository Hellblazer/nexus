### Added

- **`nx index pdf` and `nx index md` print the move command when a file moved and was indexed again from its new path.** The run that registers the second document asks the engine's metadata route for an old document under the same curator owner with the same file hash whose file is gone, and prints one line, the dry-run form of `nx catalog owners --execute move --document <old tumbler> --new-path <new path>`, after the run's own output. It only reads, drops itself on any failed query without changing the exit code, and prints nothing on an engine that does not report the move routes; an unchanged file re-indexed later asks nothing. A document indexed before v7.95.0 and not since carries no file hash: run `nx index pdf --force` once before a planned move (RDR-254 Phase 3).
- **`nx index repo` prints the owner move command when a repository's documents still name an old root, or when the repository was renamed.** Two hints at the end of every run, read from the catalog so they repeat until the move is made: one when the owner's documents (first page) name a root other than the repository's, one for each owner whose recorded root is gone and whose documents match at least half of the repository's first 20 file hashes (highest count first). Dry-run lines only, each read on its own and dropped alone on failure (RDR-254 Phase 3).
- **`nx catalog owners --census` reports `docs_outside_root` for each owner and prints the owner move command where it applies.** The flag (true, false, or null when the owner's first page of 200 documents cannot be read) sits beside the root class and is neither a class nor an input to which owners `--execute deactivate` may act on. A flagged owner's row carries the move command with its own root; each `path_vanished` row carries it with a `<new root>` placeholder next to the deactivate line it already has. The move lines are printed only when the engine reports the move routes (RDR-254 Phase 3).
