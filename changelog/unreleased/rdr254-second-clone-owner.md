### Fixed

- **A second clone of a repository in a folder with the same name no longer takes the first clone's owner over.** Two clones such as `~/work/nexus` and `~/scratch/nexus` shared one owner, and registering either one swapped the owner's root and hash to its own, so the second clone's copies of the files both clones hold were never documents of their own. When another owner of the same name records a root that is a different live git work tree on this machine (or a root `nx` is not permitted to read), `nx index repo` now registers the repository under its own owner, named `<folder>-<repo hash>`, and leaves the first owner alone. A root that is gone, or the same clone reached through a symlink, keeps the one owner as before, and so does a root recorded by another machine, a container path or an unmounted volume, which read as gone. An owner two clones already share keeps its documents; the clone whose hash it no longer carries gets its own owner and a new collection on its next registration, so that run indexes and embeds the whole clone again. The RDR evidence stream reads a second clone's RDR records from the folder's `<folder>_rdr` project, as before (RDR-254 Gap 4).
