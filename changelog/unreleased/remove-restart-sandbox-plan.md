### Fixed

- **A restart acts only on the sessions its foreground planned, and only on the tmux server that hosts them.** The 2026-11-19 sandbox run reached the operator's default tmux server because its environment had no `TMUX`; the background half then re-read the real `~/.claude/sessions` and began restarting twelve real sessions. The foreground now writes a plan file (`~/.claude/restart-plans/`, mode 0600, pruned after a day) of the sessions it decided on, the tmux server it reached and how many it skipped, and names it on the background command (`--plan`); just before it writes the plan it re-reads each planned session's own file, so a session cleared during the gates or the install is planned under its current id and one that is gone is dropped. The background half restarts exactly those sessions, never enumerates sessions itself, deletes the plan on every exit, and refuses (exit 6) when the plan is missing, unreadable, not a regular file of the user's, oversized, over a day old or made on another server. The restart, `--ask-ready` and `--status` each restart, ask or mail a session only when the tmux server they reach has the session's pane and the session's process runs in it; the session and window names in the session's `tmux` field are not compared, since a rename or a moved window changes them and says nothing about the server. A run that reaches a server holding none of its sessions refuses (exit 6) before anything is sent, naming the server (and that `TMUX` was unset, when it was) and what each session records; a session on another server is skipped with a `SKIP` log line, the rest go on, and the foreground's last line and the log's `=== done` line say how many were skipped. `--dry-run` writes nothing to the log.
