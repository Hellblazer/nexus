### Fixed

- **A restart acts only on the sessions its foreground planned, and only on the tmux server those sessions live on.** The 2026-11-19 sandbox run reached the operator's default tmux server because its environment had no `TMUX`; the background half then re-read the real `~/.claude/sessions` and began restarting twelve real sessions. The foreground now writes a plan file (`~/.claude/restart-plans/`, mode 0600) of the sessions it decided on and the tmux server it reached, and names it on the background command (`--plan`); the background half restarts exactly those sessions, refuses (exit 6) when the plan is missing, unreadable or made on another server, and never enumerates sessions itself. Both halves restart a session only when the tmux server they reach has the pane its `tmux` field names and the session's process runs in it; a run with none refuses before anything starts, naming the server it reached (and that `TMUX` was unset, when it was) and what each session records, and a session on another server is skipped with a log line while the rest go on.
