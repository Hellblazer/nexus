### Changed

- **`claude-restart-sessions`: the sandbox gate is advisory, the install no longer cleans uv's cache, a repeated ready round re-asks only the sessions that were not ready, and the ask tells a session to stop its shells.** Sam's 2026-11-19 restart rethink, so a release restart stops paying for the same four things. The sandbox pass (another script, tmux, harness or Claude Code, a missing or unreadable record) is now a WARN line in the log and on stdout naming the problem, the last pass and the weekly run's status, and the restart goes on, in the foreground run and in the detached roll; `--skip-sandbox-check REASON` is still accepted and only logs its reason, `--dry-run` and `--status` still report the pass, and `--status`'s exit code ignores it. `scripts/restart-sandbox-weekly.sh` is the regression check, and a change to the roll path runs `tests/e2e/restart-sessions/run.sh` in its own review. The `--nx` install no longer runs `uv cache clean conexus`, which waited on a lock every live session's MCP server holds; the exact `conexus==X` pin and the post-install `nx` and plugin version checks stay. A second `--ask-ready` round within `--ready-max-age` asks again only the sessions whose last answer was not ready, missing, unreadable or stale and keeps the fresh ready answers of the rest (the round file records them with their old reply file, `kept_from` and `since`); `--status` names the sessions re-asked and the answers kept. The ask now names the background tasks the script sees under the session and tells it to stop them with TaskStop, finished ones included, before it answers ready, since a live shell leaves the session at status `shell` and the restart skips it. The release skill's Step 12 says the same, and that the operator's hold message is a one-way announcement with the file reply as the only answer.
