### Fixed

- **The restart sandbox no longer binds RDR-253 identities in the operator's tenant.** The sandbox copies the operator's `config.yml` so its Claude sessions reach the operator's engine, and since 8.5.0 each session's SessionStart hook and MCP identity lease bound an identity with that credential (twelve `rs_*` rows). With `NX_IDENTITY_BIND=0` in its environment the SessionStart identity hook binds nothing and makes no engine call (one notice line says so), and the MCP server starts no identity lease; the sandbox sets that and `NX_IDENTITY_LEASE=0` for its sessions, and its `nx` refuses the `nx identity` verbs that make or change an identity or seat. Three read-only checks prove it: before any session starts, the installed `nx` must honour `NX_IDENTITY_BIND` (one that predates it ends the run unverified, exit 2, with no session started); after each scenario every session id must read `unknown_session` (an identity that bound and then ended is on no list, so this is the primary check); and the operator's list of live and lapsed identities on the host is compared before and after, failing the scenario on a new row that carries a sandbox session name or a recorded pid and noting any other. A check that cannot read fails. The gate now runs its sessions unbound, so the restart's seat and identity paths (`ensure_seat` and promote, the `NX_SEAT` carry-over, attested mail) are not exercised by it.
