### Added

- **Every generation cleanup leaves a record in `~/.config/nexus/logs/install-gc.log`.** The SessionStart sweep, `nx self gc`, `nx self install` and the bootstrap rebuild all reap through one rule set, and the sweep discarded its output, so a generation removed under a live session left no trace. Each run now appends JSON lines to that file (under `NEXUS_CONFIG_DIR` when set) as it goes, each flushed to disk before the next step: a `gc_reap_begin` line before each delete starts, then `gc_reaped`, `gc_reap_kept` (the tree stayed: in use on Windows, a refused pointer) or `gc_reap_failed`, and one `gc_run` summary; a begin line with no end means a run that was killed mid-delete. The lines name the generation, its stamp, the reason, the holder count, the process census (state, why it failed, how long `ps` took, rows), the caller (`self-gc-hook` for the SessionStart sweep, `self-gc` by hand, `self-install`, `bootstrap`), the nx that ran it (generation and version), and a map of every held generation to its pids; the begin and summary lines also name the parent process chain, each command cut to its program name and first arguments with any token, key, secret, password or auth value redacted. The file is created readable by its owner only, rotates to `install-gc.log.1` past 1 MB (a rotation that fails, as on Windows with the file open, never costs a line), a run that removes nothing still writes the summary, a missing tools directory is recorded, `--dry-run` writes nothing, and a record that cannot be written never stops the cleanup.
