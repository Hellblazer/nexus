### Fixed

- **The T1 `scratch` tool no longer fails for the rest of a session after one `[Errno 2] No such file or directory`.** A long-lived MCP server that rebuilt its scratch client (on a rotated session token or an engine restart) re-read the TLS CA bundle from the nx install it started from; once that install had been removed, the rebuild raised a pathless ENOENT after the old client was already closed, and every later scratch call answered "Cannot send a request, as the client has been closed." until the session restarted. The scratch, token-admin, identity and groups clients, the aspect worker's, the LLM operator's and the storage daemon's now share one process-wide SSL context (read once, rebuilt only when `SSL_CERT_FILE`, `SSL_CERT_DIR` or the default context factory changes, and kept when a rebuild fails). The scratch store builds a replacement client before it lets go of the old one, keeps the old one open for requests already in flight on it, sets a new token, header or endpoint only once the new client is built, rebuilds a client that was closed under it, never replays a request after a stream error, and names the CA bundle's path when it cannot be read. A lint keeps new `httpx` clients on the shared context.
