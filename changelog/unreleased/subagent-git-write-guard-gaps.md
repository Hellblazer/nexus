### Fixed

- **The subagent git-write guard no longer lets seven writes through.** From the primary checkout a subagent is now denied `git branch -f|--force`, `git tag <name>` (and `-f`, `-a`, `-s`, `-d` after the name), `git revert` (`--skip`, `--abort`, `--continue` too), `git pull` (any form), `git fetch <remote> <src>:<dst>` (also `tag <name>` and `--prune-tags`), `git submodule foreach '<cmd>'` and `--output=<path>` / `--output <path>` on `git diff|log|show` and the other commands that take diff options. The first five still pass from a proven linked worktree like every other write verb; `submodule foreach` and `--output` deny there too, since one runs any command and the other writes a file outside the tree, and only a `# routing-allow:` passes them. Listings stay allowed (`git branch`, `git tag -l|-n|--contains`, `git log`, `git diff --stat`, `git show HEAD`, `--output-indicator-*`, a plain `git fetch origin`), and `hub pull-request` is not caught. `git -C <worktree>` is not widened. Older tests that pinned `git branch -f` and `git submodule foreach` as allowed now pin the denial.
