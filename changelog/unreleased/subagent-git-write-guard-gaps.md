### Fixed

- **The subagent git-write guard no longer lets seven writes through.** From the primary checkout a subagent is now denied `git branch -f|--force`, `git tag <name>` (and `-f`, `-a`, `-s`, `-d` after the name), `git revert` (`--skip`, `--abort`, `--continue` too), `git pull` (any form), `git fetch <remote> <src>:<dst>` (also `tag <name>`, `--prune-tags`, `--refmap`, `--stdin`, a refspec held in a variable, and `-c remote.<name>.fetch|push=` in its `--config-env` and `GIT_CONFIG_*` spellings), `git submodule foreach '<cmd>'` and `git submodule--helper foreach` (the helper also gets `submodule`'s write set) and `--output=<path>` / `--output <path>` on `git diff|log|show` and the other commands that take diff options. The first five still pass from a proven linked worktree like every other write verb; `submodule foreach`, `submodule--helper` and `--output` deny there too, since one runs any command and the other writes a file outside the tree, and only a `# routing-allow:` passes them. Listings stay allowed (`git branch`, `git tag -l|-n|--contains`, `git log`, `git diff --stat`, `git show HEAD`, `git grep`, `-S '--output'`, `--output-indicator-*`, a plain `git fetch origin`), and `hub pull-request` is not caught. `git -C <worktree>` is not widened. The old tests that pinned `git branch -f` as allowed now pin the denial; the `git submodule foreach` rows that stood in tests of the quoted-data config rule were deleted or moved to `ssh`, `git rebase -x` and `tmux send-keys`, because foreach denies by itself and no longer shows whether that rule works. Known limits (xargs-fed arguments, a general `-c` injection, `archive -o` and `format-patch -o`, `bisect`, whole-word variables) are named in the module docstring.
