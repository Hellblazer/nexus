### Changed

- **The daily install ping skips automated environments, so test and build runs no longer count as installs.** `nx telemetry status` now reports `off (automation: <kind> (<signal>))` when the process looks like a pytest run (`PYTEST_CURRENT_TEST`), a lab-run grant (`NOMAD_ALLOC_ID`), a CI run (`CI`, `CONTINUOUS_INTEGRATION`, `GITHUB_ACTIONS`, `GITLAB_CI`, `BUILDKITE`, `CIRCLECI`, `TRAVIS`, `JENKINS_URL`, `JENKINS_HOME`, `TEAMCITY_VERSION`, `TF_BUILD`, `BITBUCKET_BUILD_NUMBER`, `DRONE`, `CODEBUILD_BUILD_ID`, `APPVEYOR` and a few more; a value of `0`, `false`, `no`, `off` or empty counts as not set), or a container (`/.dockerenv`, `/run/.containerenv`, a docker, containerd, kubepods or lxc entry in `/proc/1/cgroup`, or `KUBERNETES_SERVICE_HOST`). **If you run nx inside a container, its pings stop with this release; set `NX_TELEMETRY=1` to turn them back on.** `NX_TELEMETRY=1` overrides only these automation skips: `NX_NO_TELEMETRY`, `nx telemetry off` and the dev-checkout skip still win over it. The existing opt-outs and their `status` reasons are unchanged. (conexus-momd; Sam 2026-11-24)
