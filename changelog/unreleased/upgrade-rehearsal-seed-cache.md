### Changed

- **The release gate's upgrade rehearsal (step 6e) keeps each start's prepared store on the run host and restores it instead of re-seeding.** The cache lives under `~/.cache/lab-remote/upgrade-rehearsal-seeds/` (`NEXUS_UPGRADE_REHEARSAL_SEED_CACHE` moves it), one entry per previous release and prepare family, keyed on that release, the engine tag it pins, the platform, the prepare command and the sha256 of the seeder scripts; an entry unused for 30 days is removed. It changes only the preparation: a corrupt, partial or mismatched entry, a dirty destination, a failing read of the restored store, or a restored row count under the 50,000 floor or different from the manifest seeds in full, and every judged step, ceiling and exit code is as before. A hit gives the store a fresh PG port and rewrites the old run dir to the new one in text files and the catalog's `repo_root` and `source_uri` columns. Each start's table gains a `prepare (setup)` row, `store restored from cache <key> (saved <date>)` or `seeded (cache miss, saved <key>)`. `--no-seed-cache` seeds every start in full and, as a non-default setting, makes a pass NOT THE RELEASE GATE.
