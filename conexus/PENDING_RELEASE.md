# Pending release: plugin changes that are NOT live yet

`.claude-plugin/marketplace.json` pins `plugins[].source.ref` to an immutable
release tag. Claude Code loads this plugin's hooks, commands, skills, and agents
from **that tag**, not from your working tree. So every change below is merged
on `develop` and **inert in every running session** until the next release ships
and users install it.

This file is the acknowledgement ledger for that gap. It exists because the gap
is otherwise invisible: on 2026-07-25 a subagent ran `git stash -u` in a shared
tree and the guard that covers exactly that verb did not fire, because the
coverage had landed hours earlier and the installed plugin was still `v6.18.1`.
Three guards had been merged, closed as "mechanized", and were protecting
nothing.

**Rules, enforced by `tests/test_plugin_release_drift_ledger.py`:**

- Every file under the behavioural surface that differs from the pinned tag MUST
  be listed here. Adding a guard without declaring it fails the suite.
- When a release ships and the pin advances, drift goes to zero and this list
  MUST be emptied. A stale entry also fails the suite, so the ledger cannot
  quietly become fiction.
- Do NOT "fix" a failure by deleting entries. The entry is the honest statement
  that the thing is not yet live.

**Do not use this to justify skipping a release.** If a guard matters enough to
mechanize, it matters enough to ship.

**Deferring a straddling entry (nexus-2x3qy).** A plugin cut (`scripts/
cut_plugin_release.py`) refuses when a ledger entry's bead also touches wheel
content (`src/`, `conexus/plans/`, `conexus/daemon/`, `mcpb/`, `dt/`) the
wholesale import cannot hold back on a per-entry basis. The only fix is moving
that entry under `## Deferred to the next client release` below: the cut then
holds the entry's channel path(s) back from itself too (restored to the base
branch's own content) so the whole bead ships together, in one piece, at the
next client release. A deferred entry is exempt from the release-window
"ledger must be empty" rule above -- still declared there is correct, not
stale -- and stays exactly where it is until moved back deliberately.

- credentials page for mode cloud (nexus-sv2wx.18): `conexus/launch/nx_setup.py` serves one small loopback page (`127.0.0.1`, a port the system picks, a random one-time path) from the start of a `cloud` run while the build goes on, and asks the system to open an owner-only opener file that redirects the browser to it (the address is on no command line and in no other file; the file is deleted at the first load, when the listener closes without one, and at the next run's start after a kill). The managed edge's answer to a right credential on the two `/v1` routes is not measured (research-37 measured `/health` and `/version`). The status file's `credentials` field takes exactly six values; a page not loaded in 2 minutes (at once when the open request failed) says what to do, and the listener closes at 10 minutes. A timeout during the build says to wait for the run to end; credentials accepted and then lost to a failed build, a failed save or a kill are reported as not completely saved and discarded, and the next step is a new page; only a resume of a run that saved its credentials and failed at a later step skips the page, and replacing a saved credential is `nx config init` in a terminal (the real server's `setup` starts nothing while a service answers, and a saved address with a token resolves as one); saving one kind first runs `nx config unset` for a saved key of the other kind; no verdict repeats the tenant as typed.
