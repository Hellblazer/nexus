Installing Nexus

Nexus gives Claude a permanent memory and search by meaning. It runs on your computer, so you need no API key, no account, and no separate database install. The install takes about ten minutes.

How do you use Claude?

You run claude in a terminal, and you install the nx command and a plugin that adds tools, agents, and skills to Claude Code.

You index and search from the terminal only, and you can add the Claude plugin later.

You use the Claude Desktop app without Claude Code, and you install Nexus as an extension.

Nexus ships its own PostgreSQL, built for these platforms only, so an Intel Mac or Windows on ARM cannot run a local install and setup stops with an error. The memory figures come from an Apple Silicon Mac that indexed a medium-sized code repository. The first PDF you index downloads about 2.3 GB more, for the PDF models.

Windows is tested but not yet declared supported. The install, search, update, and removal steps passed on a clean Windows 11 x64 machine, in a PowerShell window without elevation. A standard (non-administrator) account was not tested. The Windows binaries are not code-signed, so Smart App Control in enforcing mode or a company application-control policy can block them, and that was not tested either. The Windows install guide has the full measured path. After you install uv, Git, or nx, open a new PowerShell window so the new command is on your PATH.

Tools to have

  • uv installs and runs the nx command. Check: uv --version. To install it:

    brew install uv
    curl -LsSf https://astral.sh/uv/install.sh | sh
    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

    Run it in a normal PowerShell window, not an elevated one. winget install --id astral-sh.uv --scope user also works, and the first time you use winget it asks you to accept its source agreements (answer Y).

  • git. Nexus reads git information when it indexes a repository, and nx doctor checks for it. Check: git --version. To install it:

    brew install git
    sudo apt install git   # Debian and Ubuntu; other distributions use their own package manager
    $ProgressPreference = 'SilentlyContinue'
$rel = Invoke-RestMethod https://api.github.com/repos/git-for-windows/git/releases/latest
$asset = $rel.assets | Where-Object name -Match '^PortableGit-.*-64-bit\.7z\.exe$'
Invoke-WebRequest $asset.browser_download_url -OutFile "$env:TEMP\PortableGit.exe" -UseBasicParsing
if ((Get-FileHash "$env:TEMP\PortableGit.exe").Hash -ne ($asset.digest -replace '^sha256:')) { throw 'PortableGit checksum mismatch' }
Start-Process "$env:TEMP\PortableGit.exe" -ArgumentList "-o`"$env:LOCALAPPDATA\Programs\Git`"", '-y' -Wait
$userPath = [Environment]::GetEnvironmentVariable('Path', 'User')
[Environment]::SetEnvironmentVariable('Path', "$userPath;$env:LOCALAPPDATA\Programs\Git\cmd", 'User')

    The Git for Windows installer always asks for administrator rights, and PortableGit is the same Git, with Git Bash, without that need. This block downloads it (about 60 MB), checks its SHA-256, extracts it to %LOCALAPPDATA%\Programs\Git, and adds it to your user PATH in under a minute. Claude Code on Windows uses the same Git Bash for its Bash tool. With administrator rights, winget install --id Git.Git -e --source winget also works.

  • Python: nothing to install, because the install command names Python 3.12 and uv downloads it.

Install

Run the steps in this order. Each step is safe to run again.

  1. Install the nx command

    The first command installs nx, and the second moves it to the layout that Nexus manages and leaves out two packages that cause conflicts.

    The first command installs nx for your user in a minute or two. The second command moves it to the layout that Nexus manages, so that an update never replaces a file that a running program uses, and it adds %USERPROFILE%\.local\share\nexus\tools\current\bin to the front of your user PATH.

    uv tool install conexus --python 3.12
nx self install
    uv tool install conexus --python 3.12 --torch-backend cpu
nx self install

    --torch-backend cpu installs the CPU build of torch. Without it, uv installs the GPU build on x86-64, which is 4.3 GB of downloads and 8 GB on disk that Nexus does not use. uv warns that the option is experimental, and that is expected. The option needs uv 0.9.19 or newer.

    uv tool install conexus --python 3.12
nx self install

    A fresh install needs no nx upgrade, even if nx self install suggests it.

    If the terminal cannot find nx after this, add ~/.local/bin to your PATH. Then open a new terminal.

    Open a new PowerShell window before the next step. If it cannot find nx, check that your user PATH holds %USERPROFILE%\.local\share\nexus\tools\current\bin.

  2. Set up the storage service

    This command first asks whether the service should start at login. Answer yes. It then downloads the service program, the database, and the search model, and starts the service.

    nx init
    ~700 MB~580 MBdownloaded, first run only
    2–5 minon a normal connection

    Use nx init --yes to answer yes automatically, or nx init --no-autostart to skip starting at login.

  3. Check the install

    nx doctor

    No line may show ✗. A ⚠ line is a soft warning. Right after nx self install, one ⚠ line, "Orphan uv install", is normal. The next nx self install, nx self gc, or Claude Code session with the plugin removes the old uv copy, and the line goes away. Read any other ⚠ line.

  4. Add the Claude Code plugin

    Start claude. Type these two commands inside Claude Code, not in the terminal:

    /plugin marketplace add Hellblazer/nexus
/plugin install conexus@nexus-plugins

    Then run /conexus:nx-preflight, which checks that everything the plugin needs is present.

  5. Index a repository and search it

    cd your-project
nx index repo .
nx search "how does retry work"

    If you index the same repository again, Nexus skips files that did not change. For a large repository, add --monitor to see the progress for each file.

The install is complete. After you index a repository, Nexus finds its topics automatically, and nx taxonomy status shows them.

Install

  1. Install uv

    The extension runs through uv. Install git as well, as shown under Before you start.

    brew install uv
    curl -LsSf https://astral.sh/uv/install.sh | sh
    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

    When you install uv this way, Claude Desktop finds it. You do not need to change your PATH.

  2. Set up the storage service

    The extension does not start the service itself. Run these commands one time in a terminal.

    uv tool install conexus --python 3.12
nx self install
nx init
nx doctor
    uv tool install conexus --python 3.12 --torch-backend cpu
nx self install
nx init
nx doctor
    uv tool install conexus --python 3.12
nx self install

    Open a new PowerShell window, then:

    nx init
nx doctor

    The first run takes a few minutes. No line of nx doctor may show ✗. A ⚠ line is a soft warning, and one ⚠ line, "Orphan uv install", is normal right after nx self install.

  3. Add the extension

    Download conexus.mcpb from the latest release and double-click the file. Claude Desktop adds it under Settings → Connectors as "Conexus", and the first start takes about 20 seconds.

    The Claude Desktop install dialog has not been tested on Windows yet.

Next: Getting started. If you already use the conexus plugin in Claude Code, do not install the extension, because Claude Desktop already sees the plugin's tools and with both you get two copies with different names.

Update Nexus

Always run both of these commands:

nx self install   # install the new version next to the current one
nx upgrade        # update the service, the data, and the plugins

Do not update with uv tool install conexus or with --force. That command removes the local search model, and search then returns nothing. If this happened, nx self install repairs it.

If you update the plugin with /plugin update in Claude Code, the next session runs both commands for you.

On Windows, nx self install also points the NexusStorageService logon task at the new version. The running storage service keeps its old version until it next starts, which happens at your next sign-in or after nx daemon service stop and Start-ScheduledTask NexusStorageService.

Remove Nexus completely

Follow these four steps in this order. The first step is optional, and none of them touches a managed cloud tenant, because they remove only what is on this computer.

  1. Optional: keep a copy of your knowledge

    You can export the knowledge store to a file and import it into a later install, but you cannot export memory or scratch.

    nx store export --all -o <A-DIRECTORY-TO-KEEP>   # one .nxexp file per collection

    Later, nx store import <FILE>.nxexp restores a collection into a new install.

  2. Remove the Claude integration

    In Claude Code:

    /plugin uninstall conexus@nexus-plugins

    In Claude Desktop: Settings → Connectors → Desktop → Conexus → Uninstall. This removes the extension only, and steps 3 and 4 remove the service and the data.

    If you use both Claude Code and Claude Desktop, do both.

  3. Stop the service and delete the data

    nx uninstall                          # preview, changes nothing
nx uninstall --yes --remove-data      # stop the service and its workers, remove autostart, delete notes, plans, catalog, the database and the search models

    Without --remove-data, the service stops and autostart is removed, but your data stays in ~/.config/nexus. Use that form if you plan to install again later.

  4. Remove the program

    nx uninstall does not remove nx itself or older versions kept side by side. Remove them by hand:

    uv tool uninstall conexus 2>/dev/null      # the uv install, if one exists
rm -rf ~/.local/share/nexus                # program versions, search model cache
rm -f ~/.local/bin/nx ~/.local/bin/nx-mcp ~/.local/bin/nx-mcp-catalog ~/.local/bin/nx-session-end-launcher ~/.local/bin/nx-hook
    uv tool uninstall conexus
Remove-Item -Recurse -Force "$HOME\.local\share\nexus" -ErrorAction SilentlyContinue
Remove-Item -Force "$HOME\.local\bin\nx.exe", "$HOME\.local\bin\nx-mcp.exe", "$HOME\.local\bin\nx-mcp-catalog.exe", "$HOME\.local\bin\nx-session-end-launcher.exe", "$HOME\.local\bin\nx-hook.exe" -ErrorAction SilentlyContinue

    nx uninstall in step 3 already stopped the background workers, removed %LOCALAPPDATA%\nexus, and took the folder that nx self install added off your user PATH. These lines remove the program itself, which nx cannot delete while it runs. If the uv copy from step 1 is still there, uv tool uninstall conexus removes it. If a Claude Code session or nx self gc already removed it, uv prints "conexus is not installed", which is also fine.

    The commands skip files that are already gone. Two engine cache folders stay: %TEMP%\onnxruntime-java* (about 11 MB) and %USERPROFILE%\.djl.ai (about 13 MB, a default location that other programs can also use, so check it first), and Remove-Item -Recurse -Force "$env:TEMP\onnxruntime-java*", "$HOME\.djl.ai" deletes them. uv itself, the Python 3.12 it downloaded, its download cache (about 2.5 GB, which uv cache clean empties), and PortableGit belong to you, not to Nexus, so they stay.

    Releases older than 7.74.0 leave the search models in ~/.cache/nexus after --remove-data, so on those also run rm -rf ~/.cache/nexus.

    Releases older than 7.74.0 also leave the search models, the aspect worker, %LOCALAPPDATA%\nexus, and the PATH entry, and the Windows install guide has the commands that remove them.

Check

which nx                        # must print nothing
launchctl list | grep -i nexus  # must print nothing
ls ~/.config/nexus              # must not exist
ls ~/.cache/nexus               # must not exist
which nx                                          # must print nothing
systemctl --user list-unit-files | grep -i nexus  # must print nothing
ls ~/.config/nexus                                # must not exist
ls ~/.cache/nexus                                 # must not exist
Get-Command nx -ErrorAction SilentlyContinue                          # must print nothing
Get-ScheduledTask NexusStorageService -ErrorAction SilentlyContinue   # must print nothing
Test-Path "$HOME\.config\nexus"                                       # must print False
Test-Path "$HOME\.cache\nexus"                                        # must print False
Test-Path "$env:LOCALAPPDATA\nexus"                                   # must print False
Test-Path "$HOME\.local\share\nexus"                                  # must print False

Problems

The install fails with "No solution found when resolving dependencies"

The hint names torch and cp314 because you left --python 3.12 off the install command and your python3 is 3.14. Run the command again with the flag.

Windows: uv tool install fails with "untrusted mount point (os error 448)"

An old python3.exe in %USERPROFILE%\.local\bin hides the Python that uv manages. Add --python-preference only-managed to the install command and run it again.

nx: command not found

Add ~/.local/bin to your PATH. Then open a new terminal. If PATH is already correct, run nx self install. If nx was never installed, run uv tool install conexus --python 3.12 (on Linux, add --torch-backend cpu).

nx: command not found

Open a new PowerShell window. If nx is still not found, check that %USERPROFILE%\.local\share\nexus\tools\current\bin is on your user PATH.

Crash on startup, or an import error mentioning voyageai or Pydantic v1

Your install runs on Python 3.14, which does not work yet. Run these two commands in order: uv tool install conexus --force --python 3.12 (on Linux, add --torch-backend cpu), then nx self install. On Windows, run nx daemon service stop first, because the install replaces files that the running service uses.

Linux: uv says "unexpected argument '--torch-backend'"

Your uv is older than 0.9.19. Run uv self update, or update uv with the package manager that installed it. Then run the install command again. Do not leave the option off: uv then installs the 4.3 GB GPU build of torch.

nx search returns nothing

Run nx doctor. If the index was interrupted, run nx index repo . again and it continues where it stopped. If you updated with uv tool install, see "Update Nexus" above.

Plugin installed but its tools never appear

The usual cause is that the nx command is not installed. Run /conexus:nx-preflight. It tells you what is missing.

Nothing above helps

Paste the recovery runbook as the first message of a Claude Code session, and Claude checks the install step by step and asks you before it changes any data.

What you installed

Nexus is one service on your computer. It contains a database (Postgres 17 with pgvector) and three stores: scratch for one session, memory for project facts, and knowledge for everything you index. The search model also runs on your computer, so your data does not leave it. While Claude uses Nexus, it sends at most one message a day with six values (a random install id, version, mode, operating system, CPU type, and Python version) and no hostname, paths, collection names, or content. The service keeps a keyed fingerprint of the sender's network address, never the address itself, as the privacy policy describes. nx telemetry off stops this, and nx telemetry status shows the setting.
