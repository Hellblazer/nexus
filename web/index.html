Installing Nexus

Persistent memory and semantic search for Claude, running entirely on your machine. No API keys, no accounts, no Postgres to install. About ten minutes from nothing to your first search.

How do you use Claude?

You run claude in a terminal. You get the CLI plus a plugin with 48 MCP tools, 13 agents and 43 skills. The plugin needs Node.js.

You want indexing and search from the shell, no Claude integration yet. You can add the plugin later.

You use the Claude Desktop chat app and do not have Claude Code. Nexus arrives as a one-click extension.

Install

Before step 1

Install Node.js now. The plugin's sequential-thinking server launches through npx. Without node and npm on PATH, step 4 will report success and the tools will never show up, with no error anywhere.

Confirm with node --version and npm --version before continuing.

Run these in order. Each one is safe to re-run.

  1. Install the nx CLI

    The second command moves it onto the generation layout, which drops a conflicting media wheel and, on Linux, swaps the 4.5 GB CUDA torch build for a CPU one.

    uv tool install conexus
nx self install

    If nx is not found afterwards, add ~/.local/bin to your PATH and open a new shell.

  2. Provision the storage service

    Downloads the signed engine and Postgres bundle, sets up pgvector and the bge-768 embedder, starts the service, and asks to register autostart at login. Say yes.

    nx init
    ~600 MBdownloaded, first run only
    2–5 minon a normal connection
    0things you have to configure

    Non-interactive: nx init --yes. To skip autostart: nx init --no-autostart.

  3. Verify

    nx doctor

    Every row should show ✓. A "credentials not set" line is expected in local mode and is not a problem.

  4. Add the Claude Code plugin

    Node.js check first: node --version must print a version. If it does not, install Node and come back; the plugin cannot start its servers without it.

    Then, inside a claude session, not in the shell:

    /plugin marketplace add Hellblazer/nexus
/plugin install conexus@nexus-plugins

    Then run /conexus:nx-preflight to confirm every dependency is present. The plugin's MCP servers are the nx package you installed in step 1, so the order matters.

  5. Index something and search it

    cd your-project
nx index repo .
nx search "how does retry work"

    Indexing skips unchanged files on re-run. Add --monitor for per-file progress on a large repo.

Done. Search runs fully local. Topics are discovered automatically after indexing; nx taxonomy status shows them.

Install

  1. Install uv

    Claude Desktop finds it without any PATH setup when installed this way.

    brew install uv
    curl -LsSf https://astral.sh/uv/install.sh | sh

  2. Provision the storage service

    The extension does not start a service itself. Do this once in a terminal:

    uv tool install conexus
nx self install
nx init
nx doctor

    First run downloads about 600 MB and takes a few minutes. Every nx doctor row should show ✓.

  3. Add the extension

    Download conexus.mcpb from the latest release and double-click it. Claude Desktop registers it under Settings → Connectors as "Conexus". First launch resolves dependencies, about 20 seconds.

Already have the conexus plugin in Claude Code? Skip the extension. Desktop chat already sees the plugin's tools, and installing both gives you two copies under different names.

Keeping it current

Two commands, always both:

nx self install   # new code, installed beside the running one
nx upgrade        # converge engine, data and plugins

Do not upgrade with uv tool install conexus or --force. That resets the environment and drops the local embedder, and search returns nothing. If you already did, nx self install repairs it.

Updating the plugin from Claude Code with /plugin update runs both commands for you at the next session start.

If something goes wrong

nx: command not found

Add ~/.local/bin to your PATH and open a new shell. If it is on PATH already, ls -l ~/.local/bin/nx tells you which layout you are on; nx self install from any working nx, or uv tool install conexus if nothing is installed yet.

Crash on startup, or an import error mentioning voyageai or Pydantic v1

You are on Python 3.14 under the plain uv layout. Run uv python install 3.13 then uv tool install conexus --force --python 3.13, and follow with nx self install.

nx doctor says credentials not set

Expected in local mode. Only the managed cloud service uses a token.

nx search returns nothing

Run nx doctor. If indexing was interrupted, re-run nx index repo .; it resumes. If you upgraded with a bare uv tool install, see Keeping it current above.

Plugin installed but its tools never appear

Two usual causes: the nx CLI is not installed (the plugin's servers are that package), or Node.js is missing so npx cannot start the bundled server. /conexus:nx-preflight names which.

Still stuck

The recovery runbook is a diagnose-first procedure you paste into a Claude Code session as its first message. It pauses for your go-ahead before anything that changes data.

What you just installed

One local service, Postgres 17 with pgvector, serving three tiers of memory: session scratch, persistent project notes, and a permanent semantic store of everything you index. An on-device embedder means nothing leaves your machine. Once a day the MCP server sends one anonymous ping with six fields (install id, version, mode, OS, CPU, Python); nx telemetry off disables it.
